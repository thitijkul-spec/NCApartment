# สเปค Module: มิเตอร์น้ำ-ไฟ (Utility Meter Reading)

Sub-module สุดท้ายของ "ห้องพัก" — ต่อจาก [module_room_key_features.md](module_room_key_features.md) และ [module_booking_key_features.md](module_booking_key_features.md)

สถานะ: ✅ สเปคเสร็จ (รอ confirm ก่อน implement)

---

## 1. หน้าที่ของโมดูล

บันทึกเลขมิเตอร์น้ำ-ไฟรายห้อง (ปัจจุบัน vs ครั้งก่อน) แล้วเก็บ "หน่วยที่ใช้" ไว้ให้โมดูลบิล (ยังไม่ทำ) ดึงไปคำนวณเป็นเงินทีหลัง — **โมดูลนี้ไม่คำนวณ/ไม่แสดงยอดเงิน ไม่ผูกกับอัตราค่าน้ำ-ไฟ**

ขอบเขต multi-building: ทุกอย่างในหน้านี้กรองตาม `building_id` ที่กำลังเลือกอยู่ (ตามสถาปัตยกรรมระบบ)

## 2. ประเภทมิเตอร์ที่รองรับ

**น้ำ + ไฟ เท่านั้น** (ไม่รวมเน็ต/ส่วนกลาง — สองอย่างนั้นเป็นค่าเหมาจ่ายที่ตั้งไว้แล้วในโมดูลห้องพัก ไม่มีมิเตอร์)

## 3. Data Model

```
MeterReading
- id
- room_id            → FK Room
- building_id         → FK Building (denormalized เพื่อ query เร็ว/สอดคล้อง multi-building)
- reading_month       → string "YYYY-MM" (เช่น "2026-08") — ตัวแทน "ค่า เดือน/ปี ของการจดครั้งล่าสุด"
- water_prev          → float (ค่ามิเตอร์น้ำครั้งก่อน)
- water_current        → float (ค่ามิเตอร์น้ำปัจจุบัน)
- water_units          → float, computed = water_current - water_prev
- electric_prev        → float
- electric_current     → float
- electric_units       → float, computed = electric_current - electric_prev
- recorded_at          → datetime (วันที่/เวลาที่บันทึก)
- recorded_by          → FK User (ชื่อผู้บันทึก)
- billing_status        → enum: unbilled | billed  (default: unbilled — field จองไว้ให้โมดูลบิลอัปเดตทีหลัง)
- bill_id             → FK Bill, nullable (จองไว้เช่นกัน)
- created_at / updated_at
```

**หมายเหตุสำคัญ:**
- ไม่มี concept "รอบ/งวด" ระดับอาคารที่ต้อง lock ปิดรอบพร้อมกันทุกห้อง — แต่ละห้องเป็น record อิสระ ต่อเนื่องตามประวัติของห้องนั้น
- 1 ห้อง = 1 record ล่าสุดที่ active (คือ record ที่ยังไม่ได้บันทึกรอบถัดไปทับ) + ประวัติเก่าเก็บไว้ดูย้อนหลังได้ทั้งหมด (append-only, ไม่ overwrite record เก่า)
- "ก่อน" (prev) ของการจดครั้งใหม่ = ค่า current ของ record ล่าสุดก่อนหน้า (ห้องว่างก็ยังสืบทอดค่าจากครั้งจดล่าสุดตอนยังมีผู้เช่าอยู่ได้)
- อัตราค่าน้ำ/ไฟต่อหน่วย **ไม่เก็บใน MeterReading** — ดึงจากอัตราปัจจุบัน (ระดับสาขา + override ราย room) ตอนออกบิลเสมอ

## 4. หน้าจอย่อย

### 4.1 หน้ารายการหลัก "บันทึกมิเตอร์น้ำ-ไฟ"
- แท็บเดียว "บันทึกเลขมิเตอร์" (**ตัดแท็บ "รูปมิเตอร์ที่ผู้เช่าส่งมา" ออกจาก MVP ทั้งหมด — ไม่มีฝั่งผู้เช่ากรอกเอง ไม่เก็บเป็น backlog**)
- การ์ดสรุป 3 อัน: รวมหน่วยน้ำ / รวมหน่วยไฟ / บันทึกแล้ว (x/N)
  - ขอบเขตการนับ: ใช้ `reading_month` ของ record ล่าสุดของแต่ละห้อง เทียบกับเดือน/ปีปัจจุบัน (ตาม client date) — ห้องที่ record ล่าสุดตรงเดือน/ปีปัจจุบันถือว่า "บันทึกแล้ว" ห้องที่ยังไม่มี record ของเดือนนี้ถือว่ายังไม่บันทึก แม้จะมี record เดือนก่อนอยู่ก็ตาม
  - N = **จำนวนห้องทั้งหมดในอาคาร** (ทุกห้องต้องกรอก ไม่ใช่แค่ห้องมีผู้เช่า)
  - รวมหน่วยน้ำ/ไฟ = sum ของ units จาก record ที่ "บันทึกแล้ว" ในเดือนปัจจุบันเท่านั้น
- ตาราง: ห้อง / ผู้เช่า / น้ำ (ก่อน→ใหม่) / ไฟ (ก่อน→ใหม่) / จัดการ
  - แถวห้องที่ยังไม่บันทึกเดือนนี้: ปุ่ม "+ ยังไม่มีการบันทึก" → เปิด modal กรอกมิเตอร์ (4.2)
  - คอลัมน์ "จัดการ" ไอคอนนาฬิกา → เปิด modal ประวัติการจดมิเตอร์ (4.3)

### 4.2 Modal กรอกมิเตอร์รายห้อง
- แสดงชื่อห้อง + ชื่อผู้เช่า (ถ้ามี)
- กล่องเหลือง "กรอกค่ามิเตอร์ครั้งก่อน" (readonly): น้ำ, ไฟ — ดึงจาก current ของ record ล่าสุด (หรือ 0 ถ้าไม่เคยมีประวัติมาก่อนเลย)
- ช่องกรอก: "น้ำปัจจุบัน", "ไฟปัจจุบัน" — แค่ 4 ช่องรวม ไม่มีเพิ่ม (ไม่มี field รูปถ่าย/หมายเหตุ ตาม MVP)
- Validation ตอนกด "บันทึก":
  - เตือน (ไม่บล็อก) ถ้า current < prev (ค่าลดลง/ย้อนหลัง ผิดปกติ)
  - เตือน (ไม่บล็อก) ถ้าหน่วยที่ใช้ (current - prev) สูง/ต่ำผิดปกติเทียบค่าเฉลี่ยของห้องนั้นในเดือนก่อนๆ (เช่น ห่างเกิน threshold ที่ตั้งไว้)
  - ทั้งสอง flag เป็น warning inline ให้แอดมินยืนยันกดบันทึกซ้ำได้ ไม่ hard block
- บันทึกสร้าง MeterReading ใหม่ (append) พร้อม `reading_month` = เดือน/ปีปัจจุบัน, `recorded_by` = user ที่ล็อกอิน, `billing_status` = unbilled

### 4.3 Modal ประวัติการจดมิเตอร์ (ต่อห้อง)
รายการย้อนหลังทุก record ของห้องนั้น เรียงใหม่→เก่า แสดง:
- เดือน/ปี
- ค่าก่อน → ใหม่ (น้ำ, ไฟ แยกกัน)
- หน่วยที่ใช้ (น้ำ, ไฟ)
- วันที่/เวลาที่บันทึก + ชื่อผู้บันทึก
- สถานะบิล (ยังไม่ออกบิล / ออกบิลแล้ว → ล็อก)

### 4.4 Import/Export
- **Export**: ปุ่ม "Export ข้อมูลปัจจุบัน" → ไฟล์ CSV/XLSX รวมทุกห้องในอาคาร คอลัมน์: หมายเลขห้อง, มิเตอร์น้ำครั้งล่าสุด, มิเตอร์น้ำปัจจุบัน (ว่างให้กรอก), มิเตอร์ไฟครั้งล่าสุด, มิเตอร์ไฟปัจจุบัน (ว่างให้กรอก)
- **Template**: ปุ่มโหลดไฟล์ตัวอย่างเปล่า (โครงคอลัมน์เดียวกัน ไม่มีข้อมูล)
- **Import**: อัปโหลดไฟล์ CSV/XLSX กลับเข้าระบบ
  - นำเข้าทุกแถวเสมอ แม้เจอค่าผิดปกติ (เช่น น้อยกว่าค่าก่อนหน้า) — ไม่ปฏิเสธทั้งไฟล์ ขึ้น flag เตือนต่อแถวเหมือน validation ปกติใน UI (4.2)
  - แถวที่หาห้องไม่เจอ (เลขห้องไม่ตรง) → ข้ามแถวนั้น + แจ้งสรุปตอนจบ

## 5. Action/ฟังก์ชันสรุป

| Action | รายละเอียด |
|---|---|
| บันทึกมิเตอร์รายห้อง | สร้าง MeterReading record ใหม่ (append-only), คำนวณ units, ตั้ง billing_status=unbilled |
| แก้ไขมิเตอร์ที่บันทึกแล้ว | แก้ได้เฉพาะ record ที่ billing_status=unbilled เท่านั้น — ถ้า billed แล้ว ล็อกแก้ไขไม่ได้ (ต้องไปจัดการที่โมดูลบิล) |
| ดูประวัติย้อนหลัง | เปิด modal 4.3 |
| Export ข้อมูล | ดาวน์โหลดสถานะปัจจุบันทุกห้องเป็น CSV/XLSX |
| Import ข้อมูล | อัปโหลดไฟล์กรอกล่วงหน้า → สร้าง record ใหม่ทีละห้องเหมือนกรอกเดี่ยว |

## 6. ความสัมพันธ์กับโมดูลอื่น

- **ห้องพัก**: มิเตอร์เริ่มต้นตอน check-in/ย้ายห้อง (บังคับกรอกตอนย้ายห้อง) จะสร้างเป็น MeterReading แรกของห้องนั้น (`reading_month` = เดือนที่ check-in) เพื่อให้มีค่า "ก่อน" ตั้งต้น
- **จองห้อง**: ฟอร์มจองมีช่องมิเตอร์เริ่มต้นแบบไม่บังคับ — ถ้ากรอกมา ก็ผูกเป็น MeterReading แรกเหมือนกัน
- **บิล (ยังไม่ทำ)**: โมดูลบิลจะ query MeterReading ที่ billing_status=unbilled ของห้อง ไปคำนวณเงินด้วยอัตราปัจจุบัน (สาขา + override) แล้วอัปเดต billing_status→billed พร้อม bill_id — ไม่ใช่หน้าที่ของโมดูลนี้สร้างบิลเอง

## 7. Out of scope (MVP)

- แท็บ/ฟีเจอร์ผู้เช่าถ่ายรูปส่งมิเตอร์เอง — ตัดทิ้งทั้งหมด ไม่เก็บ backlog
- การคำนวณ/แสดงยอดเงินในหน้านี้
- concept "รอบ/งวด" ระดับอาคารที่ต้องปิดรอบพร้อมกัน
