# Prompt สำหรับแชทใหม่ — ต่อจาก module "เอกสารสัญญา" (ห้องพัก, จองห้อง, มิเตอร์น้ำ-ไฟ, ผู้เช่า, เอกสารสัญญา เสร็จหมดแล้ว)

คัดลอกทั้งหมดด้านล่างนี้ไปวางเป็นข้อความแรกในแชทใหม่ แล้วแนบภาพแคปหน้าจอของ module ที่จะทำต่อ (ค่าเริ่มต้นด้านล่างตั้งไว้เป็น "บิลค่าเช่า" — แก้เป็น module อื่นได้ถ้าจะเปลี่ยนลำดับ)

---

ฉันกำลังพัฒนา **ระบบจัดการอพาร์ตเมนต์** โดยอ้างอิงจากโปรแกรมต้นแบบที่มีอยู่แล้ว เป้าหมายคือทำให้ฟังก์ชันการทำงานและหน้าตาใกล้เคียงต้นแบบก่อน ส่วนฟีเจอร์เพิ่มเติมจะทำทีหลัง

**วิธีทำงาน:** ฉันทำทีละ module แยกกันคนละแชท เพื่อไม่ให้ context ปนกัน

**สิ่งที่ต้องการจากคุณในแชทนี้:**
1. ดูภาพแคปหน้าจอที่แนบมา (module: **บิลค่าเช่า** — ระบุใหม่ถ้าเปลี่ยน)
2. วิเคราะห์โครงสร้างหน้าจอ: layout, ฟิลด์ข้อมูล, ปุ่ม/action, ตาราง, filter/search, validation
3. สรุปเป็น **prompt/สเปค** สำหรับสร้างโค้ดจริง ครอบคลุม: ชื่อ/หน้าที่ module, Data model, หน้าจอย่อย, Action/ฟังก์ชัน, ความสัมพันธ์กับ module อื่น
4. **ถามฉันให้ละเอียด/ครบก่อนเสมอ** (ทีละ 4 ข้อ เพราะเครื่องมือจำกัด) ก่อนสรุปสเปคจบ — อย่าเดาเอง ถ้าจุดไหนไม่ชัดจากภาพให้ถาม
5. หลังสรุปสเปคแล้ว รอฉัน confirm ก่อนค่อยเริ่ม implement โค้ดจริง — **อย่าเพิ่งลงมือเขียนโค้ดจนกว่าฉันจะบอกให้เริ่ม** แม้จะดูเหมือนพร้อมแล้วก็ตาม

**Tech stack:** Next.js 14 (App Router) + Prisma + SQLite — ตัดสินใจแล้วจากงานก่อนหน้า อยู่ที่ `D:\ระบบ อพาร์มเม้นท์\code`

**โฟลเดอร์เก็บสเปค/เอกสารวางแผน (ไม่ใช่โค้ด):** `D:\ระบบ Aparment ลึก` — ให้เซฟไฟล์สรุปสเปค (`module_xxx_key_features.md`) และไฟล์ prompt แชทถัดไปไว้ที่นี่เสมอ **อย่าเซฟเอกสารสเปคไว้ในโฟลเดอร์โค้ด** (`D:\ระบบ อพาร์มเม้นท์\code\docs` มีเอกสารเก่าที่ล้าสมัย/ผิดสเปคอยู่ — อย่ายึดเป็นหลัก)

**รายการ Module ทั้งหมด:**
1. ภาพรวม (Dashboard)
2. ห้องพัก (ห้องพัก ✅ สเปคเสร็จ, จองห้อง ✅ สเปคเสร็จ, มิเตอร์น้ำ-ไฟ ✅ สเปคเสร็จ) — **ยังไม่ implement โค้ดจริงเลยสักตัว รอทำพร้อมกันทีหลัง**
3. ผู้เช่า (ผู้เช่า ✅ สเปคเสร็จ, เอกสารสัญญา ✅ สเปคเสร็จ) — **ครบทุกตัวในหมวดนี้แล้ว**
4. การเงิน (**บิลค่าเช่า ← กำลังทำ**, บิลกำหนดเอง, ค่าใช้จ่าย, ฐานข้อมูลบัญชี, แจ้งซ่อม, พัสดุ)
5. สื่อสาร
6. ประวัติการใช้งาน
7. ตั้งค่า
8. รายงาน (Reports — export Excel/CSV)

**Module ที่กำลังทำในแชทนี้:** บิลค่าเช่า

## [สำคัญ — สถาปัตยกรรมระดับระบบ] รองรับหลายอาคาร/สาขา (Multi-Building) ตั้งแต่แรก
- ระบบต้องรองรับเจ้าของที่มีมากกว่า 1 อาคาร/อพาร์ตเมนต์ ภายใต้บัญชีเดียวกัน
- ทุก entity ที่เกี่ยวกับห้อง (ห้อง, ชั้น, ผู้เช่า, บิล, ค่าตั้งสาขา ฯลฯ) ผูกกับ `building_id`
- ไม่แสดงหลายอาคารในหน้าเดียวกัน — ทุกหน้าจอแสดงเฉพาะอาคารที่กำลังเลือกอยู่
- การสลับอาคารทำงานเหมือน "สลับโปรไฟล์/workspace switcher" — เลือกตอน login ครั้งแรก และสลับได้จากหน้า "ตั้งค่า"
- เลขห้อง unique เฉพาะภายในอาคารเดียวกัน ไม่ unique ทั้งระบบ

## ⚠️ สถานะโค้ดจริงในโปรเจกต์ (สำคัญ อ่านก่อนเริ่ม)
โค้ดที่มีอยู่แล้ว (`app/rooms`, `app/bookings`, `prisma/schema.prisma`) เป็นเวอร์ชันเก่ากว่าที่ตัดสินใจไว้ในสเปคทุกไฟล์ในโฟลเดอร์นี้มาก (status ห้องมีแค่ 3 ค่า, ไม่มี multi-building, ไม่มี Gantt, Booking รองรับแค่รายวัน, ไม่มี meter reading) — **ห้องพัก/จองห้อง/มิเตอร์น้ำ-ไฟ/ผู้เช่า/เอกสารสัญญา ยังไม่ได้ implement โค้ดจริงเลย มีแต่สเปค** ถ้า module "บิลค่าเช่า" อ้างอิงข้อมูลห้อง/ผู้เช่า/มิเตอร์/สัญญา ให้อิงตามไฟล์สเปคในโฟลเดอร์นี้ ไม่ใช่โค้ดปัจจุบันในโปรเจกต์

## ลิงก์สเปคที่ทำเสร็จแล้ว (อ่านเพิ่มถ้าต้องอ้างอิง)
- `module_room_key_features.md` — ห้องพัก: สถานะห้อง, การคิดค่าน้ำ-ไฟ-เน็ต-ส่วนกลางต่อห้อง, Calendar/Gantt view
- `module_booking_key_features.md` — จองห้อง
- `module_meter_key_features.md` — มิเตอร์น้ำ-ไฟ: MeterReading data model (มี field `billing_status`/`bill_id` จองไว้ให้โมดูลบิลใช้ทีหลัง), ไม่มี concept รอบ/งวดระดับอาคาร
- `module_tenant_key_features.md` — ผู้เช่า: ข้อมูลผู้เช่า (รวมรายวัน+รายเดือน), กติกาห้ามผูกห้อง-ผู้เช่าจากหน้านี้ (ทำที่หน้าห้องเท่านั้น ยกเว้นตอนนำเข้าไฟล์/check-in), โครงสร้าง `room_occupancies` แยกจาก `tenants` (รองรับ 1 ผู้เช่าหลายห้อง), soft-delete/archive 2 ชั้น (มี auto-archive หลังย้ายออกครบทุกห้องเกิน 14 วัน), Flow เชื่อมต่อ LINE 2 วิธี
- `module_contract_key_features.md` — เอกสารสัญญา: ผูกกับ `tenant_id`+`room_id` (occupancy ผูกทีหลังได้ ไม่บังคับ), ข้อมูลผู้รับเงินตั้งค่าที่ "ตั้งค่าหอพัก" ครั้งเดียว (snapshot ต่อสัญญา), เซ็นสดบน iPad เท่านั้น (ไม่มีอัปโหลดไฟล์ในระบบ), ข้อสัญญาเป็น template กลางเริ่มต้น 12 ข้อ (เพิ่มได้ไม่จำกัด) รองรับสองภาษาไทย/อังกฤษ, **มี field ทางการเงินต่อสัญญาที่ module บิลน่าจะต้องใช้อ้างอิง**: `rent_amount`, `deposit_amount`, `payment_due_day`, `late_fee_per_day`, `advance_rent_amount`, `electrical_equipment_fee`, `furniture_equipment_fee`

สรุปย่อที่อาจเกี่ยวกับ "บิลค่าเช่า":
- ห้องมีสถานะ "มีผู้เช่า" (Occupied) ผูกกับผู้เช่าหลัก 1 record ต่อห้อง ผ่านตาราง `room_occupancies` (tenant_id + room_id + วันเข้า-ออก + มัดจำ)
- ค่าเช่า/วันกำหนดชำระ/ค่าปรับล่าช้า ถูกกำหนดไว้แล้วระดับสัญญา (`contracts.rent_amount` ฯลฯ) — บิลค่าเช่าน่าจะดึงค่าตั้งต้นจากตรงนี้ แทนที่จะให้กรอกใหม่
- มิเตอร์น้ำ-ไฟมี field `billing_status`/`bill_id` จองไว้ล่วงหน้าให้ module บิลมาผูกยอดค่าน้ำ-ไฟเข้ากับบิลได้ (ดู `module_meter_key_features.md`)
- ผู้เช่ารายวัน (walk-in) ไม่มีสัญญา — ต้องคุยให้ชัดว่าบิลค่าเช่ารายวันคิดเงินผ่านช่องทางไหน (อาจเป็นคนละ flow กับบิลรายเดือน)

## หมายเหตุการใช้งาน prompt นี้
- แก้ "Module ที่กำลังทำในแชทนี้" และหัวข้อภาพ ให้ตรงกับ module จริงที่จะทำ (ถ้าไม่ใช่ "บิลค่าเช่า")
- ถ้าเปลี่ยนไปทำ module ที่ไม่เกี่ยวกับห้องพัก/ผู้เช่า/สัญญาโดยตรง (เช่น "สื่อสาร") ตัดส่วนสรุปที่ไม่เกี่ยวออกได้ เก็บไว้แค่ส่วน Multi-Building ที่จำเป็นทุก module + ลิงก์ไปอ่านไฟล์สเปคที่เกี่ยวข้องในโฟลเดอร์นี้แทน
- หลังทำสเปค module ใหม่เสร็จในแต่ละแชท ให้สร้าง `module_xxx_key_features.md` ในโฟลเดอร์ `D:\ระบบ Aparment ลึก` แล้วอัปเดตไฟล์ `next_module_prompt.md` นี้ต่อ (mark ✅ module ที่เสร็จ + สรุปย่อผูกกับ module ถัดไป) เพื่อใช้เปิดแชทถัดไป
