# Prompt สำหรับแชทใหม่ — ต่อจาก module "ใบเสร็จ/ใบกำกับภาษี" (ห้องพัก, จองห้อง, มิเตอร์น้ำ-ไฟ, ผู้เช่า, เอกสารสัญญา, บิลรายเดือน, แจ้งซ่อม, พัสดุ, ใบเสร็จ/ใบกำกับภาษี เสร็จหมดแล้ว)

คัดลอกทั้งหมดด้านล่างนี้ไปวางเป็นข้อความแรกในแชทใหม่ แล้วแนบภาพแคปหน้าจอของ module ที่จะทำต่อ (**เลือก module ถัดไปจากรายการด้านล่าง** เช่น "สื่อสาร", "รายได้อื่นๆ/ค่าใช้จ่าย", "ฐานข้อมูลบัญชี", "ตั้งค่า" แล้วแก้ "Module ที่กำลังทำในแชทนี้" ให้ตรง)

---

ฉันกำลังพัฒนา **ระบบจัดการอพาร์ตเมนต์** โดยอ้างอิงจากโปรแกรมต้นแบบที่มีอยู่แล้ว เป้าหมายคือทำให้ฟังก์ชันการทำงานและหน้าตาใกล้เคียงต้นแบบก่อน ส่วนฟีเจอร์เพิ่มเติมจะทำทีหลัง

**วิธีทำงาน:** ฉันทำทีละ module แยกกันคนละแชท เพื่อไม่ให้ context ปนกัน (รอบนี้ทำ 2 module พร้อมกันในแชทเดียวเพราะเกี่ยวข้องกัน — ดู "Module ที่กำลังทำในแชทนี้" ด้านล่าง)

**สิ่งที่ต้องการจากคุณในแชทนี้:**
1. ดูภาพแคปหน้าจอที่แนบมา (module: **ระบุ module ที่จะทำ**)
2. วิเคราะห์โครงสร้างหน้าจอ: layout, ฟิลด์ข้อมูล, ปุ่ม/action, ตาราง, filter/search, validation
3. สรุปเป็น **prompt/สเปค** สำหรับสร้างโค้ดจริง ครอบคลุม: ชื่อ/หน้าที่ module, Data model, หน้าจอย่อย, Action/ฟังก์ชัน, ความสัมพันธ์กับ module อื่น — แยกไฟล์สเปคคนละไฟล์ต่อ module ถ้าทำหลาย module พร้อมกัน
4. **ถามฉันให้ละเอียด/ครบก่อนเสมอ** (ทีละ 4 ข้อ เพราะเครื่องมือจำกัด) ก่อนสรุปสเปคจบ — อย่าเดาเอง ถ้าจุดไหนไม่ชัดจากภาพให้ถาม
5. หลังสรุปสเปคแล้ว รอฉัน confirm ก่อนค่อยเริ่ม implement โค้ดจริง — **อย่าเพิ่งลงมือเขียนโค้ดจนกว่าฉันจะบอกให้เริ่ม** แม้จะดูเหมือนพร้อมแล้วก็ตาม

**Tech stack:** Next.js 14 (App Router) + Prisma + SQLite — ตัดสินใจแล้วจากงานก่อนหน้า อยู่ที่ `D:\ระบบ อพาร์มเม้นท์\code`

**โฟลเดอร์เก็บสเปค/เอกสารวางแผน (ไม่ใช่โค้ด):** `D:\ระบบ Aparment ลึก` — ให้เซฟไฟล์สรุปสเปค (`module_xxx_key_features.md`) และไฟล์ prompt แชทถัดไปไว้ที่นี่เสมอ **อย่าเซฟเอกสารสเปคไว้ในโฟลเดอร์โค้ด** (`D:\ระบบ อพาร์มเม้นท์\code\docs` มีเอกสารเก่าที่ล้าสมัย/ผิดสเปคอยู่ — อย่ายึดเป็นหลัก)

**รายการ Module ทั้งหมด:**
1. ภาพรวม (Dashboard)
2. ห้องพัก (ห้องพัก ✅ สเปคเสร็จ, จองห้อง ✅ สเปคเสร็จ, มิเตอร์น้ำ-ไฟ ✅ สเปคเสร็จ) — **ยังไม่ implement โค้ดจริงเลยสักตัว รอทำพร้อมกันทีหลัง**
3. ผู้เช่า (ผู้เช่า ✅ สเปคเสร็จ, เอกสารสัญญา ✅ สเปคเสร็จ) — **ครบทุกตัวในหมวดนี้แล้ว**
4. การเงิน (บิลรายเดือน ✅ สเปคเสร็จ, ใบเสร็จ/ใบกำกับภาษี ✅ สเปคเสร็จ [ออกแบบเองไม่ได้อิงภาพต้นแบบ — แก้ทีหลังได้], รายได้อื่นๆ ⬜, ค่าใช้จ่าย ⬜, ฐานข้อมูลบัญชี ⬜)
5. **งานซ่อมบำรุง (แจ้งซ่อม)** ✅ สเปคเสร็จ — [แยกหมวดต่างหาก ไม่รวมกับพัสดุ] รวม sub-feature "งานซ่อมบำรุง" (ล้างแอร์/อุปกรณ์ส่วนกลาง)
6. **พัสดุ** ✅ สเปคเสร็จ — [แยกหมวดต่างหาก ไม่รวมกับแจ้งซ่อม]
7. สื่อสาร
8. ประวัติการใช้งาน
9. ตั้งค่า
10. รายงาน (Reports — export Excel/CSV)

**Module ที่กำลังทำในแชทนี้:** ยังไม่ได้เลือก — ระบุ module ที่จะทำต่อ (ตัวเลือก: สื่อสาร / ประวัติการใช้งาน / ตั้งค่า / รายงาน / หรือกลับไปทำสเปคที่เหลือในหมวดการเงิน: รายได้อื่นๆ, ค่าใช้จ่าย, ฐานข้อมูลบัญชี)

## [สำคัญ — สถาปัตยกรรมระดับระบบ] รองรับหลายอาคาร/สาขา (Multi-Building) ตั้งแต่แรก
- ระบบต้องรองรับเจ้าของที่มีมากกว่า 1 อาคาร/อพาร์ตเมนต์ ภายใต้บัญชีเดียวกัน
- ทุก entity ที่เกี่ยวกับห้อง (ห้อง, ชั้น, ผู้เช่า, บิล, ค่าตั้งสาขา ฯลฯ) ผูกกับ `building_id`
- ไม่แสดงหลายอาคารในหน้าเดียวกัน — ทุกหน้าจอแสดงเฉพาะอาคารที่กำลังเลือกอยู่
- การสลับอาคารทำงานเหมือน "สลับโปรไฟล์/workspace switcher" — เลือกตอน login ครั้งแรก และสลับได้จากหน้า "ตั้งค่า"
- เลขห้อง unique เฉพาะภายในอาคารเดียวกัน ไม่ unique ทั้งระบบ

## ⚠️ สถานะโค้ดจริงในโปรเจกต์ (สำคัญ อ่านก่อนเริ่ม)
โค้ดที่มีอยู่แล้ว (`app/rooms`, `app/bookings`, `prisma/schema.prisma`) เป็นเวอร์ชันเก่ากว่าที่ตัดสินใจไว้ในสเปคทุกไฟล์ในโฟลเดอร์นี้มาก (status ห้องมีแค่ 3 ค่า, ไม่มี multi-building, ไม่มี Gantt, Booking รองรับแค่รายวัน, ไม่มี meter reading) — **ยังไม่ได้ implement โค้ดจริงเลยสักโมดูล มีแต่สเปค** ถ้า module ใหม่อ้างอิงข้อมูลห้อง/ผู้เช่า ให้อิงตามไฟล์สเปคในโฟลเดอร์นี้ ไม่ใช่โค้ดปัจจุบันในโปรเจกต์

## ลิงก์สเปคที่ทำเสร็จแล้ว (อ่านเพิ่มถ้าต้องอ้างอิง)
- `module_room_key_features.md` — ห้องพัก: สถานะห้อง, การคิดค่าน้ำ-ไฟ-เน็ต-ส่วนกลางต่อห้อง, Calendar/Gantt view, มี Tab "แจ้งซ่อม" ใน Room Detail Modal — เป็น data source เดียวกับ `module_repair`
- `module_booking_key_features.md` — จองห้อง
- `module_meter_key_features.md` — มิเตอร์น้ำ-ไฟ
- `module_tenant_key_features.md` — ผู้เช่า: ข้อมูลผู้เช่า, โครงสร้าง `room_occupancies` แยกจาก `tenants`, Flow เชื่อมต่อ LINE 2 วิธี — ใช้โดย `module_repair` (แจ้งซ่อมผ่าน LIFF) และ `module_parcel` (แจ้งเตือนพัสดุผ่าน LINE)
- `module_contract_key_features.md` — เอกสารสัญญา
- `module_bill_key_features.md` — บิลรายเดือน: Bill/BillLineItem/Payment data model, สถานะ 6 แบบ (คำนวณ overdue แบบ computed สด ไม่มี cron), บิลรายเดือน/บิลแรกเข้า, split payment แบบกดเพิ่มทีละครั้ง, ใบเสร็จ/ใบกำกับภาษีแยกเลข running number จากเลขบิล, หน้า "ใบเสร็จ" แยกต่างหาก, ปริ้นบิล/ใบเสร็จ A5 (ใบกำกับภาษี A4 formal), ต่อสัญญาอัตโนมัติสร้างสัญญาใหม่ทุกครั้ง
- `module_repair_key_features.md` — แจ้งซ่อม: RepairRequest data model, ใช้ data source เดียวกับ Tab "แจ้งซ่อม" ใน Room Detail Modal, แจ้งซ่อมผ่าน LINE LIFF (auto-link ห้อง/ผู้เช่าจาก LINE ID), แจ้งเตือนงานใหม่ในภาพรวม, รายชื่อช่าง (Technician) จัดการในหน้า "ตั้งค่า", ลบงาน = hard delete, sub-feature เสริม "งานซ่อมบำรุง" (ล้างแอร์ผูกห้อง + อุปกรณ์ส่วนกลางผูก SharedEquipment, ไม่มีแจ้งเตือนอัตโนมัติ)
- `module_parcel_key_features.md` — พัสดุ: Parcel data model (ไม่มี field ประเภทพัสดุ, รูปใบนำส่งไม่บังคับ), สถานะ 3 ขั้น (พัสดุเข้า/แจ้งลูกบ้านแล้ว/รับพัสดุแล้ว) + "ตกค้าง" เป็น flag คำนวณสดจาก `parcel_overdue_days`, แจ้งเตือนผ่าน LINE แบบกดเอง (ไม่ auto), เปลี่ยนสถานะย้อนกลับได้มี confirm dialog, ลบพัสดุ = hard delete, ตัด OCR อ่านชื่อผู้รับออกจากสโคป
- `module_receipt_key_features.md` — ใบเสร็จ/ใบกำกับภาษี: **ออกแบบเองไม่ได้อิงภาพต้นแบบ (แก้ทีหลังได้)** ไม่มี data model แยก ต่อยอดจาก `Payment` ใน module_bill (เพิ่ม field `receipt_no`/`tax_invoice_no` แยก sequence กัน + snapshot ข้อมูลผู้รับเงิน), ใบเสร็จออกอัตโนมัติทุกครั้งที่ชำระ (A5), ใบกำกับภาษีเป็น toggle เสริม (A4 formal, ไม่คิด VAT เพราะค่าเช่าที่พักยกเว้นภาษีตามกฎหมาย), หน้ารายการแยกต่างหากในเมนูย่อยการเงิน ต้องรอ module "ตั้งค่า" ทำ field ข้อมูลกิจการ (ชื่อ/ที่อยู่/เลขผู้เสียภาษี) ให้ก่อนถึงจะ implement ได้ครบ

สรุปย่อที่อาจเกี่ยวกับ module ถัดไป:
- ระบบ multi-building — ทุก module ใหม่ต้องผูกกับ `building_id` และห้อง/ผู้เช่าเหมือน module อื่นทั้งหมด
- ถ้าทำ "สื่อสาร" ถัดไป: อาจเกี่ยวกับช่องทาง LINE เดียวกับที่ใช้ใน `module_repair`/`module_parcel`/`module_tenant` — ควรดูรูปแบบการส่งข้อความ LINE ที่ตกลงไว้แล้วในสามไฟล์นี้ให้สอดคล้องกัน

## หมายเหตุการใช้งาน prompt นี้
- แก้ "Module ที่กำลังทำในแชทนี้" และหัวข้อภาพ ให้ตรงกับ module จริงที่จะทำ (ถ้าไม่ใช่ "แจ้งซ่อม และ พัสดุ")
- ถ้าเปลี่ยนไปทำ module ที่ไม่เกี่ยวกับห้องพัก/ผู้เช่า/สัญญาโดยตรง (เช่น "สื่อสาร") ตัดส่วนสรุปที่ไม่เกี่ยวออกได้ เก็บไว้แค่ส่วน Multi-Building ที่จำเป็นทุก module + ลิงก์ไปอ่านไฟล์สเปคที่เกี่ยวข้องในโฟลเดอร์นี้แทน
- หลังทำสเปค module ใหม่เสร็จในแต่ละแชท ให้สร้าง `module_xxx_key_features.md` ในโฟลเดอร์ `D:\ระบบ Aparment ลึก` แล้วอัปเดตไฟล์ `next_module_prompt.md` นี้ต่อ (mark ✅ module ที่เสร็จ + สรุปย่อผูกกับ module ถัดไป) เพื่อใช้เปิดแชทถัดไป
