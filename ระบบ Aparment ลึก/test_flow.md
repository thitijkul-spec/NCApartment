# Test Flow — ระบบจัดการอพาร์ตเมนต์ (ทดสอบทั้งระบบ)

เอกสารนี้ไล่ทดสอบทีละโมดูลตามลำดับ **dependency** (ไม่ใช่ลำดับเมนู) เพื่อให้เจอบั๊กต้นน้ำก่อน จะได้ไม่ต้อง retest หน้าปลายน้ำซ้ำเวลาบั๊กต้นน้ำถูกแก้ทีหลัง — อ้างอิงลำดับจาก `feedback-dormitory-dev-workflow` memory

**Login (dev):** username `owner` / password `owner1234` (ถ้า login ไม่ผ่าน อาจมีการรีเซ็ตรหัสไปแล้ว ให้เช็ค `prisma.user.findMany()`)

**วิธีอ่าน:** แต่ละหัวข้อมี Precondition → ขั้นตอนทดสอบ → ผลที่ควรเห็น → จุดที่มักพลาด (edge case ตามสเปค) ทำเรียงจากบนลงล่างได้เลย ข้ามได้ถ้าโมดูลนั้นยังไม่กระทบ sprint ปัจจุบัน

## Phase 0 — Login / Building Selector

1. Login ด้วย owner/staff → เข้าหน้า Dashboard (หรือ Building Selector ถ้ามีมากกว่า 1 อาคาร)
2. Login ผิด password → ต้อง reject พร้อมข้อความ error ชัดเจน
3. ถ้ามีหลายอาคาร: เลือกอาคาร A → ทุกหน้าจอต้องกรองข้อมูลเฉพาะอาคาร A เท่านั้น (ห้าม leak ข้อมูลอาคาร B) → สลับไปอาคาร B จากเมนู "ตั้งค่า"/สลับอาคาร แล้วเช็คว่าข้อมูลเปลี่ยนตาม

## Phase 1 — ห้องพัก (Rooms) — ต้นทางของทุกโมดูล ทดสอบก่อนเสมอ

### 1.1 CRUD ห้องเดี่ยว
- เพิ่มห้องใหม่: เลขห้อง (ลองแบบ "A101" ผสมตัวอักษร), ชั้น, ประเภทการรองรับ (ลองทั้ง 3 แบบ: รายวัน/รายเดือน/ทั้งคู่), ราคา, มัดจำ, ค่าน้ำ-ไฟ-เน็ต-ส่วนกลาง (ลอง "ไม่คิด" / "ใช้ตามสาขา" / override เอง — เช็คว่า "ไม่คิด" ต้อง override ทุกกรณีแม้ติ๊ก "ใช้ตามสาขา" ไว้ด้วย), amenities, อัปโหลดรูป (ลองเกิน 10 รูป/เกิน 10MB ต้องมี error), เลือกรูปปก
- แก้ไขห้อง: เปลี่ยนราคา/สถานะ → บันทึกแล้วเช็คว่าการ์ดอัปเดตถูก
- **กฎสำคัญ**: ห้องที่มีผู้เช่าอยู่ ลองแก้ "ประเภทการรองรับ" ให้เหลือแบบที่ไม่ตรงกับสัญญา/การจองปัจจุบัน → ต้อง**บล็อก**พร้อมข้อความอธิบาย
- ลบห้องว่าง/ปิดปรับปรุง → ลบได้
- ลบห้องที่มีผู้เช่า หรือ "จองแล้ว" → ต้อง**บล็อก** พร้อมข้อความอธิบายเหตุผล

### 1.2 สร้างหลายห้องพร้อมกัน (Bulk create)
- ตั้งช่วงชั้น+เลขห้อง auto-generate → เช็ค preview table ถูกต้อง, แก้ไขบางแถวใน preview ได้, ลบแถวออกได้, เพิ่มแถวนอกช่วงได้
- กด "สร้างทั้งหมด (N ห้อง)" → เช็คจำนวนห้องที่สร้างจริงตรงกับ N

### 1.3 Multi-select mode
- เข้าโหมดเลือกหลายห้อง → เลือกห้องว่าง 2-3 ห้อง + ห้องที่มีผู้เช่า 1 ห้องปนกัน
- กด "แก้ไขที่เลือก" → บันทึก → เช็คว่า field ที่ค่าไม่ตรงกันตอนแรกแสดง placeholder "หลายค่า" ไม่ใช่ดึงค่าห้องแรกมาโชว์เฉย ๆ
- กด "ลบที่เลือก" (มีห้องมีผู้เช่าปนอยู่) → ต้อง**บล็อกทั้งชุด** (ไม่ partial-success) พร้อมระบุชื่อ/เลขห้องที่ลบไม่ได้ชัดเจน (เช่น "ไม่สามารถลบห้อง 101, 105 ได้")

### 1.4 Filter tabs / View switch
- เช็คตัวนับแต่ละ tab (ทั้งหมด/รายเดือน/รายวัน/ว่าง/มีผู้พัก/ปิดปรับปรุง) ตรงกับจำนวนจริง
- สลับ Grid ↔ List ↔ Calendar → ข้อมูลต้องตรงกันทั้ง 3 view
- Calendar (Gantt รายสัปดาห์): เลื่อนสัปดาห์ก่อนหน้า/ถัดไป, กลับ "วันนี้"; คลิกแท่งห้องที่มีข้อมูล → เปิด Room Detail; คลิกช่องว่าง → เปิด modal จอง/เพิ่มผู้เช่า พร้อม prefill วันที่ที่คลิก
  > **หมายเหตุ:** ตาม memory ระบบยังมี known gap เรื่อง Calendar View — ถ้ายังไม่ implement ข้ามข้อนี้ไปเลย ไม่ต้อง report เป็นบั๊ก

### 1.5 Room Detail Modal (6 tabs)
- เปิดจากคลิกห้อง → เช็คครบ 6 tab: ข้อมูลห้อง, ผู้เช่า, สัญญา, มิเตอร์, แจ้งซ่อม, การชำระ
- Tab "ผู้เช่า" ห้องว่าง → ปุ่ม "+ เพิ่มผู้เช่า" / "จองห้อง" ต้องมีทั้งคู่

## Phase 2 — จองห้อง (Booking)

Precondition: มีห้องว่างอย่างน้อย 2-3 ห้อง

1. **สร้างการจอง**: เลือกห้อง (dropdown ต้องแสดงทุกห้องไม่กรองสถานะ) → toggle รายเดือน/รายวัน → กรอกวันเข้าพัก + (รายวัน: จำนวนคืน auto-คำนวณวันออก) → กรอกมัดจำแบบ split payment (เงินสด+โอนหลายบัญชี) หรือปล่อย 0 บาท (จองเปล่า) → บันทึก
2. เช็คว่า**ห้องเปลี่ยนเป็น "จองแล้ว" ทันที** (สีต่างจาก "มีผู้เช่า" ชัดเจน) ตั้งแต่ status ยัง "รอยืนยัน"
3. **ยืนยันการจอง** → status → "ยืนยันแล้ว"
4. **เช็คอินจากการจอง**: กดเช็คอินจากรายการจอง → modal ต้อง prefill ข้อมูลผู้เช่า/วันที่/มัดจำจากตอนจองครบ → ตรวจว่า**เงินมัดจำที่วางไว้ตอนจองถูกหักลบกับบิลค่าเช่างวดแรกอัตโนมัติ** → จบแล้ว booking.status = เสร็จสิ้น, ห้อง = มีผู้เช่า
5. **ยกเลิกการจอง** (ต้องเป็น owner เท่านั้น — ลอง login เป็น staff แล้วเช็คว่าปุ่มถูกซ่อน/บล็อก): เลือกคืน/ไม่คืนเงินมัดจำ → ห้องกลับเป็น "ว่าง"
6. ค้นหาด้วยรหัสจอง/ชื่อ/เบอร์/เลขห้อง + filter 6 สถานะ ทำงานถูกต้อง
7. เช็ค edge case ที่ยืนยันไว้ในสเปค (ไม่ต้อง report เป็นบั๊ก): จองซ้อนทับวันเดียวกันในห้องเดียวกัน**ไม่ถูก block**, การจอง "จองแล้ว" ไม่หมดอายุอัตโนมัติ, จองล่วงหน้าไม่จำกัดวัน

## Phase 3 — Check-in เต็มรูปแบบ (จากห้องว่างโดยตรง ไม่ผ่านจอง)

1. กด "Check-in" จากห้องว่างที่รองรับทั้งรายวัน+รายเดือน → ต้องให้เลือกประเภทก่อน (ห้องรองรับแบบเดียว ต้องข้ามขั้นตอนนี้ไปเลย)
2. โหมด "สร้างผู้เช่าใหม่": กรอกฟอร์มเต็ม (หรือกดปุ่ม "สร้างข้อมูลสมมติ" ถ้ามี) → ทดสอบกรอกเบอร์โทร/เลขบัตรที่ซ้ำกับผู้เช่าเดิมในระบบ → ต้องมี**คำเตือนแต่ยังบันทึกได้** (ไม่บล็อก)
3. โหมด "เลือกจากผู้เช่าที่มีอยู่": ค้นหาด้วยชื่อ → เลือกผู้เช่าเดิม (ทดสอบเคสเช่า 2 ห้องพร้อมกัน)
4. ติ๊ก/ไม่ติ๊ก "เป็นการจองหรือไม่": ติ๊ก → จบแค่บันทึก สถานะห้อง = จองแล้ว, ไม่ผ่านขั้นตอนบิล — ไม่ติ๊ก → ต้องผ่านขั้นตอนทำบิล/รับเงินก่อนจบ
5. ขั้นตอนบิล/รับเงิน (ไม่ติ๊กจอง): สรุปยอด (ค่าเช่า+มัดจำ+ค่าใช้จ่ายอื่นของห้อง) → ทดสอบ**ส่วนลด**ทั้งแบบจำนวนเงินตายตัวและเปอร์เซ็นต์ → เปิด/ปิด**ใบกำกับภาษี** → เลือกวิธีชำระ (เงินสด/โอน+เลือกบัญชี) → ทดสอบ **split payment กดบันทึกทีละครั้ง** (เช่น จ่าย 300 ก่อน เช็คสถานะ "ชำระบางส่วน" แล้วจ่ายอีก 300 ให้ครบ) → ทดสอบจ่ายไม่ครบเจตนา (ปล่อยค้าง) แล้วเช็คว่ายอดค้างไปโผล่บนการ์ดห้อง
6. checkbox "ออกบิลแรกเข้าให้เลย" → auto-generate + ปิดบิลในคลิกเดียวถ้ากรอกครบยอด
7. เช็คว่าข้อมูลผู้เช่าที่กรอกตอน check-in **ไปโผล่ในโมดูล "ผู้เช่า" เต็มรูปแบบด้วย** (ไม่ใช่แค่เก็บย่อในฝั่ง booking)
8. ทดสอบมิเตอร์เริ่มต้น (ไม่บังคับ) — กรอกหรือเว้นว่างก็บันทึกได้

## Phase 4 — ผู้เช่า (Tenant)

1. หน้ารายการ: ค้นหาชื่อ/เบอร์/เลขห้อง, filter สถานะ (ปัจจุบัน/ย้ายออกแล้ว/ใกล้หมดสัญญา/ใกล้ถึงกำหนดชำระ/ค้างชำระ), filter ประเภท (รายวัน/รายเดือน) — ต้อง**ไม่รวม archived** โดย default
2. เปิดฟอร์ม "เพิ่มผู้เช่าใหม่" ตรง ๆ จากเมนูผู้เช่า → **ต้องไม่มีช่องเลือกห้อง** (business rule: ผูกห้องได้ที่หน้าห้องเท่านั้น)
3. แก้ไขข้อมูลผู้เช่า → ทุก field แก้ได้อิสระ
4. เปิด Modal รายละเอียดผู้เช่า: เช็ค badge ห้อง (ถ้าเช่าหลายห้อง แสดงหลายห้อง), กล่องแดง "หมดเวลาพักแล้ว" แสดงเมื่อ `วันนี้ > planned_checkout_date` (เฉพาะรายเดือน) — ปุ่ม "แก้ไข" ใช้เลื่อนวันออกแทนปุ่ม "ต่ออายุ" (ไม่มีปุ่มต่ออายุแยก)
5. ปุ่ม "ย้ายห้อง"/"ย้ายออก" ในหน้าผู้เช่า → ต้องพาไปหน้าห้อง (ไม่เปิด modal ในหน้าผู้เช่าเอง)
6. **นำเข้าไฟล์ (Import CSV/Excel)**: ทดสอบไฟล์ปกติ + ทดสอบแถวที่ระบุเลขห้องชนกับ occupancy active อยู่แล้ว → ต้อง**บล็อกเฉพาะแถวนั้น** ไม่ล้มทั้งไฟล์
7. **เชื่อมต่อ LINE (จับคู่มือ)**: ทดสอบจับคู่เบอร์โทรตรง/ไม่ตรง
8. ลบผู้เช่าที่ยัง active occupancy อยู่ → ต้อง**บล็อก** — ลบผู้เช่าที่ย้ายออกครบทุกห้องแล้ว → ลบได้ (soft delete จากรายการปกติ, hard delete จริงถ้ากดจากใน Archive)
9. ทดสอบ auto-archive ผู้เช่า (ยากทดสอบจริงเพราะเป็น batch job รายสัปดาห์ — ข้ามได้ ถือเป็น known behavior ไม่ใช่บั๊กถ้าไม่ทำงานทันที)

## Phase 5 — สัญญาเช่า (Contract)

Precondition: มีผู้เช่า+ห้องพร้อม (ทำต่อจาก Check-in ก็ได้ ปกติสัญญาสร้างพร้อม check-in อยู่แล้ว — เทสสร้างแยกเพิ่มเติมด้วย)

1. สร้างสัญญาใหม่: เลือกผู้เช่า (เดิม/สร้างใหม่) + ห้อง → เช็คว่าข้อมูลผู้รับเงินเป็น **read-only** ดึงจากตั้งค่าหอพัก (มีลิงก์ไปแก้ที่ตั้งค่า)
2. ค่าเช่า/มัดจำ auto-fill จากราคาห้อง → แก้ไขเป็นค่าอื่นได้อิสระ (ไม่กระทบราคาห้องตั้งต้น)
3. เลือกเปิด/ปิดข้อสัญญาจาก 12 ข้อ template — ทดสอบ checkbox "พิมพ์เอกสารสองภาษา" → preview ต้องมีข้อปิดท้าย "ภาษาที่ใช้บังคับ" ต่อท้ายเป็นข้อสุดท้ายเสมอ (เลขข้อคำนวณอัตโนมัติ ไม่ใช่เลข 13 ตายตัว) และปิด/ลบไม่ได้
4. กรอกพยาน (ไม่บังคับแม้ require_witness=true)
5. **เซ็นสัญญาผ่าน iPad (canvas)** → เซ็นแล้วเช็คว่าเอกสารสมบูรณ์
6. **แก้ไขสัญญาหลังเซ็นแล้ว** → บันทึก → เช็คว่า**ลายเซ็นถูกล้างทิ้งอัตโนมัติ** ต้องเซ็นใหม่
7. พิมพ์/ดาวน์โหลด PDF → เช็ค placeholder แทนค่าถูกต้อง (วันที่เป็น พ.ศ., จำนวนเงินสะกดเป็นตัวหนังสือไทยกำกับ)
8. ลบสัญญาที่ยังไม่เซ็น → ลบได้จริง (hard delete) — ลบสัญญาที่เซ็นแล้ว → ทำได้แค่ archive เท่านั้น
9. ทดสอบสร้างสัญญาซ้อนในห้องที่มีสัญญา active อยู่แล้ว → ต้องแค่**เตือน ไม่บล็อก**

## Phase 6 — มิเตอร์น้ำ-ไฟ

1. หน้ารายการ: เช็คการ์ดสรุป 3 อัน (รวมหน่วยน้ำ/รวมหน่วยไฟ/บันทึกแล้ว x/N) ตรงกับข้อมูลจริง
2. บันทึกมิเตอร์ห้องที่ยังไม่บันทึกเดือนนี้ → เช็คว่าค่า "ก่อน" ดึงจาก current ของ record ล่าสุดถูกต้อง
3. ทดสอบกรอกค่าปัจจุบัน**น้อยกว่าค่าก่อนหน้า** → ต้องมี**คำเตือน (ไม่บล็อก)** ยังกดบันทึกซ้ำได้
4. ทดสอบกรอกหน่วยใช้สูง/ต่ำผิดปกติเทียบเดือนก่อน ๆ → เตือนเช่นกัน ไม่บล็อก
5. ดูประวัติย้อนหลังต่อห้อง (modal 4.3) → เรียงใหม่→เก่าถูกต้อง แสดงสถานะบิล (ยังไม่ออก/ออกแล้ว→ล็อก)
6. แก้ไข record ที่ `billing_status=unbilled` → แก้ได้ — record ที่ `billed` แล้ว → ต้อง**ล็อกแก้ไขไม่ได้**
7. Export → ไฟล์ครบทุกห้อง / Import กลับเข้าไป → ทดสอบแถวที่หาห้องไม่เจอ (เลขห้องผิด) ต้องข้ามแถวนั้น+สรุปตอนจบ ไม่ปฏิเสธทั้งไฟล์

## Phase 7 — บิลรายเดือน & การชำระเงิน

Precondition: มีห้องมีผู้เช่ารายเดือนอย่างน้อย 2-3 ห้อง, มีมิเตอร์บันทึกไว้บางห้อง

1. **ออกบิล bulk**: เลือกรอบบิล(เดือน) → ยืนยัน → เช็คว่า generate เฉพาะห้องที่มีผู้เช่ารายเดือน+ยังไม่มีบิลเดือนนั้น (ข้ามห้องว่าง/รายวัน/มีบิลแล้ว) → เช็ค line items ครบ (ค่าเช่า+น้ำ+ไฟ+เน็ต+ส่วนกลาง+extra fees) และมิเตอร์ unbilled ถูก mark เป็น billed
2. ห้องที่ยังไม่บันทึกมิเตอร์เดือนนี้ → ออกบิลได้ปกติ แค่มี**คำเตือน ไม่บล็อก**
3. **ออกบิลแรกเข้า** (เดี่ยว): เลือกห้อง/ผู้เช่าที่ยังไม่เคยออกบิลแรกเข้า → prefill จากสัญญา แก้ไขได้ก่อนยืนยัน
4. **บันทึกการชำระ**: แอดมินกดยืนยันเอง (ไม่บังคับสลิป) → เช็คว่าสถานะบิลอัปเดตทันที + ออกใบเสร็จทันที
5. ทดสอบ **split payment แบบกดทีละครั้ง**: จ่ายครั้งที่ 1 ไม่ครบยอด → บิลเป็น "ชำระบางส่วน" → **ใบเสร็จออกแยกเป็นใบย่อยของยอดครั้งนั้น** (ไม่รวมเป็นใบเดียวตอนจบ) → จ่ายครั้งที่ 2 ให้ครบ → บิลเป็น "ชำระแล้ว"
6. ทดสอบเปิด toggle "ออกใบกำกับภาษี" ตอนบันทึกชำระ (ต่อครั้ง ไม่ใช่ต่อบิล) → บังคับกรอกข้อมูลผู้เสียภาษีก่อนบันทึก
7. เพิ่ม line item ค่าปรับล่าช้าเข้าไปในบิลที่ออกแล้ว → เช็คยอดรวมอัปเดต
8. **ยกเลิก/ลบบิลที่มี Payment ผูกอยู่แล้ว** → ต้อง**บล็อก** จนกว่าจะลบใบเสร็จของ payment เหล่านั้นก่อน (จากหน้าใบเสร็จ)
9. ยกเลิก/ลบบิลที่ยังไม่มี payment → สำเร็จ → ห้องกลับ "รอออกบิล" + มิเตอร์ที่ mark billed คืนกลับ unbilled
10. โหลด/พิมพ์ PDF: บิล/ใบเสร็จ ต้องเป็น A5, ใบกำกับภาษี A4
11. **ปริ้นบิล bulk**: เข้าโหมดเลือกหลายห้อง → พิมพ์รวมเป็น PDF เดียว แยกหน้าต่อบิล
12. ทดสอบสถานะ "เกินกำหนด" → เลื่อนวันที่ผ่าน due_date ของบิล unpaid → ต้องแสดง overdue ทันทีแบบ computed สด (ไม่ต้องรอ cron)

## Phase 8 — ใบเสร็จ/ใบกำกับภาษี

1. หน้ารายการ: filter ช่วงวันที่/ห้อง-ผู้เช่า/เลขที่เอกสาร/ประเภท ทำงานถูกต้อง
2. พิมพ์ซ้ำ: เลือกได้ทั้งใบเสร็จ(A5)/ใบกำกับภาษี(A4) แยกกันถ้ามีทั้งคู่
3. **ลบใบเสร็จ** → ต้องมี confirm dialog → หลังลบ: Payment ถูก void, **ยอดค้างของบิลเพิ่มกลับคืน** (unpaid/partially_paid ตามจริง) → ถ้าบิลไม่มี payment เหลือเลย ต้องกลับไปยกเลิก/ลบบิลได้แล้ว (เทสต่อเนื่องกับ Phase 7.8)

## Phase 10 — เช็คเอาท์ / ย้ายห้อง / เงินมัดจำ

1. **เช็คเอาท์**: จดมิเตอร์ล่าสุด → คำนวณบิลปิดยอด → เลือก/เพิ่มรายการหักลบมัดจำ (ค่าล้างแอร์/ทำความสะอาด/ของเสียหาย/custom) → เช็คสูตร: มัดจำ − (ค่าน้ำไฟงวดสุดท้าย + ค้างชำระอื่น + รายการหัก) = ยอดคืนสุทธิ (ทดสอบเคสติดลบ = ผู้เช่าต้องจ่ายเพิ่ม) → หลังจบ ห้องต้องกลับเป็น "ว่าง" ทันที
2. **ย้ายห้อง**: เลือกห้องปลายทาง (ต้องว่างเท่านั้น) → ปิดห้องเดิม (mini checkout เต็มรูปแบบ) → ทดสอบย้ายห้องได้แม้ห้องเดิมมียอดค้างชำระอยู่ (ไม่บล็อก) → ปรับค่าเช่าคืนตามสัดส่วนวันได้อิสระ (ไม่ auto-calculate บังคับ) → เปิดห้องใหม่ (**มิเตอร์เริ่มต้นบังคับกรอก** ต่างจาก check-in ปกติ) → เช็คว่าเงินมัดจำเก่า/ใหม่ทำ **netting** แสดงยอดสุทธิให้พนักงานเห็นครั้งเดียว แต่หลังบ้านบันทึกแยก 2 ธุรกรรม → เช็คว่าสัญญาเดิมถูกปิด + สร้างสัญญาใหม่ทันที
3. **คืนเงินมัดจำเต็มจำนวน** (จากโมดูลฐานข้อมูลบัญชี, sub-tab เงินมัดจำ): เลือกบัญชีจ่ายออก → เช็คว่าออกเอกสาร "ใบสำคัญคืนเงินมัดจำ" A4 + สถานะเปลี่ยนเป็น "คืนแล้ว" + LedgerEntry ขาออกถูกสร้าง
4. **ริบเงินมัดจำทั้งหมด**: กดริบ → สถานะเปลี่ยน "ริบทั้งหมด" ทันที + เช็คว่ามี `OtherIncome` หมวด "เงินมัดจำริบ" ถูกสร้างอัตโนมัติ (ไม่มีเอกสารแยกออกมา)
5. ยืนยันว่า**ไม่มีตัวเลือก "ริบบางส่วน"** — มีแค่คืนเต็ม/ริบเต็มเท่านั้น

## Phase 11 — ค่าใช้จ่าย (Expense) & รายได้อื่นๆ (Other Income)

### 11.1 ค่าใช้จ่าย
1. บันทึกค่าใช้จ่ายใหม่ multi-line: เพิ่มผู้ขาย (dropdown Contact + เพิ่มใหม่ inline) → เลือก ซื้อสด/ซื้อเชื่อ (เชื่อ→บังคับ due_date) → เพิ่มหลายบรรทัดรายการย่อย (หมวด 7 แบบ, ทดสอบ VAT ทั้ง 3 โหมด: ไม่มี/รวม/แยก, เปลี่ยน vat_rate) → เช็คยอดรวมหัวบิล = sum ของ total_with_vat ทุกบรรทัด (ปัดเศษ 2 ตำแหน่ง)
2. เลือก "ซื้อสด" → ต้อง auto-สร้าง ExpensePayment เต็มจำนวนทันที 1 รายการ
3. เลือก "ซื้อเชื่อ" → ยังไม่มี payment → เปิด modal จัดการการจ่ายเงิน → เพิ่มจ่ายทีละงวดจนครบ → payment_status ขยับ unpaid→partial→paid อัตโนมัติ
4. แก้ไข/ลบ Expense ที่มี payment ผูกอยู่แล้ว → ต้องทำได้อิสระ (ไม่ล็อก ต่างจากบิลผู้เช่า)
5. เช็ค stat cards + กราฟ (สัดส่วนตามประเภท, รายเดือนทั้งปี) อัปเดตตามข้อมูลจริง

### 11.2 รายได้อื่นๆ
1. บันทึกรายได้ใหม่: เลือกผู้ซื้อ toggle ผู้เช่า/ลูกค้าทั่วไป → ทดสอบทั้ง 2 แบบ → หมวด 10 แบบ → โครงสร้าง VAT/split payment เหมือน Expense ทุกจุด
2. เช็คว่า Contact ใช้ร่วมกับ module ค่าใช้จ่าย (เพิ่มที่นี่แล้วไปโผล่ dropdown ฝั่งค่าใช้จ่ายด้วย)

### 11.3 Contact (ผู้ซื้อ/ผู้ขาย)
- CRUD → ลบได้อิสระแม้มีประวัติ Expense/OtherIncome อ้างอิงอยู่ (hard delete, ข้อมูลเก่ามี snapshot แยกไม่กระทบ)

## Phase 12 — ฐานข้อมูลบัญชี (Accounting)

### 12.1 ทะเบียนเอกสาร (7 sub-tabs)
- เช็คทีละ sub-tab: ใบเสร็จรับเงิน / ใบแจ้งหนี้ / บิลกำหนดเอง(=รายได้อื่นๆ) / สัญญาเช่า / เงินมัดจำ / ค่าใช้จ่าย / บิลรายวัน — filter เดือน/ปี + สถานะชำระ + ค้นหา ใช้ร่วมกันทุกแท็บ
- Multi-select + "พิมพ์/บันทึก PDF (N)" หลายใบพร้อมกัน

### 12.2 บัญชีแยกประเภท
- เลือกบัญชี → เช็คยอดยกมา + ตาราง เดบิต/เครดิต/คงเหลือสะสม (running balance) คำนวณถูกต้องตรงกับ LedgerEntry จริง

### 12.3 จัดการบัญชี
- เพิ่มบัญชีใหม่ (ชื่อ/ประเภท/เลขบัญชี/ยอดยกมา) → เช็ค current_balance คำนวณสด = opening + LedgerEntry ทั้งหมด
- ลบบัญชีที่ยอดคงเหลือ ≠ 0 → ต้อง**บล็อก** (ปุ่มลบ disabled) — ต้องปิดใช้งาน (inactive) แทน — ลบบัญชียอด 0 → ลบได้

### 12.4 ยอดค้างชำระ/ค้างรับ
- ตาราง "ค้างรับ" (ผู้เช่าที่ยังค้างบิล) และ "ค้างจ่าย" (Contact ที่ยังค้างจ่ายค่าใช้จ่าย) ยอดรวมต่อคน/ราย ตรงกับข้อมูลจริง

### 12.5 บิลรายวัน (walk-in)
- ออกบิลรายวันใหม่จากแท็บนี้: เลือกห้อง(ต้องรองรับรายวัน)+ผู้เช่า(หรือสร้างใหม่) → กรอกจำนวนคืน → เช็คยอด auto-คำนวณจากราคาห้อง (nights × ราคา/คืน) ไม่รวมค่าน้ำ-ไฟแยก (เหมาในราคาแล้ว) → เลือกวิธีชำระ+บัญชี → ยืนยัน = **จ่ายแล้วทันที** ไม่มีสถานะค้างชำระ + สร้าง LedgerEntry ขาเข้าอัตโนมัติ

## Phase 14 — ภาพรวม (Dashboard)

1. Stat cards แถวบน: ห้องทั้งหมด/ว่าง/มีผู้เช่า/occupancy rate, รายรับ-รายจ่ายเดือนนี้, บิลค้างชำระ (จำนวน+ยอด) — เทียบกับตัวเลขจริงจากโมดูลต้นทาง
2. กราฟ 6 เดือน (รายรับ vs รายจ่าย, occupancy) — โหลดจริง ไม่ error
   > known gap ตาม memory: กราฟ occupancy 6 เดือนใช้ snapshot วันนี้ซ้ำทุกเดือน ไม่ใช่ room-nights จริง — **ไม่ต้อง report เป็นบั๊ก** ใช้ report "Occupancy Rate" ในหน้ารายงานแทนถ้าต้องการเลขจริง
3. การ์ดย่อย: งานแจ้งซ่อมค้าง/พัสดุตกค้าง/สัญญาใกล้หมดอายุ (≤60 วัน) → กด "ดูทั้งหมด" ไปหน้าจริง
4. Activity feed (AuditLog ล่าสุด) → **แสดงเฉพาะ owner** — login เป็น staff แล้วเช็คว่า section นี้หายไปทั้ง section
5. Quick actions (+เพิ่มผู้เช่า / +บันทึกพัสดุ / +แจ้งซ่อม / +บันทึกค่าใช้จ่าย) → เปิด modal เดิมของโมดูลนั้นจริง ไม่ใช่ฟอร์มปลอม
6. staff ที่ไม่มีสิทธิ์โมดูลไหน → quick action ของโมดูลนั้นต้องถูกซ่อน

## Phase 16 — ประวัติการใช้งาน (Audit Log)

1. Login เป็น **staff** → เมนู "ประวัติการใช้งาน" ต้อง**ไม่แสดงเลย** (ไม่ใช่แค่ซ่อนปุ่ม)
2. Login เป็น owner → ทำ action สำคัญ 2-3 อย่าง (เช่น สร้างห้อง, บันทึกชำระเงิน, ลบพัสดุ) → กลับมาหน้า Audit → เช็คว่า log ขึ้นครบพร้อม description ที่อ่านเข้าใจ, ไอคอนสีตาม action_type ถูก (เขียว=create, แดง=delete, ฟ้า=payment, เขียวอมฟ้า=status_change)

4. ค้นหา + filter module + filter action type ทำงานถูกต้อง
5. เช็คว่า auto-action (เช่น ริบเงินมัดจำ) แสดง actor เป็น "ระบบ (ริบเงินมัดจำ)" ไม่ใช่ชื่อ user จริง

## Phase 17 — ตั้งค่า (Settings)

1. **ข้อมูลกิจการ/ผู้รับเงิน**: แก้ไข → เช็คว่าสัญญา/ใบเสร็จเก่าที่ออกไปแล้วไม่เปลี่ยนตาม (snapshot) แต่สัญญา/บิลใหม่ใช้ค่าล่าสุด
2. **ค่าตั้งสาขา**: แก้ค่า default น้ำ/ไฟ/เน็ต/ส่วนกลาง/มัดจำ → เช็คว่าห้องที่ตั้ง "ใช้ตามสาขา" ไว้ **เปลี่ยนตามทันที** (live, ไม่ใช่ snapshot) ต่างจากสัญญา
3. **ผู้ใช้งาน/สิทธิ์**: สร้าง staff ใหม่ตั้ง username/password ตรง ๆ → กำหนด permission ระดับ module (7 หมวด) + อาคารที่เข้าถึงได้ → login ด้วย staff คนนั้นเช็คว่าเห็นเฉพาะเมนูที่ได้สิทธิ์ → ทดสอบปุ่ม "รีเซ็ตรหัสผ่าน" จาก owner
4. **ช่าง**: CRUD → ลบช่างที่มีงานผูกอยู่ → ต้องลบได้อิสระ งานเก่ากลายเป็น "ยังไม่มอบหมาย" ไม่ลบประวัติ
5. **ประเภทงานซ่อม**: CRUD → ลบประเภทที่มีงานอ้างอิงอยู่ → ลบได้ (เพราะ snapshot ชื่อไว้แล้ว)
6. **Template สัญญาเช่า**: แก้ไข/เพิ่ม/จัดลำดับ/ลบข้อสัญญา → เช็คว่าสัญญาที่ generate ไปแล้วก่อนหน้าไม่เปลี่ยนตาม (snapshot ตอนสร้าง)
7. **เชื่อมต่อ LINE OA**: กรอก placeholder → ปุ่มทดสอบการเชื่อมต่อ disabled/แจ้งเตือนถ้ายังไม่มีบัญชีจริง (ยอมรับได้ว่ายังใช้งานจริงไม่ได้)
8. **Building Selector**: ลบอาคาร → ต้องผ่าน 3 ขั้น (popup เตือน 2 ครั้ง + บังคับกรอกรหัสผ่าน owner) ก่อนลบจริง
