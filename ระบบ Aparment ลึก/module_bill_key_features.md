## 1. หน้าที่ของโมดูล

จัดการบิลรายเดือนของผู้เช่า**รายเดือนเท่านั้น** — ออกบิล, ติดตามสถานะการชำระ, บันทึก/ยืนยันการชำระเงิน, ออกใบเสร็จ/ใบกำกับภาษี, ส่งบิลผ่าน LINE หรือปริ้นแจกสำหรับห้องที่ไม่เชื่อม LINE

**ขอบเขต multi-building:** ทุกอย่างในหน้านี้กรองตาม `building_id` ที่กำลังเลือกอยู่ รวมถึงเลขที่บิล/ใบเสร็จที่ต้องรันแยกตามอาคาร

### ไม่อยู่ในสโคปของโมดูลนี้ (ตัดออกจากภาพต้นแบบ)
- **ผู้เช่ารายวัน (walk-in)** — คิดเงินแยกไปเลยที่ module "ฐานข้อมูลบัญชี" ห้องโหมดรายวันขึ้นป้าย "รายวัน" + ข้อความ "บิลรายวันอยู่ที่หน้าบัญชี" กดออกบิลจากหน้านี้ไม่ได้
- **"บิลกำหนดเอง"** — ตัดออกทั้งหมด ย้ายไปเป็นส่วน **"รายได้อื่นๆ"** และ **"ค่าใช้จ่าย"** ในหมวดบัญชี (module แยก) ใช้สำหรับ ค่าซ่อมของส่วนตัว, จ้างแม่บ้าน, ค่าเสียหายของส่วนกลาง ฯลฯ

## 2. Data Model

```
Bill
- id
- bill_no               → string, running number แยกตามอาคาร (เช่น "BILL-2026-08-0001")
                            **แยกชุดจาก receipt_no/tax_invoice_no โดยเจตนา** — เผื่อระบบบัญชีในอนาคตต้องแยก
                            "ชุดส่งงบ" กับ "ชุดใช้ภายใน" ไม่ผูกเลขบิลกับเลขเอกสารการเงินเป็นชุดเดียวกัน
- building_id            → FK Building
- room_id                → FK Room
- tenant_id              → FK Tenant
- contract_id            → FK Contract (ที่มาของยอดตั้งต้น — บังคับ, เป็น snapshot ไม่ใช่ live reference)
- bill_type              → enum: monthly (บิลรายเดือน) | move_in (บิลแรกเข้า)
- billing_month          → string "YYYY-MM"
- issue_date             → date
- due_date               → date, auto-calc จาก contract.payment_due_day ตอนออกบิล
                            **ไม่มีการแก้ due_date หลังบิลออกแล้ว** แม้ลูกค้าขอผ่อนผัน/ต่อเวลา — ปล่อยให้ระบบ
                            ขึ้น "เกินกำหนด" ตามจริง แอดมินทราบจากบริบทเองว่ามีการตกลงผ่อนผันไว้ (ไม่บันทึกใน data model)
- status                 → enum: unpaid(รอชำระ) | partially_paid(ชำระบางส่วน) | pending_review(รอตรวจสอบ) | paid(ชำระแล้ว) | overdue(เกินกำหนด, คำนวณสด) | cancelled(ยกเลิก)
- discount_amount        → decimal, nullable
- notes                  → text, nullable
- created_at / updated_at

BillLineItem
- id
- bill_id                → FK Bill
- item_type              → enum: rent | water | electric | internet | common_area | extra_fee | deposit | advance_rent | equipment_electrical | equipment_furniture | late_fee
- description            → string
- quantity               → decimal, nullable (หน่วยที่ใช้ — water/electric)
- unit_price              → decimal, nullable
- amount                  → decimal

Payment
- id
- bill_id                → FK Bill
- amount                  → decimal
- method                  → enum: cash | transfer
- bank_account_id         → FK BankAccount, nullable
- source                  → enum: admin_manual | line_upload
- slip_image              → string url, nullable (ไม่บังคับทั้งสอง source)
- verified                → boolean, default true ถ้า admin_manual, default false ถ้า line_upload
- verified_by / verified_at → nullable
- paid_at                 → datetime
- issue_tax_invoice       → boolean, default false — **เลือกต่อการชำระแต่ละครั้ง** ไม่ใช่ต่อบิล
- taxpayer_name / taxpayer_tax_id / taxpayer_address → nullable, บังคับกรอกถ้า issue_tax_invoice=true
- receipt_no              → string, nullable — running number แยกตามอาคาร ออกให้ทุกครั้งที่มีการบันทึกชำระเงิน (ทั้งจ่ายครบและจ่ายบางส่วน)
- created_at
```

**หมายเหตุสำคัญเรื่องที่มาของยอดเงิน:**
- **ห้องเก็บแค่ "ราคามาตรฐาน"** (ค่าเช่าตั้งต้น, ค่าน้ำ/ไฟ/เน็ต/ส่วนกลาง) ใช้เป็นค่า default ตอนสร้างสัญญาใหม่เท่านั้น
- **สัญญา (Contract) คือ snapshot ยอดจริงที่ใช้ออกบิลเสมอ** — ดึงจาก `contracts.rent_amount`, `deposit_amount`, `payment_due_day`, `late_fee_per_day`, `advance_rent_amount`, `electrical_equipment_fee`, `furniture_equipment_fee`
- เหตุผล: ราคาห้องอาจเปลี่ยนไปตามเวลา แต่สัญญาที่เซ็นแล้วต้องคงยอดเดิมตลอดอายุสัญญา

**การคำนวณสถานะ "เกินกำหนด":** **computed สด ตอน query/แสดงผล** (ไม่มี cron job) — เช็คว่า `due_date < วันนี้` และ `status` ยังเป็น unpaid/partially_paid ก็ถือว่า overdue ทันที ไม่เก็บเป็น physical state ที่ต้องอัปเดต DB ล่วงหน้า

## 3. หน้าจอย่อย

### 3.1 หน้ารายการหลัก "บิลรายเดือน"
- Header: "บิลรายเดือน" + subtitle "จัดการบิลรายเดือนของแต่ละห้อง"
- Top bar: เลือกเดือน (◀ เดือน/ปี ▶ — `billing_month`), ปุ่มรีเฟรช, ปุ่ม "ประวัติสลิป", ปุ่ม "ส่ง LINE ทุกห้อง", ปุ่ม "ปริ้นบิล" (bulk — ดู 3.7), ปุ่ม "+ ออกบิล" (dropdown 2 ตัวเลือก — ดู 3.3)
- การ์ดสรุป 4 ใบ (นับเฉพาะบิลของ `billing_month` ที่กำลังดู): ทั้งหมด, รอชำระ, ชำระแล้ว, เกินกำหนด (จำนวนรายการ + ยอดเงินรวม)
- แท็บกรอง 6 สถานะ: ทั้งหมด / รอชำระ / ชำระบางส่วน / รอตรวจสอบ / ชำระแล้ว / เกินกำหนด
- รายการห้องจัดกลุ่มตามชั้น แสดงเป็นการ์ดห้อง สถานะ/ป้ายบนการ์ด (derived ไม่ได้เก็บเป็น field แยก):

| สถานะห้อง (บริบทบิล) | เงื่อนไข | สี |
|---|---|---|
| ยังไม่มีบิล | ห้องว่าง ไม่มีผู้เช่า | เทา |
| รายวัน | โหมดปัจจุบันของห้อง = รายวัน (ข้อความ "บิลรายวันอยู่ที่หน้าบัญชี" ไม่มี action ออกบิล) | ฟ้า |
| รอออกบิล | มีผู้เช่ารายเดือน แต่ยังไม่มี Bill record ของ `billing_month` ที่กำลังดู | เทาอ่อน/ป้ายใหม่ |
| รอชำระ / ชำระบางส่วน / รอตรวจสอบ / ชำระแล้ว / เกินกำหนด | มี Bill record แล้ว — ตรงตาม `Bill.status` (เกินกำหนด = computed) | ตามสี status |

**Multi-select mode** (สำหรับปริ้นบิล bulk — ดู 3.7): เปิดโหมดเลือกหลายห้องด้วย checkbox บนการ์ด (pattern เดียวกับ multi-select ของ module ห้องพัก)

### 3.2 Modal "ประวัติสลิป" (ปุ่มบน top bar)
- **ขอบเขต: รวมทุกห้องในอาคาร** ไม่ใช่ต่อห้อง
- แสดงรายการ Payment ทุกตัว (ไม่กรองตาม billing_month ปัจจุบัน) เรียงใหม่→เก่า: ห้อง, ผู้เช่า, ยอดเงิน, วิธีชำระ, ที่มา (LINE/แอดมิน), สถานะ (รอตรวจสอบ/ยืนยันแล้ว)
- ปุ่ม "ยืนยัน" ต่อรายการที่ยังไม่ verified → set `verified=true`, `verified_by`, `verified_at` แล้วคำนวณสถานะ Bill ใหม่ (paid ถ้ายอดครบ, partially_paid ถ้ายังไม่ครบ) + ออก `receipt_no` ให้ ณ จุดนี้ (ตรงกับตอนที่ยืนยันว่าเงินเข้าจริง)
- ปุ่มรีเฟรช

### 3.3 "+ ออกบิล" dropdown (2 ตัวเลือก)

**บิลรายเดือน (ทุกห้อง・รอเดือนนี้)**
- เปิด Modal "ออกบิล": เลือกรอบบิล (เดือน, ◀▶), แสดง "วันที่สร้างบิล" (default วันนี้) + "วันครบกำหนดชำระ" (auto-calc จาก `payment_due_day` ของสัญญาแต่ละห้อง), ปุ่ม ยกเลิก/ยืนยันออกบิล
- กดยืนยัน → generate Bill (bill_type=monthly) ให้ทุกห้องที่: มีผู้เช่ารายเดือนอยู่ + ยังไม่มี Bill ของเดือนนั้น (ข้ามห้องว่าง/ห้องรายวัน/ห้องที่มีบิลแล้ว)
- Line items ที่ generate อัตโนมัติต่อบิล: ค่าเช่า (จาก contract.rent_amount) + **ค่าใช้จ่ายทุกประเภทของห้องอัตโนมัติ**: ค่าน้ำ/ค่าไฟ (ดึงจาก MeterReading ที่ `billing_status=unbilled` × อัตราปัจจุบัน แล้ว mark เป็น `billed` พร้อมผูก `bill_id`) + ค่าอินเทอร์เน็ต + ค่าส่วนกลาง + ค่าใช้จ่ายอื่นๆ รายเดือนที่ตั้งไว้ที่ห้อง (`extra_monthly_fees`)
- ห้องที่มีผู้เช่าแต่ยังไม่บันทึกมิเตอร์ของเดือนนี้ → แจ้งเตือน แต่ไม่บล็อกการออกบิล
- ห้องที่เลือกไม่ครบเงื่อนไข (เช่นห้องว่าง) → toast แจ้งเตือน "ห้อง 106 — ยังไม่มีผู้เช่า ออกบิลไม่ได้"

**บิลแรกเข้า (ผู้เช่าใหม่・ทีละห้อง)**
- เลือกห้อง/ผู้เช่าที่มีสัญญาใหม่ยังไม่เคยออกบิลแรกเข้า
- Pre-fill รายการจากสัญญาของห้อง/ผู้เช่านั้น: ค่าเช่าเดือนแรก + เงินมัดจำ + ค่าเช่าล่วงหน้า + ค่าอุปกรณ์ไฟฟ้า + ค่าอุปกรณ์เฟอร์นิเจอร์ (แก้ไขได้ก่อนออกบิลจริง)
- bill_type = move_in

### 3.4 การชำระเงิน
สองช่องทางเข้าสู่สถานะ:
1. **แอดมินกดยืนยันเอง** — บันทึก Payment (source=admin_manual, verified=true ทันที) ไม่บังคับแนบสลิป → คำนวณสถานะบิลใหม่ทันที + ออกใบเสร็จ (receipt_no) ทันที
2. **ผู้เช่าอัปโหลดสลิปผ่าน LINE** — สร้าง Payment (source=line_upload, verified=false) → Bill.status = pending_review → แอดมินไปกดยืนยันที่ Modal "ประวัติสลิป" (3.2) → ออกใบเสร็จตอนยืนยัน

**บันทึกการชำระแบบแบ่งจ่าย (split payment):** บันทึกทีละครั้ง ไม่ใช่กรอกหลายแถวพร้อมกัน — กดปุ่ม "บันทึกการชำระ" → กรอกยอด+วิธีครั้งนี้ → บันทึก → ถ้ายังไม่ครบยอด บิลเป็น "ชำระบางส่วน" กดเพิ่มการชำระได้อีกเรื่อยๆ จนครบ **แต่ละครั้งที่บันทึก ออกใบเสร็จแยกเป็นใบย่อยของยอดครั้งนั้น** (ไม่รวมเป็นใบเดียวตอนจบ)
> ⚠️ ต้องแก้ flow check-in ของ module ห้องพัก (`module_room_key_features.md`) ให้ตรงกัน — เดิมสเปคห้องพักเป็นแบบกรอกหลายแถววิธีชำระพร้อมกันแล้วบันทึกทีเดียว ต้องเปลี่ยนเป็น "กดเพิ่มทีละครั้ง" แบบเดียวกับที่นี่

**ใบกำกับภาษี:** toggle **เลือกต่อการชำระแต่ละครั้ง** (ไม่ใช่ต่อบิล) — เปิดแล้วต้องกรอกข้อมูลผู้เสียภาษี (ชื่อ/เลขผู้เสียภาษี/ที่อยู่) ก่อนบันทึกการชำระครั้งนั้น

**ค่าปรับล่าช้า (เกินกำหนด):** ไม่คำนวณอัตโนมัติ — แอดมินกดเพิ่ม line item `late_fee` เข้าไปในบิลเดิมเองทีหลัง

### 3.5 หน้ารายละเอียดบิล (กดเข้าห้องที่มีบิล)
- แสดงรายการ line items ทั้งหมด, ยอดรวม, ประวัติการชำระ (Payment list ของบิลนี้ — แต่ละแถวมีปุ่มโหลด/พิมพ์ใบเสร็จของครั้งนั้น)
- ปุ่ม **โหลด/พิมพ์บิล PDF** — ขนาด **A5**
- ปุ่ม **ยกเลิก/ลบบิล** — ใช้กรณีออกบิลผิดห้อง/ผิดยอด → Bill.status = cancelled (ไม่นับใน summary/filter ปกติ), ห้องกลับสถานะ "รอออกบิล", **MeterReading ที่ถูก mark `billed` ไปแล้วคืนกลับเป็น `unbilled`** เพื่อออกบิลใหม่ได้
  - **บล็อกการยกเลิก/ลบบิลถ้ายังมี Payment (ที่มีใบเสร็จออกไปแล้ว) ผูกอยู่กับบิลนั้น** — ต้องไปลบใบเสร็จของ Payment เหล่านั้นก่อน (ที่หน้า "ใบเสร็จ" — ดู 3.8) จนบิลไม่มี Payment เหลืออยู่เลย จึงจะกดยกเลิก/ลบบิลได้
- ปุ่มเพิ่ม line item เข้าไปในบิลที่ออกแล้ว (เช่น ค่าปรับล่าช้า)

### 3.6 เอกสารที่พิมพ์ได้ — ขนาด/รูปแบบ

| เอกสาร | ขนาดกระดาษ | หน้าตา | ออกตอนไหน |
|---|---|---|---|
| บิล (Bill) | A5 | เรียบง่าย ประหยัดกระดาษ | เมื่อออกบิลแล้ว พิมพ์ได้ทันที |
| ใบเสร็จรับเงิน (ไม่มีภาษี) | A5 | เรียบง่าย | ทุกครั้งที่บันทึกการชำระ (แม้จ่ายบางส่วน) |
| ใบกำกับภาษี | **A4** | **Formal เต็มรูปแบบ** | เมื่อ toggle ใบกำกับภาษีเปิดตอนบันทึกการชำระครั้งนั้น |

### 3.7 ปริ้นบิลแบบ bulk (สำหรับห้องที่ไม่เชื่อม LINE)
- เข้าโหมดเลือกหลายห้องจากหน้ารายการหลัก (checkbox บนการ์ด — pattern เดียวกับ multi-select ของห้องพัก)
- แอดมิน**เลือกห้องเอง** (ไม่ auto-filter จากสถานะเชื่อม LINE ของผู้เช่า) — เผื่อกรณีอื่นที่อยากปริ้นด้วยตนเอง
- กดปุ่ม "ปริ้นบิล" → รวมบิลของห้องที่เลือกไว้เป็นไฟล์ PDF เดียว (แต่ละบิลแยกหน้า) ขนาด A5 ต่อบิล พร้อมพิมพ์/ดาวน์โหลด

### 3.8 หน้า "ใบเสร็จ" (แยกหน้าต่างหาก — เมนูย่อยในหมวดการเงิน)

> ผู้ใช้ยืนยันแล้วว่าอยากให้เป็น**หน้าแยกต่างหาก** เข้าถึงจากเมนูย่อยในหมวด "การเงิน" (ไม่ใช่ modal ผูกอยู่ในหน้า "บิลรายเดือน" เหมือน "ประวัติสลิป") — ข้อมูลยังอ้างอิง Payment/Bill ของโมดูลนี้โดยตรง จึง spec ไว้ในเอกสารนี้ก่อน แต่ให้เพิ่มเป็นรายการแยกใน "รายการ Module ทั้งหมด" ของ `next_module_prompt.md` ด้วย (หมวดการเงิน → "ใบเสร็จ/ใบกำกับภาษี")

- แสดงรายการใบเสร็จ + ใบกำกับภาษีทุกใบที่เคยออก (ทุก `billing_month`ไม่จำกัดแค่เดือนปัจจุบัน) เรียงใหม่→เก่า
- คอลัมน์: เลขที่ใบเสร็จ/ใบกำกับภาษี (`receipt_no`), ประเภท (ใบเสร็จ/ใบกำกับภาษี), ห้อง, ผู้เช่า, ยอดเงิน, วิธีชำระ, วันที่ออก, ปุ่มพิมพ์ซ้ำ (reprint PDF — A5 หรือ A4 ตามประเภท), ปุ่ม "ลบ"
- **Filter/ค้นหา (ครบทุกแบบ):** ช่วงวันที่, ห้อง/ผู้เช่า, เลขที่ใบเสร็จ/ใบกำกับภาษี, ประเภทเอกสาร (ใบเสร็จ/ใบกำกับภาษี)
- **ปุ่ม "ลบ" ต่อรายการ = ยกเลิกการชำระเงิน (Payment) ที่ผูกกับใบนั้นด้วย** ไม่ใช่แค่ซ่อนเอกสาร — ผลคือ:
  - Payment record ถูกลบ/void
  - ยอดค้างของ Bill ที่เกี่ยวข้องเพิ่มกลับคืน (สถานะ Bill กลับเป็น unpaid/partially_paid ตามยอดที่เหลือ)
  - ถ้า Bill นั้นไม่มี Payment เหลือเลย → สามารถกดยกเลิก/ลบ Bill ได้แล้ว (ดู 3.5)
  - ต้องมี confirm dialog ก่อนลบจริง (ป้องกันลบพลาด เพราะกระทบยอดบัญชี)

### 3.9 ส่ง LINE
- ปุ่ม "ส่ง LINE ทุกห้อง" → ส่งเฉพาะห้องที่มีบิลค้าง/ยังไม่ชำระ (status = unpaid, partially_paid, overdue) ของ `billing_month` ปัจจุบัน
- ถ้ายังไม่ได้ตั้งค่า LINE OA → toast "กรุณาตั้งค่า LINE ก่อนส่งบิล" บล็อกการส่ง

## 4. Action/ฟังก์ชันสรุป

| Action | รายละเอียด |
|---|---|
| ออกบิลรายเดือน (bulk) | สร้าง Bill+BillLineItem ให้ทุกห้องที่เข้าเงื่อนไขในรอบที่เลือก, ดึงค่าน้ำ/ไฟจาก MeterReading (unbilled→billed) |
| ออกบิลแรกเข้า (เดี่ยว) | สร้าง Bill (move_in) ต่อห้อง prefill จาก contract แก้ไขได้ก่อนยืนยัน |
| บันทึกการชำระ (แอดมิน, ทีละครั้ง) | สร้าง Payment verified ทันที ปรับสถานะบิล ออกใบเสร็จ (+ใบกำกับภาษีถ้าเลือก) |
| อัปโหลดสลิป (ผู้เช่า ผ่าน LINE) | สร้าง Payment รอตรวจสอบ → บิล pending_review |
| ยืนยันสลิป | แอดมินกดยืนยันใน "ประวัติสลิป" → verified=true → ปรับสถานะบิล + ออกใบเสร็จ |
| เพิ่ม line item ในบิลเดิม | เช่น ค่าปรับล่าช้า — แก้ยอดรวมบิลเดิม ไม่ออกบิลใหม่ |
| ยกเลิก/ลบบิล | เปลี่ยนสถานะ cancelled, ห้องกลับเป็น "รอออกบิล", คืนมิเตอร์เป็น unbilled |
| โหลด/พิมพ์ PDF | บิล/ใบเสร็จ (A5), ใบกำกับภาษี (A4 formal) |
| ปริ้นบิล bulk | เลือกหลายห้องเอง → รวม PDF A5 |
| ส่ง LINE ทุกห้อง | ส่งเฉพาะห้องที่มีบิลค้างของรอบปัจจุบัน |

## 5. ความสัมพันธ์กับโมดูลอื่น

- **ห้องพัก**: ยอดค้างชำระที่แสดงบนการ์ดห้องมาจาก Bill ของโมดูลนี้ (amount − sum(verified payments)) **ย้ายห้องได้แม้ห้องเดิมมีบิลค้าง** — บิลค้างไม่ถูกดึงมารวมกับการหักลบเงินมัดจำตอนย้ายห้อง ยังคงเป็นบิลค้างแยกที่ต้องตามเก็บต่อไปตามปกติ (อ้างอิงกฎเดิมใน `module_room_key_features.md`)
  - **⚠️ ต้องแก้ไข `module_room_key_features.md` เพิ่ม**: Check-in flow ส่วนรับชำระเงินแบบ split payment ต้องเปลี่ยนจาก "กรอกหลายแถวพร้อมกัน" เป็น "กดเพิ่มทีละครั้ง" ให้ตรงกับโมดูลนี้
- **สัญญา**: ยอดตั้งต้นของบิลดึงจาก contract แบบ snapshot เสมอ
  - **ต่อสัญญาอัตโนมัติ**: เมื่อสัญญารายเดือนครบกำหนดโดยไม่มีเช็คเอาท์ ระบบ**สร้างสัญญาใหม่**ทั้งฉบับ (ไม่ใช่แก้ end_date ของสัญญาเดิม) คัดลอกเงื่อนไขเดิม+ขยายวันที่ — บิลของเดือนถัดไปอ้างอิง `contract_id` ของสัญญาใหม่นี้
- **มิเตอร์น้ำ-ไฟ**: ตอนออกบิลรายเดือน query MeterReading ที่ `billing_status=unbilled` มาคำนวณเป็น line item แล้วอัปเดตเป็น `billed` พร้อม `bill_id` (ยกเลิกบิล → คืนกลับ unbilled)
- **ฐานข้อมูลบัญชี (ยังไม่ทำ)**: บัญชีธนาคารที่เลือกตอนบันทึกการชำระแบบโอน, และเป็นที่ที่บิลรายวัน + บิลกำหนดเอง (รายได้อื่นๆ/ค่าใช้จ่าย) ไปอยู่แทน
- **ผู้เช่า**: LINE ID ที่ใช้ส่งบิล/รับสลิป ดึงจากข้อมูลผู้เช่า
- **รายงาน (ยังไม่ทำ)**: ข้อมูลที่มีอยู่ในโมดูลนี้ (Payment.paid_at/method/verified, Bill.due_date/room_id/status) เพียงพอรองรับความต้องการรายงานที่แจ้งไว้แล้ว โดยไม่ต้องเพิ่ม field ตอนนี้:
  - ดูว่าใครจ่ายวันไหน, filter ช่วงวันที่, เรียงตามห้อง/ตามวันที่ชำระ
  - สรุปห้องที่จ่ายเร็ว vs ห้องที่ค้าง (ค้างเท่าไร ค้างกี่วัน — คำนวณจาก due_date)
  - สรุปยอดตามประเภทการรับเงิน (cash/transfer) ในช่วงเวลา สำหรับชนบัญชีกับ Bank Statement
  - สรุปยอดเงินสด vs โอน "วันนี้" สำหรับชนกับเงินสดในมือจริง

## 6. Out of scope (ตัดออกจาก MVP นี้)

- บิลกำหนดเอง (ย้ายไปเป็น "รายได้อื่นๆ"/"ค่าใช้จ่าย" ในหมวดบัญชี)
- บิลผู้เช่ารายวัน (อยู่ที่ module ฐานข้อมูลบัญชี)
- การคำนวณค่าปรับล่าช้าอัตโนมัติ (เป็นการกดเพิ่มเองของแอดมิน)
- การแก้ไข due_date ของบิลที่ออกแล้ว (ไม่รองรับผ่อนผันในระบบ ปล่อยเกินกำหนดตามจริง)
- module "รายงาน" เอง (แค่เตรียมข้อมูลให้พอ ไม่ได้ทำหน้าจอรายงานในสเปคนี้)
