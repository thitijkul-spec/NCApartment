# Module: รายได้อื่นๆ (Other Income)

> ไม่มีภาพหน้าจอต้นแบบแยกต่างหาก — ผู้ใช้ให้ทำ**โครงสร้างเดียวกันกับ `module_expense`** (เป็นระบบบัญชีคู่กัน คนละทิศทางเงิน) ดูรายละเอียด data model ที่มาจากการวิเคราะห์ภาพร่วมกับ `module_expense_key_features.md`

## หน้าที่ของ module
บันทึกและติดตามรายได้อื่นๆ ของแต่ละอาคาร ที่ไม่ใช่รายได้ค่าเช่า/บิลรายเดือนปกติ (เช่น ค่าปรับ, ค่าเช่าพื้นที่ส่วนกลาง/ป้ายโฆษณา, ดอกเบี้ยรับ, เงินมัดจำริบ ฯลฯ) — เดิมเคยเป็นส่วนหนึ่งของ "บิลกำหนดเอง" ที่ตัดออกจาก `module_bill` เช่นเดียวกับ `module_expense`

## ความสัมพันธ์กับระบบ multi-building
- OtherIncome ผูกกับ `building_id`
- ใช้ **Contact (ผู้ซื้อและผู้ขาย)** และ **Account** (เดิมชื่อ `BankAccount`, generalize แล้วตาม `module_accounting_key_features.md`) master data ชุดเดียวกับ `module_expense` (Contact ใช้ร่วมทุกอาคาร, Account แยกตามอาคาร)

## Data Model

### ผู้ซื้อ/ผู้จ่ายเงิน — เลือกได้ 2 แบบ (บังคับเลือกเสมอ)
เนื่องจาก "บางทีผู้เช่าเป็นผู้ซื้อ" ต้องรองรับทั้งผู้เช่าที่มีอยู่ในระบบ และลูกค้าทั่วไป:
- `buyer_type` — enum: `tenant` (ผู้เช่าในระบบ) / `contact` (ผู้ซื้อทั่วไปจาก master data)
- `buyer_tenant_id` — FK → Tenant (บังคับกรอกถ้า `buyer_type = tenant`)
- `buyer_contact_id` — FK → Contact (บังคับกรอกถ้า `buyer_type = contact`)

> UI: ตอนเลือกผู้ซื้อ มี toggle/tab ให้เลือก "ผู้เช่า" (ค้นหาจากห้อง/ชื่อผู้เช่า) หรือ "ลูกค้าทั่วไป" (ค้นหาจาก Contact + ปุ่มเพิ่มใหม่ inline)

### OtherIncome (หัวบิลรายได้)
- `id`
- `building_id`
- `document_no` — เลข running number เฉพาะของ module นี้ เช่น `INC-2569-08-001` **รันแยกต่ออาคาร** — **รีเซ็ตตัวนับท้ายทุกเดือน**
- `buyer_type`, `buyer_tenant_id`, `buyer_contact_id` (ตามด้านบน) *
- `buyer_name_snapshot`, `buyer_tax_id_snapshot`, `buyer_address_snapshot` — **snapshot ข้อมูลผู้ซื้อ ณ เวลาบันทึก** (ก็อปจาก Tenant หรือ Contact ตอนบันทึกครั้งแรก แล้วไม่เปลี่ยนตามภายหลัง)
- `room_id` — FK → Room (optional, ไม่บังคับผูกห้อง)
- `date` — วันที่รับรู้รายได้ * (ใช้เป็นฐานคำนวณสถิติ Dashboard)
- `sale_type` — enum: `cash` (รับเงินสดทันที) / `credit` (ขายเชื่อ ค้างรับ) *
- `due_date` — วันครบกำหนดรับเงิน (บังคับกรอกถ้า `credit`) — ไม่มีระบบแจ้งเตือนอัตโนมัติในภาพรวม ใช้ประกอบ filter เท่านั้น
- `sale_invoice_no` — เลขที่ใบกำกับภาษีขายที่ออกให้ผู้ซื้อ (ระดับหัวบิล, optional)
- `wht_amount` — ยอดที่ถูกผู้จ่ายหัก ณ ที่จ่าย (กรอกเอง เป็น memo field, ไม่กระทบการคำนวณอัตโนมัติ)
- `total_amount` — ยอดรวมทั้งบิล (คำนวณอัตโนมัติจากผลรวม `OtherIncomeLineItem.total_with_vat`)
- `payment_status` — enum คำนวณสด: `unpaid` / `partial` / `paid`
- `attachment_urls` — ไฟล์แนบ **หลายไฟล์ได้** (ถ้ามี)
- `notes`
- `created_at`, `updated_at`

> **แก้ไข/ลบได้อิสระ** แม้มีการบันทึก OtherIncomePayment ไปแล้วบางส่วน/ครบแล้วก็ตาม
>
> **`date` เลือกวันไหนก็ได้ ไม่ล็อกเฉพาะเดือนปัจจุบัน** รองรับการทำบิลย้อนหลัง/ข้ามเดือน และแก้ไขวันที่ของบิลเก่าได้อิสระ — สถิติ Dashboard จะขยับตามเดือนใหม่ที่แก้ทันที

> หมายเหตุ: กติกาการคำนวณเหมือน `module_expense` ทุกประการ — VAT ต่อรายการย่อย, ปัดเศษ 2 ตำแหน่ง, ไม่มีส่วนลด/ค่าใช้จ่ายเพิ่มระดับหัวบิล

### OtherIncomeLineItem (รายการย่อย — รองรับหลายรายการต่อบิล)
- `id`
- `other_income_id` — FK → OtherIncome
- `title` *
- `category` — enum fixed list (10 หมวด): `ค่าปรับ/ค่าเสียหาย` / `ค่าเช่าพื้นที่ส่วนกลาง/ป้ายโฆษณา` / `ดอกเบี้ยรับ` / `เงินมัดจำริบ` / `ขายของเก่า/เศษวัสดุ` / `ค่าจอดรถ` / `เครื่องซักผ้า/ตู้หยอดเหรียญ` / `ค่าธรรมเนียมเอกสาร` / `เงินสนับสนุนส่วนกลาง` / `อื่นๆ` *
- `amount` *
- `vat_mode` — enum: `none` / `included` / `excluded`
- `vat_rate` — % VAT, default `7`
- `vat_amount` — คำนวณอัตโนมัติ
- `total_with_vat` — คำนวณอัตโนมัติ
- `description`

### OtherIncomePayment (การรับเงิน — รองรับรับหลายครั้ง/หลายวิธี/หลายบัญชี)
- `id`
- `other_income_id` — FK → OtherIncome
- `amount`
- `method` — enum: `cash` / `transfer` / `check` / `credit_card`
- `account_id` — FK → Account (เดิมชื่อ `bank_account_id`; บังคับกรอกเสมอตอนนี้ เพราะทุกธุรกรรมต้องเลือกบัญชี รวมถึงเงินสด)
- `date`
- `slip_image_urls` — สลิปโอน/หลักฐานการรับเงิน **แนบต่อรายการรับนี้โดยเฉพาะ** (แยกจาก `attachment_urls` ที่หัวบิล)
- `notes`

> เมื่อเลือก `sale_type = cash` ตอนบันทึกครั้งแรก ระบบสร้าง OtherIncomePayment อัตโนมัติ 1 รายการเต็มจำนวนทันที เหมือน `module_expense`

### LedgerEntry
ใช้ตารางร่วมกับ `module_expense` — `source_type = other_income_payment` เมื่อบันทึกจาก OtherIncomePayment (ดูรายละเอียดใน `module_expense_key_features.md`)

## หน้าจอย่อย
โครงสร้างหน้าเหมือน `module_expense` ทุกจุด ต่างกันที่:
1. **List/Dashboard**: filter tab เปลี่ยนเป็น 10 หมวดของรายได้อื่นๆ, สถิติ/กราฟรูปแบบเดียวกัน (รวมเดือนนี้/รวมทั้งปี/เฉลี่ยต่อเดือน + กราฟสัดส่วน + กราฟรายเดือน) + filter เพิ่มเติม: สถานะรับ (unpaid/partial/paid), ผู้ซื้อ, ช่วงวันที่, ค้นหาด้วยเลขที่เอกสาร
2. **Modal บันทึก/แก้ไข (multi-line)**: เลือกผู้ซื้อ (ผู้เช่า/ลูกค้าทั่วไป) แทนผู้ขาย, ฟิลด์อื่นเหมือนกัน (ประเภทรับเงิน สด/เชื่อ, เลขใบกำกับภาษีขาย, หัก ณ ที่จ่าย, รายการย่อยหลายบรรทัด, VAT ต่อรายการ)
3. **Modal จัดการการรับเงิน**: เหมือน ExpensePayment แต่เป็นฝั่งรับเงิน
4. ใช้หน้าจัดการ Contact และ Account ร่วมกับ `module_expense` (ไม่ต้องสร้างหน้าซ้ำ) — รวมถึงกติกาลบ Contact ได้อิสระ, ไม่มี archive, ไม่มีเตือนรายการซ้ำ (ดูรายละเอียดใน `module_expense_key_features.md`)
5. **ไม่มีปุ่มดู/พิมพ์ PDF ในหน้านี้** — ดู/พิมพ์เอกสารรายตัวอยู่ที่ sub-tab "บิลกำหนดเอง" ใน module "ฐานข้อมูลบัญชี", ส่วนรายงานสรุป/วิเคราะห์/export อยู่ที่ module "รายงาน"

## Action/ฟังก์ชัน
- เพิ่ม/แก้ไข/ลบ OtherIncome (hard delete)
- เพิ่ม/ลบรายการย่อยแบบ dynamic
- เพิ่ม/แก้ไข/ลบ OtherIncomePayment
- คำนวณ VAT ต่อรายการย่อย + รวมยอดหัวบิลอัตโนมัติ
- คำนวณ `payment_status` อัตโนมัติ
- สร้าง LedgerEntry อัตโนมัติ (data model เตรียมไว้ ไม่มี UI กระทบยอดในรอบนี้)

## สิทธิ์การเข้าถึง (Permission)
เหมือนกับ `module_expense` ทุกประการ — ผูกกับ permission flag ระดับ module ของหมวด "การเงิน" (Owner เห็นหมด, Staff ที่ไม่มีสิทธิ์จะมองไม่เห็นเมนูนี้เลย) หน้าจัดการ user/role อยู่นอกสโคป รอ module "ตั้งค่า" — ดูรายละเอียดเพิ่มใน `module_expense_key_features.md`

## ความสัมพันธ์กับ module อื่น
- **module_expense**: ใช้ Contact, Account, LedgerEntry model ชุดเดียวกัน — โครงสร้างหน้าจอ/logic เหมือนกันเกือบทั้งหมด
- **module_tenant**: ผูก `buyer_tenant_id` เมื่อผู้ซื้อเป็นผู้เช่าในระบบ
- **module_room**: ผูก `room_id` แบบ optional
- **module ฐานข้อมูลบัญชี**: จัดการ Account ที่นี่ (ย้ายจากตั้งค่าเดิม) + ดึง LedgerEntry ไปแสดงในทะเบียนเอกสาร/บัญชีแยกประเภท + หน้าสรุปยอดค้างรับ (ดูด้านล่าง) + ดู/พิมพ์เอกสารรายตัว (sub-tab "บิลกำหนดเอง")
- **module รายงาน**: รายงานสรุป/วิเคราะห์/export Excel-CSV ของรายได้อื่นๆ (ไม่ใช่ดูเอกสารรายตัว — ย้ายไปฐานข้อมูลบัญชีแล้ว)

## นอกสโคปรอบนี้ (ตัดออกโดยเจตนา)
- หน้าสรุป "ยอดค้างรับทั้งหมด" ต่อผู้ซื้อ 1 คน — ไม่ทำในรอบนี้ **ย้ายไปอยู่ใน module ฐานข้อมูลบัญชี (แท็บ "ยอดค้างชำระ/ค้างรับ") แล้ว** ดู `module_accounting_key_features.md`
- ระบบแจ้งเตือนอัตโนมัติในภาพรวมสำหรับรายการค้างรับเกินกำหนด

## Assumption ที่ยังไม่ได้ยืนยัน (ควรถามผู้ใช้ตอนเริ่ม implement)
- Category 10 หมวดที่เสนอ ผู้ใช้ตอบว่า "ใช้ตามที่เสนอ" แล้ว — ยึดตามนี้ได้เลย ไม่ต้องถามซ้ำ
