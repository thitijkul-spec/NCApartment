# Key Feature Spec — Module: จองห้อง (Booking)
Sub-module ของ "ห้องพัก" (ห้องพัก ✅ / **จองห้อง ✅** / มิเตอร์น้ำ-ไฟ)

**สถานะ:** Design Complete — รอ implement (ขึ้นกับโมดูล "ห้องพัก" ต้องอัปเดตโค้ดจริงให้ตรงสเปคก่อน — ดูหมายเหตุท้ายไฟล์)

## หน้าที่ของโมดูล
จัดการรายการ "จองห้องล่วงหน้า" ก่อนเช็คอินจริง — บันทึกเจตนาจอง, เก็บมัดจำ (ถ้ามี), ติดตามสถานะจนถึงวันเช็คอินจริงหรือยกเลิก

## ตำแหน่งเมนู
Sub-tab ใต้ "ห้องพัก": `ห้องพัก / จองห้อง / มิเตอร์น้ำ-ไฟ`
**ปฏิทิน (Gantt รายสัปดาห์) อยู่ในโมดูล "ห้องพัก" เท่านั้น — ยืนยันแล้ว ไม่ทำซ้ำในโมดูลนี้** คลิกช่องว่างในปฏิทิน (ที่ห้องพัก) เปิด modal จองแบบเดียวกับที่ใช้ในโมดูลนี้
**ตัดออกจาก MVP:** ปุ่ม "ลิงก์จอง" (self-service booking link — ลูกค้าจองเองผ่านลิงก์สาธารณะ)

## Data Model
```
bookings (
  booking_id, booking_code (unique/building, auto-gen เช่น "202F3C71"),
  building_id, room_id,
  tenant_id (nullable ถ้าสร้างผู้เช่าใหม่พร้อมกัน — re-use mechanism เดียวกับฟอร์ม "เพิ่มผู้เช่า" ของห้องพัก),
  booking_type ENUM('monthly','daily'),
  checkin_date,
  contract_deadline_date   -- เฉพาะ monthly, ไม่บังคับ
  nights, checkout_date    -- เฉพาะ daily (nights auto คำนวณ checkout_date)
  deposit_amount           -- = SUM(booking_payments.amount), ไม่บังคับ (จองเปล่าได้ 0 บาท)
  note,
  status ENUM('pending','confirmed','cancelled','completed','archived'),
  cancel_reason (nullable),
  deposit_refunded BOOLEAN (nullable, ตั้งตอนยกเลิก),
  created_by, created_at, checked_in_at, checked_in_by, archived_at
)

booking_payments (
  payment_id, booking_id,
  method ENUM('cash','transfer'),
  bank_account_id (nullable, ref โมดูล "ฐานข้อมูลบัญชี" — บังคับถ้า method=transfer),
  amount,
  slip_url (nullable)
)
-- ยืนยันแล้ว: 1 booking รองรับหลายแถวการชำระพร้อมกัน (เช่น โอนบัญชี A 200 + บัญชี B 200 ในรายการเดียวกัน)
```

## สถานะ & Flow
```
รอยืนยัน → ยืนยันแล้ว → เสร็จสิ้น (หลัง check-in)
รอยืนยัน / ยืนยันแล้ว → ยกเลิก (สิทธิ์: owner เท่านั้น)
เสร็จสิ้น / ยกเลิก → เก็บแล้ว (archive)
```
- **ยืนยันแล้ว: ห้องเปลี่ยนเป็นสถานะ "จองแล้ว" ทันทีตั้งแต่สร้างการจอง** (สถานะ "รอยืนยัน") ไม่ต้องรอ staff กด "ยืนยัน"
- "ยืนยันแล้ว" = staff ตรวจสอบความถูกต้องแล้ว (เช่น ตรวจสลิป) — **ไม่มีสถานะ "รอตรวจสอบสลิป" แยกต่างหาก** (ตัดออกแล้ว)
- **"จองแล้ว" ไม่หมดอายุอัตโนมัติ** (ตามที่ตัดสินใจไว้ที่ห้องพัก) — ต้องมีคนกดยกเลิกเอง แม้เลยกำหนดทำสัญญาไปแล้ว
- ระบบ**ไม่ป้องกัน**การจอง/เช็คอินซ้อนทับวันเดียวกัน
- **เก็บแล้ว (archive)**: กดเก็บเองได้ทันที หรือ auto-archive อัตโนมัติ 3 วันหลังเข้าสถานะ เสร็จสิ้น/ยกเลิก
- **แก้ไขข้อมูลการจอง** (ห้อง/วันที่/ยอดเงิน) ทำได้ตราบใดที่ยังไม่เช็คอิน (สถานะ รอยืนยัน/ยืนยันแล้ว)
- **จองล่วงหน้าได้ไม่จำกัดระยะเวลา** ไม่มี limit วัน

## หน้าจอย่อย

### รายการ (List)
- ค้นหาด้วย: รหัสจอง, ชื่อผู้เช่า, เบอร์โทร, เลขห้อง
- Filter chip 6 แบบ: ทั้งหมด / รอยืนยัน / ยืนยันแล้ว / ยกเลิก / เสร็จสิ้น / เก็บแล้ว
- แสดง badge เตือนเมื่อเลยกำหนด "ทำสัญญาภายใน" แล้วแต่ยังไม่เช็คอิน (default เปิดไว้ — ไม่บล็อกอะไร แค่เตือนสายตา, ปรับได้ทีหลังถ้าไม่ต้องการ)
- แสดง badge เตือนถ้าผู้เช่าอยู่ใน Blacklist (เช็คจาก Blacklist model เดิม — **ไม่บล็อกการจอง** แค่เตือน)

### Modal "จองห้องพัก"
- เลือกห้อง: dropdown แสดง **ทุกห้องไม่กรองสถานะ** (ยืนยันแล้ว)
- เลือกผู้เช่า (ใหม่ / เดิม) — **re-use ฟอร์มเดียวกับ "เพิ่มผู้เช่า" ของห้องพัก** ทุกฟิลด์
- Toggle ประเภทการจอง: รายเดือน / รายวัน (ฟิลด์เปลี่ยนตาม toggle — ยืนยันแล้ว)
  - **รายเดือน** → วันที่เข้าพัก + กำหนดทำสัญญาภายใน (ไม่บังคับ)
  - **รายวัน** → วันที่เข้าพัก + จำนวนคืน (auto คำนวณวันออก) + วันออก
- รายละเอียดการชำระเงิน: รองรับหลายแถว (เงินสด/โอนเงิน + เลือกบัญชีถ้าโอน + จำนวนเงิน + อัปโหลดสลิป ต่อแถว) รวมเป็นยอดมัดจำ — **ไม่บังคับกรอก** (จองเปล่าได้ 0 บาท)
- หมายเหตุ (free text)

### Modal "ยืนยันการเข้าพัก (Check-in)"
- Prefill ข้อมูลจากรายการจอง: ห้อง, ผู้เช่า, ประเภท, วันเข้าพัก, วันออก
- ถ้ายังไม่มีผู้เช่าในระบบ → สร้างผู้เช่าใหม่อัตโนมัติจากข้อมูลจอง
- ยืนยันแล้ว → เข้าสู่ flow ทำบิล/รับเงินของห้องพัก (re-use flow เดิมที่ตัดสินใจไว้แล้ว — split payment, ส่วนลด, ใบกำกับภาษี ฯลฯ)
- **ยืนยันแล้ว: เงินมัดจำที่วางไว้ตอนจอง จะถูกหักลบกับบิลค่าเช่างวดแรกอัตโนมัติตอนเช็คอิน**
- ตั้งสถานะ booking = เสร็จสิ้น, ห้อง = มีผู้เช่า

### Modal "ยกเลิกการจอง" (สิทธิ์: **owner เท่านั้น**)
- เหตุผล — ไม่บังคับกรอก
- เลือกเอง: คืนเงินมัดจำ / ไม่คืนเงินมัดจำ (`deposit_refunded`)
- ตั้งสถานะ booking = ยกเลิก, ห้องกลับเป็น "ว่าง"

## Action หลัก
สร้างจอง (staff+owner) · แก้ไขจอง (ก่อนเช็คอิน) · ยืนยันจอง (staff+owner) · ยกเลิกจอง (**owner เท่านั้น**) · เช็คอินจากจอง (staff+owner) · เก็บ/archive · ค้นหา/กรอง

## สิทธิ์
ใช้ role ที่มีอยู่แล้ว (`owner | staff`) — ไม่มี sub-role เพิ่มสำหรับโมดูลนี้ ยกเว้นปุ่มยกเลิกจองจำกัดเฉพาะ owner

## ความสัมพันธ์กับ module อื่น
- **ห้องพัก**: ผูก room_id, sync สถานะห้อง (ว่าง ↔ จองแล้ว ↔ มีผู้เช่า), ใช้ปฏิทิน Gantt ร่วมกัน
- **ผู้เช่า**: สร้าง/เชื่อม tenant record, เช็ค Blacklist
- **การเงิน**: ทำบิล/รับเงินจริงเกิดตอนเช็คอิน (มัดจำจองเป็นแค่ field บันทึกไว้ก่อน แล้วไปหักลบกับบิลแรกตอนเช็คอิน), เชื่อม bank_account_id กับ "ฐานข้อมูลบัญชี"
- **ตั้งค่า/ผู้ใช้งาน**: ใช้ role เดิม owner/staff

## ตัดออกจาก MVP (ยืนยันแล้ว)
- ลิงก์จองแบบ self-service (public booking link)
- ใบจองห้องพัก (เอกสารพิมพ์/PDF) — ต้นแบบมีแต่ตัดออก
- สถานะ "รอตรวจสอบสลิป" แยกต่างหาก
- การจำกัดระยะเวลาจองล่วงหน้า
- การป้องกันจอง/เช็คอินซ้อนทับวันเดียวกัน

## ⚠️ หมายเหตุสำคัญก่อน implement จริง
ตรวจพบว่าโค้ดจริงในโปรเจกต์ (`app/rooms`, `app/bookings`, `prisma/schema.prisma`) **ไม่ตรงกับสเปคโมดูล "ห้องพัก" ที่ตัดสินใจไว้เลย**:
- `Room.status` มีแค่ 3 ค่า (available/unavailable/blocked) — ไม่มี "จองแล้ว"
- ไม่มีปฏิทิน Gantt, ไม่มี multi-building (`building_id`), ไม่มี modal เช็คอินแบบเลือก "เป็นการจองหรือไม่"
- `Booking` model เดิมรองรับแค่รายวัน ไม่มี booking_code/split payment/monthly flow
**ต้องเขียนโมดูล "ห้องพัก" ใหม่ทั้งหมดให้ตรงสเปค (`module_room_key_features.md`) ก่อน แล้วจึงย้อนมาทำ "จองห้อง" ตามสเปคนี้**
