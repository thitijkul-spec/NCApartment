# Module: ค่าใช้จ่าย (Expense)

> อ้างอิงภาพหน้าจอต้นแบบ (List/Dashboard, Modal บันทึก, ตารางรายการ) + ปรับเป็นรูปแบบระบบบัญชี ตามที่ตกลงในแชท — **ไม่ใช่การ mirror ภาพต้นแบบตรงๆ เหมือน module อื่น** เพราะขยายสโคปเพิ่มจากภาพเดิม (ผู้ขาย/VAT/หัก ณ ที่จ่าย/multi-line/split payment)

## หน้าที่ของ module
บันทึกและติดตามค่าใช้จ่ายของแต่ละอาคาร ในรูปแบบใกล้เคียงระบบบัญชี (มีผู้ขาย, VAT, หัก ณ ที่จ่าย, จ่ายเชื่อ/จ่ายสด, แบ่งจ่ายหลายงวดหลายบัญชี) — เดิมเคยเป็นส่วนหนึ่งของ "บิลกำหนดเอง" ในหน้าห้องพัก แต่ตัดออกจาก `module_bill` เพราะไม่ผูกกับห้อง/สัญญาโดยตรง (ใช้บันทึก เช่น ค่าซ่อมของส่วนตัว, จ้างแม่บ้าน, ค่าเสียหายส่วนกลาง ฯลฯ)

## ความสัมพันธ์กับระบบ multi-building
- Expense ผูกกับ `building_id` เหมือน entity อื่นทั้งหมด
- **Contact (ผู้ซื้อและผู้ขาย)** เป็น master data ที่ **ใช้ร่วมกันทุกอาคาร** ภายใต้บัญชีเดียวกัน (ไม่ต้องสร้างซ้ำต่ออาคาร)
- **BankAccount (บัญชีธนาคารกิจการ)** **แยกตามอาคาร** เพราะแต่ละอาคารมีบัญชีที่ทำ statement กระทบยอดแยกกัน

## Data Model

### Contact (master data ผู้ซื้อและผู้ขาย — ใช้ร่วมกับ module รายได้อื่นๆ)
ตารางเดียวใช้ทั้งเป็น "ผู้ขาย" (ใน module นี้) และ "ผู้ซื้อ/ลูกค้าทั่วไป" (ใน module รายได้อื่นๆ) ไม่แยก type — จะได้ไม่ต้องสร้างข้อมูลซ้ำ
- `id`
- `name` — ชื่อ/ชื่อกิจการ *
- `tax_id` — เลขผู้เสียภาษี
- `address` — ที่อยู่
- `phone`, `email` — เบอร์โทร/อีเมล
- `contact_person` — ชื่อผู้ติดต่อ
- `created_at`, `updated_at`

หน้าจัดการ: CRUD แยกต่างหาก (หน้ารายชื่อ "ผู้ซื้อและผู้ขาย") — ยังไม่กำหนดตำแหน่งเมนูแน่ชัด เสนอให้อยู่ใต้เมนูย่อย "การเงิน" คู่กับ ค่าใช้จ่าย/รายได้อื่นๆ (ถามผู้ใช้ยืนยันตำแหน่งเมนูตอนเริ่ม implement ได้)

### BankAccount (master data บัญชีธนาคารกิจการ — แยกตามอาคาร)
- `id`
- `building_id`
- `bank_name` — ชื่อธนาคาร
- `account_number` — เลขบัญชี
- `account_name` — ชื่อบัญชี
- `branch` — สาขา (optional)

หน้าจัดการ: อยู่ในหน้า **"ตั้งค่า"** (CRUD)

### Expense (หัวบิลค่าใช้จ่าย)
- `id`
- `building_id`
- `document_no` — เลข running number เฉพาะของ module นี้ เช่น `EXP-2569-08-001` **รันแยกต่ออาคาร** (ไม่ปนกับเลขบิล/ใบเสร็จของ module_bill) — **รีเซ็ตตัวนับท้ายทุกเดือน** (ทุกต้นเดือนเริ่มนับ 001 ใหม่)
- `vendor_contact_id` — FK → Contact (ผู้ขาย) — optional (ไม่บังคับต้องมีผู้ขายเสมอ เช่นรายจ่ายเบ็ดเตล็ด)
- `vendor_name_snapshot`, `vendor_tax_id_snapshot`, `vendor_address_snapshot` — **snapshot ข้อมูลผู้ขาย ณ เวลาบันทึก** (ก็อปมาจาก Contact ตอนบันทึกครั้งแรก) ถ้าแก้ไขข้อมูล Contact ภายหลัง บิลเก่าจะไม่เปลี่ยนตาม
- `room_id` — FK → Room (optional, ไม่บังคับผูกห้อง — เช่นค่าซ่อมของห้องใดห้องหนึ่งโดยเฉพาะ) ให้สอดคล้องกับ OtherIncome
- `date` — วันที่จ่าย/วันที่บิล * (ใช้เป็นฐานคำนวณสถิติ "รวมเดือนนี้/รวมทั้งปี" ในหน้า Dashboard)
- `purchase_type` — enum: `cash` (ซื้อสด) / `credit` (ซื้อเชื่อ) *
- `due_date` — วันครบกำหนด (บังคับกรอกถ้า `credit`) — **ไม่มีระบบแจ้งเตือนอัตโนมัติในภาพรวม** ต่างจากบิลผู้เช่า ใช้ดูประกอบการ filter ในหน้า list เท่านั้น
- `vendor_invoice_no` — เลขที่ใบกำกับภาษีซื้อจากผู้ขาย (ระดับหัวบิล, optional)
- `wht_amount` — ยอดหัก ณ ที่จ่าย (กรอกเอง เป็น memo field, **ไม่กระทบการคำนวณยอดจ่ายสุทธิอัตโนมัติ**)
- `total_amount` — ยอดรวมทั้งบิล (คำนวณอัตโนมัติ = ผลรวม `ExpenseLineItem.total_with_vat` ทุกรายการ)
- `payment_status` — enum คำนวณสด: `unpaid` / `partial` / `paid` (จากผลรวม `ExpensePayment.amount` เทียบกับ `total_amount`)
- `receipt_image_urls` — รูปใบเสร็จ/สลิป **แนบได้หลายไฟล์**
- `notes` — หมายเหตุ
- `created_at`, `updated_at`

> **แก้ไข/ลบได้อิสระ** แม้จะมีการบันทึก ExpensePayment ไปแล้วบางส่วน/ครบแล้วก็ตาม (ไม่ล็อก ไม่ต้องลบ payment ออกก่อน) — เหมาะกับการใช้งานจริงที่ต้องแก้ไขพิมพ์ผิด
>
> **`date` เลือกวันไหนก็ได้ ไม่ล็อกเฉพาะเดือนปัจจุบัน** รองรับการทำบิลย้อนหลัง/ข้ามเดือน และแก้ไขวันที่ของบิลเก่าได้อิสระ — เมื่อแก้วันที่แล้ว สถิติในหน้า Dashboard (รวมเดือนนี้/รวมทั้งปี/กราฟ) จะคำนวณตามเดือนใหม่ที่แก้ทันที

### ExpenseLineItem (รายการย่อยในบิล — รองรับ "1 บิล มีหลายรายการที่ซื้อ")
- `id`
- `expense_id` — FK → Expense
- `title` — หัวข้อรายการ *
- `category` — enum fixed list: `ค่าน้ำ` / `ค่าไฟ` / `ซ่อมแซม` / `ค่าอินเตอร์เน็ต` / `เงินเดือน` / `วัสดุสิ้นเปลือง` / `อื่นๆ` *
- `amount` — จำนวนเงิน *
- `vat_mode` — enum: `none` (ไม่มี VAT) / `included` (รวม VAT ใน `amount`) / `excluded` (แยก VAT เพิ่มจาก `amount`)
- `vat_rate` — % VAT, default `7`, แก้ไขได้ต่อรายการ (ใช้เมื่อ `vat_mode != none`)
- `vat_amount` — คำนวณอัตโนมัติจาก `amount` + `vat_mode` + `vat_rate`
- `total_with_vat` — คำนวณอัตโนมัติ (ยอดสุทธิของรายการนี้รวม VAT)
- `description` — รายละเอียดเพิ่มเติม (optional)

> หมายเหตุ: VAT คำนวณ**ต่อรายการย่อย** ไม่ใช่ต่อทั้งบิล — ยอดรวมหัวบิล (`Expense.total_amount`) รวมอัตโนมัติจากผลรวมรายการย่อยทั้งหมด ปัดเศษทศนิยม **2 ตำแหน่ง** ทุกจุดคำนวณ ไม่มีส่วนลด/ค่าใช้จ่ายเพิ่มเติมระดับหัวบิล (ถ้ามีให้เพิ่มเป็นรายการย่อยแทน)

### ExpensePayment (การจ่ายเงิน — รองรับจ่ายหลายครั้ง/หลายวิธี/หลายบัญชี)
- `id`
- `expense_id` — FK → Expense
- `amount` — จำนวนเงินที่จ่ายในครั้งนี้
- `method` — enum: `cash` (เงินสด) / `transfer` (โอนธนาคาร) / `check` (เช็ค) / `credit_card` (บัตรเครดิต/เดบิต)
- `bank_account_id` — FK → BankAccount (บังคับกรอกถ้า `method = transfer`)
- `date` — วันที่จ่ายจริง
- `slip_image_urls` — สลิปโอน/หลักฐานการจ่าย **แนบต่อรายการจ่ายนี้โดยเฉพาะ** (แยกจาก `receipt_image_urls` ที่หัวบิล — จ่าย 3 งวด แนบสลิปได้ 3 ชุดแยกกัน)
- `notes`

> รองรับ "แบ่งจ่ายหลายงวด หลายวิธี หลายบัญชี" — กดเพิ่ม ExpensePayment ได้เรื่อยๆ จนกว่า `sum(amount)` จะครบ `Expense.total_amount` (`payment_status` จะขยับ unpaid → partial → paid อัตโนมัติ)
> เมื่อเลือก `purchase_type = cash` (ซื้อสด) ตอนบันทึก Expense ครั้งแรก ให้ระบบสร้าง ExpensePayment ให้อัตโนมัติ 1 รายการเต็มจำนวน (ผู้ใช้เลือกวิธีจ่ายตอนนั้นได้เลย)

### LedgerEntry (รายการเดินบัญชี — เตรียม data model ไว้ก่อน ยังไม่ทำ UI กระทบยอด รอ module "ฐานข้อมูลบัญชี")
สร้างอัตโนมัติทุกครั้งที่มีการบันทึกเงินเข้า/ออกจริงจากสามแหล่ง:
- `id`
- `building_id`
- `bank_account_id` — nullable (null = เงินสด)
- `direction` — enum: `in` (รับเงินเข้า) / `out` (จ่ายเงินออก)
- `amount`
- `date`
- `source_type` — enum: `bill_payment` (การชำระบิลผู้เช่า) / `expense_payment` (ค่าใช้จ่าย) / `other_income_payment` (รายได้อื่นๆ)
- `source_id` — FK ไปยัง record ต้นทาง (Payment ใน module_bill / ExpensePayment / OtherIncomePayment)
- `description`

> ยังไม่มีหน้าจอ UI กระทบยอดกับ statement ในรอบนี้ — แค่เตรียมโครงสร้างข้อมูลให้ระบบบันทึกอัตโนมัติไว้ก่อน เพื่อให้ module "ฐานข้อมูลบัญชี" ในอนาคตดึงไปใช้ต่อได้
>
> **Requirement ล่วงหน้าสำหรับ module "ฐานข้อมูลบัญชี" (ยังไม่ทำในรอบนี้):** ผู้ใช้ต้องการฟีเจอร์ **อัปโหลด Bank Statement เป็น PDF (จากธนาคารโดยตรง) แล้วให้ระบบ cross-check กับ `LedgerEntry` อัตโนมัติ** จับคู่รายการด้วยวันที่+จำนวนเงิน แล้ว flag รายการที่ไม่ตรงกัน (มีใน statement แต่ไม่มีในระบบ / มีในระบบแต่ไม่มีใน statement) — ข้อควรระวังตอนออกแบบจริง: PDF แต่ละธนาคารมี layout ต่างกัน ต้องมี parser เฉพาะต่อธนาคาร หรือให้ผู้ใช้ map คอลัมน์เอง อาจต้องเพิ่ม field เช่น `matched_status`, `external_ref` ใน `LedgerEntry` ตอนออกแบบ module นั้นจริง

## หน้าจอย่อย

### 1. หน้า List/Dashboard ค่าใช้จ่าย
ตามภาพต้นแบบ:
- Header + ปุ่ม "+ บันทึกค่าใช้จ่าย"
- ตัวเลือกเดือน (เลื่อนก่อน/ถัดไป) + จำนวนรายการ
- 3 stat cards: รวมเดือนนี้ / รวมทั้งปี / เฉลี่ยต่อเดือน
- 2 กราฟ: สัดส่วนตามประเภท (โดนัท), ค่าใช้จ่ายรายเดือนทั้งปี (แท่ง)
- Filter tab ตามหมวดหมู่ (fixed list 7 หมวด)
- Filter เพิ่มเติม: สถานะจ่าย (unpaid/partial/paid), ผู้ขาย, ช่วงวันที่, ค้นหาด้วยเลขที่เอกสาร (`document_no`)
- ตารางรายการ: เลขที่เอกสาร, รายการ(หัวข้อ+ผู้ขาย), ประเภท, วันที่, ยอดรวม, สถานะจ่าย (unpaid/partial/paid), actions (แก้/ลบ)
- **ไม่มีปุ่มดู/พิมพ์ PDF ในหน้านี้** — ฟีเจอร์ export/พิมพ์เอกสารทั้งหมดย้ายไปอยู่ที่ module "รายงาน"

### 2. Modal บันทึก/แก้ไขค่าใช้จ่าย (แบบ multi-line)
- เลือกผู้ขาย (dropdown จาก Contact, ค้นหาได้, optional) + ปุ่ม "เพิ่มผู้ขายใหม่" แบบ inline (เปิด mini-form)
- วันที่จ่าย/บิล *
- ประเภทการซื้อ: ซื้อสด / ซื้อเชื่อ (ถ้าซื้อเชื่อ ให้กรอกวันครบกำหนด)
- เลขที่ใบกำกับภาษีซื้อ (optional)
- ยอดหัก ณ ที่จ่าย (optional, กรอกเอง)
- **รายการย่อย (บรรทัดที่ 1..n)** — กดเพิ่มบรรทัดได้เรื่อยๆ แต่ละบรรทัด: หัวข้อ, ประเภท (icon เดิม 7 แบบ), จำนวนเงิน, VAT (ไม่มี/รวม/แยก) + % VAT (default 7), รายละเอียด
- ยอดรวมทั้งบิล — แสดงคำนวณสดจากผลรวมรายการย่อย (read-only)
- ถ้าเลือก "ซื้อสด" — เพิ่มส่วนเลือกวิธีจ่าย + บัญชี (ถ้าโอน) ทันทีในฟอร์มเดียวกัน
- รูปใบเสร็จ (แนบไฟล์)
- หมายเหตุ

### 3. Modal จัดการการจ่ายเงิน (สำหรับ purchase_type = credit หรือจ่ายไม่ครบ)
- แสดงยอดรวม / จ่ายไปแล้ว / คงเหลือ
- รายการ ExpensePayment ที่บันทึกไปแล้ว (แก้ไข/ลบได้)
- ปุ่ม "+ เพิ่มการจ่ายเงิน" — กรอกจำนวนเงิน, วิธีจ่าย, บัญชีธนาคาร (ถ้าโอน), วันที่, หมายเหตุ

### 4. หน้าจัดการ Contact (ผู้ซื้อและผู้ขาย) — ใช้ร่วมกับ module รายได้อื่นๆ
- ตาราง list + ค้นหา
- ฟอร์ม CRUD: ชื่อ, เลขผู้เสียภาษี, ที่อยู่, เบอร์โทร, อีเมล, ชื่อผู้ติดต่อ
- **ลบได้อิสระ (hard delete)** แม้มีประวัติ Expense/OtherIncome อ้างอิงอยู่ — ข้อมูลเก่าไม่กระทบ เพราะมี snapshot เก็บแยกไว้แล้ว
- **ไม่มี flag เลิกใช้งาน/archive** — จัดการด้วยการลบเท่านั้น
- **ไม่มีระบบเตือนรายการซ้ำ** ตอนบันทึก Expense/OtherIncome (ผู้ขาย/ผู้ซื้อ + จำนวนเงิน + วันที่ตรงกับรายการเดิม บันทึกซ้ำได้เลย ไม่มี warning)

### 5. หน้าจัดการ BankAccount — อยู่ใน module "ตั้งค่า"
- CRUD ต่ออาคาร: ชื่อธนาคาร, เลขบัญชี, ชื่อบัญชี, สาขา

## Action/ฟังก์ชัน
- เพิ่ม/แก้ไข/ลบ Expense (ลบ = hard delete, ลบแล้วลบเลย)
- เพิ่ม/ลบรายการย่อยภายใน Expense แบบ dynamic
- เพิ่ม/แก้ไข/ลบ ExpensePayment (แบ่งจ่ายได้หลายครั้ง หลายวิธี หลายบัญชี)
- คำนวณ VAT อัตโนมัติต่อรายการย่อย, รวมยอดหัวบิลอัตโนมัติ
- คำนวณ `payment_status` อัตโนมัติจากยอดจ่ายสะสม
- สร้าง LedgerEntry อัตโนมัติทุกครั้งที่บันทึก ExpensePayment (เตรียมข้อมูลไว้ ไม่มี UI)
- CRUD Contact, CRUD BankAccount (ในตั้งค่า)

## สิทธิ์การเข้าถึง (Permission)
โค้ดต้นแบบเก่ามีระบบ `User.role` (`owner`/`staff`) + `User.permissions` เป็น list รหัสโมดูลที่ staff เข้าถึงได้ (`prisma/schema.prisma` model User) — module นี้ต้อง **เช็ค permission flag ระดับ module** (เช่นรหัสหมวด "การเงิน") ก่อนอนุญาตให้เข้าหน้าค่าใช้จ่าย/รายได้อื่นๆ/Contact/BankAccount
- Owner เห็น/แก้ไข/ลบได้ทุกอย่างเสมอ
- Staff ที่ไม่ได้รับสิทธิ์หมวด "การเงิน" จะมองไม่เห็นเมนูนี้เลย (ไม่ใช่แค่ซ่อนปุ่ม แก้ไข/ลบ)
- เป็น permission **ระดับ module** เท่านั้น (เห็น/ไม่เห็นทั้งหมด) ไม่แยกละเอียดระดับ action (ดู/แก้/ลบ) ในรอบนี้
- **หน้าจอจัดการผู้ใช้งาน/role/permission (login, เพิ่ม staff, กำหนดสิทธิ์) อยู่นอกสโคปของแชทนี้ — รอไปทำใน module "ตั้งค่า"** สเปคนี้แค่ระบุว่า module ค่าใช้จ่าย/รายได้อื่นๆ ต้องผูกกับระบบ permission ที่จะมาทีหลัง

## ความสัมพันธ์กับ module อื่น
- **module_bill**: เดิมส่วนนี้เคยรวมอยู่ใน "บิลกำหนดเอง" ที่ตัดออกมา — ไม่ผูกกับ `room_id`/`contract_id` บังคับ
- **module รายได้อื่นๆ**: ใช้ Contact master data ร่วมกัน (ตาราง "ผู้ซื้อและผู้ขาย" เดียวกัน)
- **module ตั้งค่า**: จัดการ BankAccount ที่นี่
- **module รายงาน**: ฟีเจอร์ดู/พิมพ์/export PDF และรายงานสรุปทั้งหมดของค่าใช้จ่ายอยู่ที่ module นี้ ไม่ใช่ในหน้าค่าใช้จ่ายเอง
- **module ฐานข้อมูลบัญชี (ยังไม่ทำ)**: จะดึง LedgerEntry ไปทำ UI กระทบยอดกับ bank statement ต่อในอนาคต

## นอกสโคปรอบนี้ (ตัดออกโดยเจตนา)
- หน้าสรุป "ยอดค้างชำระทั้งหมด" ต่อผู้ขาย/ผู้ซื้อ 1 คน (รวมยอดค้างจากหลายบิล) — ไม่ทำในรอบนี้ อาจไปอยู่ใน module ฐานข้อมูลบัญชี ทีหลัง
- ระบบแจ้งเตือนอัตโนมัติในภาพรวมสำหรับบิลค้างจ่ายเกินกำหนด (ต่างจากบิลผู้เช่าที่มีแจ้งเตือน)

## Assumption ที่ยังไม่ได้ยืนยัน (ควรถามผู้ใช้ตอนเริ่ม implement)
- ตำแหน่งเมนู "จัดการ Contact (ผู้ซื้อและผู้ขาย)" ในโครงสร้างเมนูจริง
- Category ของค่าใช้จ่ายเป็น fixed list ตามที่ตกลง (ไม่ใช่ master data แก้ไขเองได้)
