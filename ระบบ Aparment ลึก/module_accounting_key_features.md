# Module: ฐานข้อมูลบัญชี (Accounting Database)

> module สุดท้ายในหมวดการเงิน — อ้างอิงภาพต้นแบบ 2 ภาพที่ให้แนวคิดต่างกัน (1. หน้ารายการ/พิมพ์เอกสาร แยกตามประเภท 2. บัญชีแยกประเภทแบบมีเดบิต/เครดิต/ยอดคงเหลือ) แต่**ไม่ทำระบบบัญชีคู่เต็มรูปแบบ** (ไม่มีผังบัญชีรหัส, ไม่มีสมุดรายวันหลายเล่ม RV/GV/PV, ไม่มีขั้นตอน Post/Draft) — ออกแบบให้เรียบง่ายกว่า ใช้ **Account** (บัญชีที่ผู้ใช้เพิ่มเองได้ไม่จำกัด) แทนผังบัญชีมาตรฐาน ตามที่ตกลงในแชท

## หน้าที่ของ module
รวมศูนย์ดูข้อมูลการเงินทั้งหมดของอาคาร: ดู/พิมพ์ทะเบียนเอกสารทุกประเภท (รวมถึง**ออกบิลผู้เช่ารายวัน/walk-in ซึ่งไม่มีอยู่ที่ module_bill**), ดูบัญชีแยกประเภทของแต่ละบัญชีเงินสด/ธนาคาร, จัดการบัญชี (master data), และสรุปยอดค้างชำระ/ค้างรับ

## ความสัมพันธ์กับระบบ multi-building
- ทุก entity ในโมดูลนี้ผูกกับ `building_id`
- `Account` (บัญชี) ผูกกับ 1 อาคารเท่านั้น (ไม่ใช้ร่วมข้ามอาคาร)

## Data Model

### Account (บัญชี — generalize มาจาก `BankAccount` เดิมที่ module_expense/module_other_income อ้างอิงไว้)
เปลี่ยนจาก "บัญชีธนาคารกิจการอย่างเดียว" เป็น **"บัญชี" ทั่วไปที่ผู้ใช้เพิ่มเองได้ไม่จำกัดจำนวน** — ครอบคลุมทั้งบัญชีธนาคารจริงและบัญชีเสมือน (เช่น เงินสดแยกตามจุดเก็บเงิน/พนักงาน) — ดูหัวข้อ "ต้องย้อนไปแก้ spec เดิม" ด้านล่าง
- `id`
- `building_id`
- `name` — ชื่อบัญชี (เช่น "เงินสด", "ธนาคารกสิกร สาขา A", "เงินสดคุณสมศรี") *
- `type` — ประเภท (เงินสด/ธนาคาร/บัตรเครดิต/อื่นๆ — preset + ผู้ใช้กำหนดเองได้)
- `account_number` — เลขบัญชี (optional ใช้กับธนาคาร)
- `opening_balance` — ยอดยกมาเริ่มต้น (กรอกตอนสร้างบัญชี)
- `current_balance` — คำนวณสด = `opening_balance` + ผลรวม `LedgerEntry` ทุกรายการของบัญชีนี้ (in - out)
- `status` — enum: `active` / `inactive`
- `created_at`, `updated_at`

> **ลบได้เฉพาะเมื่อ `current_balance = 0` เท่านั้น** — ถ้ามียอดคงเหลืออยู่ ปุ่มลบ disabled ให้ปิดใช้งาน (`inactive`) แทน

### LedgerEntry (ต่อยอดจาก module_expense/module_other_income — เปลี่ยน FK และเพิ่ม source_type ใหม่)
- `id`
- `building_id`
- `account_id` — FK → Account (เดิมชื่อ `bank_account_id`, nullable ไม่ได้แล้วเพราะทุกธุรกรรมต้องเลือกบัญชี รวมถึงเงินสด)
- `direction` — enum: `in` / `out`
- `amount`
- `date`
- `source_type` — enum: `bill_payment` / `expense_payment` / `other_income_payment` / `deposit_refund` (คืนเงินมัดจำ) / `deposit_forfeit` (ริบเงินมัดจำ → เกิดจาก OtherIncome อัตโนมัติ นับรวมกับ `other_income_payment` ก็ได้เพราะสุดท้ายไหลผ่าน OtherIncomePayment) / `daily_bill` (บิลผู้เช่ารายวัน)
- `source_id` — FK ไปยัง record ต้นทาง
- `description`

### DailyBill (บิลผู้เช่ารายวัน/walk-in — เอนทิตีใหม่ **จุดที่ตกหล่นจาก module_bill เดิม** ระบุไว้ใน `module_bill_key_features.md` ว่า "ผู้เช่ารายวัน คิดเงินแยกไปเลยที่ module ฐานข้อมูลบัญชี")
- `id`
- `building_id`
- `document_no` — running number เฉพาะ `DLY-YYYY-MM-###` รันแยกต่ออาคาร รีเซ็ตรายเดือน (เหมือน `EXP-`/`INC-`)
- `room_id` — FK → Room (ต้องเป็นห้องที่รองรับโหมดรายวัน)
- `tenant_id` — FK → Tenant (`tenant_type = daily`)
- `checkin_date`
- `nights` — จำนวนคืน
- `daily_price_snapshot` — snapshot ราคารายวันของห้อง ณ วันทำรายการ
- `deposit_amount_snapshot` — snapshot มัดจำรายวันของห้อง ณ วันทำรายการ (nullable ถ้าห้องไม่มีมัดจำรายวัน)
- `total_amount` — คำนวณอัตโนมัติ = `nights × daily_price_snapshot` (ไม่รวมมัดจำ แสดงแยกบรรทัด)
- `account_id` — FK → Account ที่รับเงินเข้า
- `method` — enum: `cash` / `transfer` / `credit_card`
- `created_at`

> **จ่ายล่วงหน้าเต็มจำนวนเสมอตอน check-in** — ไม่มีสถานะค้างชำระ/บางส่วนเหมือนบิลรายเดือน สร้างแล้ว = จ่ายแล้วทันที + สร้าง `LedgerEntry` ขาเข้าอัตโนมัติทันที
>
> **ไม่คิดค่าน้ำ-ไฟแยก** — เหมารวมอยู่ในราคารายวันแล้วทั้งหมด (ต่างจากบิลรายเดือนที่แยกรายการ)
>
> **อยู่เกิน/ต่ออายุ**: ออก `DailyBill` ใบใหม่แยกต่างหาก (ผูก `room_id`/`tenant_id` เดิม) ไม่แก้ไขใบเดิม — เป็นการจ่ายล่วงหน้ารอบใหม่

### Deposit (เงินมัดจำ — เอนทิตีใหม่ ผูกกับ Contract)
- `id`
- `contract_id` — FK → Contract
- `room_id` — FK → Room (denormalize เพื่อ query ง่าย)
- `amount` — จำนวนเงินมัดจำที่เก็บตอนทำสัญญา (snapshot จาก `Contract.deposit_amount` ซึ่ง**มีอยู่แล้ว**ใน module_contract ไม่ต้องเพิ่ม field ใหม่ — ดูหัวข้อ "ความสัมพันธ์กับ module อื่น" ด้านล่าง)
- `collected_date` — วันที่เก็บมัดจำ (= วันทำสัญญา)
- `status` — enum: `held` (ถืออยู่) / `returned` (คืนแล้ว) / `forfeited` (ริบทั้งหมด) — **3 สถานะเท่านั้น ไม่มี "ริบบางส่วน"**
- `returned_date`, `returned_account_id` (FK → Account ที่จ่ายเงินคืนออก, เลือกตอนออกเอกสารคืน)
- `forfeited_date`, `forfeited_other_income_id` (FK → OtherIncome ที่สร้างอัตโนมัติ)
- `created_at`, `updated_at`

**Flow คืน/ริบเงินมัดจำ:**
- **คืนเต็มจำนวน**: กดปุ่ม "คืนเงินมัดจำ" → เลือกบัญชีที่จ่ายเงินออก → ระบบสร้าง `LedgerEntry` ขาออกทันที + เปลี่ยนสถานะเป็น `returned` + ออกเอกสาร **"ใบสำคัญคืนเงินมัดจำ" ขนาด A4** (formal เหมือนใบกำกับภาษี) ใช้เลขสัญญา/เลขห้องอ้างอิง **ไม่มีเลขที่เอกสารวิ่งเฉพาะตัว**
- **ริบทั้งหมด** (เช่น ผู้เช่าหนีหาย/ผิดสัญญาร้ายแรง): กดปุ่ม "ริบเงินมัดจำ" → เปลี่ยนสถานะเป็น `forfeited` ทันที + **สร้าง `OtherIncome` อัตโนมัติทันที หมวด "เงินมัดจำริบ"** (หมวดนี้มีอยู่แล้วใน module_other_income) → **ไม่ต้องออกเอกสารแยก** เปลี่ยนสถานะอย่างเดียวพอ
- **หักค่าเสียหาย/ทำความสะอาดบางส่วน**: **ไม่เกี่ยวกับ Deposit โดยตรง** — ให้ไปออกบิลแยกต่างหาก (เช่น "บิลกำหนดเอง" เรียกเก็บค่าน้ำ-ไฟ-ทำความสะอาด) เรียกเก็บจากผู้เช่า**อิสระ ไม่หักกลบกับเงินมัดจำ** — ฝั่งเงินมัดจำเองมีแค่ "คืนเต็ม" กับ "ริบเต็ม" เท่านั้น

> เหตุผลทางบัญชี: เงินมัดจำที่ถืออยู่ = หนี้สิน (ยังไม่ใช่รายได้) พอริบแล้วเปลี่ยนสถานะเป็นรายได้อื่นๆ — สอดคล้องกับหมวด "เงินมัดจำริบ" ที่เตรียมไว้ใน module_other_income อยู่แล้ว

## หน้าจอย่อย (4 แท็บหลัก)

### แท็บ 1: ทะเบียนเอกสาร
7 sub-tab: **ใบเสร็จรับเงิน / ใบแจ้งหนี้ / บิลกำหนดเอง / สัญญาเช่า / เงินมัดจำ / ค่าใช้จ่าย / บิลรายวัน**
- แต่ละ sub-tab **ดึงข้อมูลจาก module ต้นทางตรงๆ** (Payment/Bill/Contract/Expense/Deposit) — คอลัมน์ตามโครงสร้างของ module ต้นทางนั้นๆ ไม่บังคับให้ทุกแท็บมีคอลัมน์เหมือนกัน
- Filter บนสุด (ใช้ร่วมทุก sub-tab): เลือกเดือน/ปี (ปุ่มเลื่อนก่อน-หลัง), dropdown กรอง**สถานะการชำระ** (ทั้งหมด/ชำระแล้ว/ยังไม่ชำระ), ช่องค้นหา (ห้อง/ชื่อผู้เช่า/เบอร์โทร)
- Checkbox เลือกหลายแถว + ปุ่ม "พิมพ์/บันทึก PDF (N)" (พิมพ์เอกสารที่เลือกพร้อมกันหลายใบ) + ปุ่ม "เลือกใบเสร็จ (N)"
- ปุ่มพิมพ์รายแถว (ไอคอนเครื่องพิมพ์ท้ายแถว)
- แถวสรุปท้ายตาราง: จำนวนรายการ + ยอดรวม

ตัวอย่างคอลัมน์ sub-tab **ใบเสร็จรับเงิน** (จากภาพต้นแบบ): วันที่, ห้อง, ผู้เช่า, เบอร์โทร, ค่าเช่า, ค่าไฟ, ค่าน้ำ, อื่นๆ, ค่าปรับ, รวม, สถานะ, วิธีชำระ, สลิป, พิมพ์ใบเสร็จ

sub-tab **เงินมัดจำ**: วันที่ทำสัญญา, ห้อง, ผู้เช่า, จำนวนเงินมัดจำ, สถานะ (ถืออยู่/คืนแล้ว/ริบทั้งหมด), ปุ่ม "คืนเงิน"/"ริบเงิน" (แสดงเฉพาะสถานะ `held`)

sub-tab **บิลรายวัน**: เลขที่เอกสาร, ห้อง, ผู้เช่า, วันที่เข้าพัก, จำนวนคืน, ราคา/คืน, มัดจำ, รวม, วิธีชำระ, ปุ่มพิมพ์ใบเสร็จ — มีปุ่ม "+ ออกบิลรายวัน" แยกต่างหากในแท็บนี้ (เลือกห้อง+ผู้เช่า/สร้างผู้เช่าใหม่ → กรอกจำนวนคืน → ระบบคำนวณยอด+มัดจำอัตโนมัติจากราคาห้อง → เลือกวิธีชำระ+บัญชี → ยืนยัน = จ่ายแล้วทันที)

> คอลัมน์ของ sub-tab ใบแจ้งหนี้/บิลกำหนดเอง/สัญญาเช่า/ค่าใช้จ่าย ยังไม่ได้ยืนยันจากภาพจริงแต่ละแท็บ — อ้างอิงจาก field ที่มีอยู่แล้วใน module_bill/module_contract/module_expense แทนไปก่อน ควรขอภาพเพิ่มถ้ามีตอน implement

### แท็บ 2: บัญชีแยกประเภท
- Dropdown เลือกบัญชี 1 รายการ (จาก `Account` master)
- โชว์ยอดยกมา (`opening_balance`) + ตารางรายการ: **วันที่, รายการ/คู่ค้า** (จาก `LedgerEntry.description`), **เดบิต, เครดิต, คงเหลือสะสม** (running balance คำนวณสด)
- **ไม่มี filter ช่วงเวลา/ปุ่มพิมพ์ PDF** — แสดงรายการทั้งหมดของบัญชีนั้นตั้งแต่เริ่มมีข้อมูล

### แท็บ 3: จัดการบัญชี
- ตาราง: ชื่อบัญชี, ประเภท, ยอดยกมาเริ่มต้น, **ยอดคงเหลือปัจจุบัน**, สถานะ (ใช้งาน/ปิดใช้งาน), actions (แก้ไข/ปิดใช้งาน/ลบ)
- ปุ่ม "+ เพิ่มบัญชี" — ฟอร์ม: ชื่อ, ประเภท, เลขบัญชี (optional), ยอดยกมาเริ่มต้น
- ปุ่มลบ **disabled ถ้ายอดคงเหลือ ≠ 0** (ต้องปิดใช้งานแทน)

### แท็บ 4: ยอดค้างชำระ/ค้างรับ
2 ตารางแยกกัน (ไม่มี aging bucket — แค่ยอดรวมค้างต่อคน/ราย):
- **ตาราง "ค้างรับ"** — รายชื่อผู้เช่าที่ยังค้างชำระบิล (ดึงจาก module_bill) + ยอดค้างรวมต่อคน
- **ตาราง "ค้างจ่าย"** — รายชื่อ Contact (เจ้าหนี้การค้า) ที่ยังค้างจ่ายค่าใช้จ่าย (ดึงจาก module_expense) + ยอดค้างรวมต่อราย

## Action/ฟังก์ชัน
- ดู/ค้นหา/กรองทะเบียนเอกสารทุกประเภท (7 sub-tab)
- **ออกบิลผู้เช่ารายวัน (walk-in)** ใหม่ — เลือกห้อง/ผู้เช่า, กรอกจำนวนคืน, คำนวณยอดอัตโนมัติจากราคาห้อง, รับชำระเต็มจำนวนทันที → สร้าง `LedgerEntry` อัตโนมัติ
- พิมพ์/บันทึก PDF เอกสารทีละใบหรือหลายใบพร้อมกัน (bulk select)
- ดูบัญชีแยกประเภทต่อบัญชี พร้อมยอดคงเหลือสะสม
- CRUD บัญชี (Account) + เปิด/ปิดใช้งาน + ลบ (เฉพาะยอด 0)
- คืนเงินมัดจำเต็มจำนวน (เลือกบัญชีจ่ายออก + ออกเอกสาร A4) → สร้าง `LedgerEntry` ขาออกอัตโนมัติ
- ริบเงินมัดจำทั้งหมด → สร้าง `OtherIncome` หมวด "เงินมัดจำริบ" อัตโนมัติทันที
- ดูสรุปยอดค้างชำระ/ค้างรับรวมต่อคน (2 ตาราง)

## สิทธิ์การเข้าถึง (Permission)
รอ module "ตั้งค่า" เหมือน module อื่นในหมวดการเงิน — ไม่ออกแบบระบบ role/permission ในรอบนี้

## นอกสโคปรอบนี้ (ตัดออกโดยเจตนา)
- **อัปโหลด Bank Statement PDF แล้ว cross-check อัตโนมัติกับ `LedgerEntry`** — requirement เดิมที่เคยระบุไว้ล่วงหน้า **เลื่อนไปทำสเปคทีหลัง** (อาจเป็นแท็บที่ 5 ในอนาคต) ไม่อยู่ในสโคปรอบนี้
- Aging bucket (0-30/31-60/60+ วัน) ในหน้ายอดค้างชำระ/ค้างรับ
- ระบบบัญชีคู่แบบเต็มรูปแบบ (ผังบัญชีรหัส, สมุดรายวันหลายเล่ม RV/GV/PV, ขั้นตอน Post/Draft) — ใช้ `Account` แบบง่ายแทน บันทึกอัตโนมัติทันทีไม่มี draft
- สถานะมัดจำ "ริบบางส่วน" — ตัดออก ใช้การออกบิลแยกแทน

## ความสัมพันธ์กับ module อื่น (และรายการที่ต้อง**ย้อนไปแก้ spec เดิม**)
- **`module_contract_key_features.md`**: ตรวจสอบแล้วพบว่า `Contract.deposit_amount` **มีอยู่แล้ว**ในสเปคเดิม (ไม่ต้องเพิ่ม field ใหม่) — แก้แค่เพิ่ม cross-reference บอกว่าสถานะคืน/ริบมัดจำติดตามที่ `Deposit` entity ในโมดูลนี้ (แก้แล้ว)
- **ต้องแก้ `module_expense_key_features.md`**: เปลี่ยน `BankAccount` → `Account` (เพิ่ม field `type`/`opening_balance`/`current_balance`/`status`, เปลี่ยนจากบัญชีธนาคารอย่างเดียวเป็นบัญชีทั่วไปไม่จำกัดจำนวน) — เปลี่ยน FK `bank_account_id` → `account_id` ใน `ExpensePayment` และ `LedgerEntry`
- **ต้องแก้ `module_other_income_key_features.md`**: เปลี่ยนแบบเดียวกัน — `bank_account_id` → `account_id` ใน `OtherIncomePayment` และ `LedgerEntry`
- **module_bill**: ถ้ามี field วิธีชำระ/บัญชีธนาคารใน `Payment` ต้องตรวจสอบเปลี่ยนตามเช่นกัน (ต้องเปิดไฟล์ `module_bill_key_features.md` ตรวจตอน implement) — **ปิดจุดที่ตกหล่นแล้ว**: `module_bill` ระบุไว้ว่าบิลผู้เช่ารายวัน (walk-in) อยู่ที่ module นี้ ตอนนี้มี `DailyBill` entity + sub-tab "บิลรายวัน" รองรับแล้ว
- **module_tenant, module_room**: อ้างอิงผ่านทะเบียนเอกสาร (ห้อง/ผู้เช่า) ในแท็บ 1 — `DailyBill` ต้องเลือกห้องที่รองรับโหมดรายวัน (`daily_price` ไม่ null) และผู้เช่า `tenant_type = daily`
- **module ตั้งค่า**: ระบบสิทธิ์ผู้ใช้งาน (permission) จะทำที่นี่, เดิมมีหน้าจัดการ `BankAccount` ในตั้งค่า → ย้าย/เปลี่ยนเป็นจัดการ `Account` ในโมดูลนี้แทน (ตัดออกจากตั้งค่า)

## Assumption ที่ยังไม่ได้ยืนยัน (ควรถามผู้ใช้ตอนเริ่ม implement)
- ประเภทบัญชี (`type`) preset มีอะไรบ้างชัดเจน (เงินสด/ธนาคาร/บัตรเครดิต/อื่นๆ) — ยังไม่ยืนยัน list สุดท้าย
- คอลัมน์ของ sub-tab ใบแจ้งหนี้/บิลกำหนดเอง/สัญญาเช่า/ค่าใช้จ่าย ในทะเบียนเอกสาร — ยังไม่มีภาพต้นแบบยืนยัน อ้างอิง field จาก spec module ต้นทางไปก่อน
