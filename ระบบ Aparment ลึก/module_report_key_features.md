# Module: รายงาน (Reports)

> ไม่มีภาพต้นแบบอ้างอิง — ออกแบบเองทั้งหมดจากการคุยในแชท เพราะขอบเขตกว้างครอบคลุมเกือบทุก module

## หน้าที่ของ module
หน้ารวม "สรุป/วิเคราะห์/export" ข้อมูลจากหลาย module (การเงิน, ห้องพัก, ผู้เช่า, ซ่อมบำรุง/พัสดุ) เป็นรูปแบบตาราง + export Excel — **ไม่ใช่หน้าดูเอกสารรายตัว** (นั่นคือหน้าที่ของ `module_accounting`)

### ขอบเขตที่แยกจาก module ฐานข้อมูลบัญชีชัดเจน
- **module ฐานข้อมูลบัญชี** = ดู/พิมพ์/export PDF **เอกสารรายตัว** (ทะเบียนเอกสาร 7 sub-tab, บัญชีแยกประเภท) — คนละหน้ากับที่นี่
- **module รายงาน** (ไฟล์นี้) = **สรุป/วิเคราะห์/export ข้อมูลรวม** (Excel, สรุปยอดตามช่วงเวลา/หมวดหมู่) — ไม่มีปุ่มดูเอกสารต้นฉบับทีละใบ

หมวดที่ออกแบบสเปคไว้ในไฟล์นี้ครบทุกหมวดแล้ว: **การเงิน** (6 รายงาน), **ห้องพัก** (5 รายงาน), **ซ่อมบำรุง/พัสดุ** (3 รายงาน), **ผู้เช่า** (3 รายงาน) — รวม 17 รายงาน

## ความสัมพันธ์กับระบบ multi-building
- ทุกรายงานดึงข้อมูลเฉพาะ `building_id` ที่กำลังเลือกอยู่เท่านั้น — **ไม่มี dropdown เลือกดูรวมหลายอาคาร**

## โครงสร้างหน้าจอ

### หน้าแรก "รายงาน" (สารบัญ — ไม่มี tab)
หน้าเดียว แสดงรายการรายงานทั้งหมด **จัดกลุ่มเป็นหัวข้อตามหมวด** (แบบ list ใต้หัวข้อ ไม่ใช่ tab):

```
รายงาน

การเงิน
  • สรุปรายรับ-รายจ่าย
  • สรุปห้องค้างชำระ
  • สรุปยอดตามบัญชีที่รับเงิน
  • สรุปเงินสด-โอน
  • สรุปภาษีซื้อ-ขาย (VAT/หัก ณ ที่จ่าย)
  • ยอดซื้อ-ขายตามคู่ค้า

ห้องพัก
  • สรุปสถานะห้องพัก/ผู้เช่า
  • รายงานเงินมัดจำ
  • รายงานมิเตอร์น้ำ-ไฟ (เทียบรายเดือน)
  • อัตราการเข้าพัก (Occupancy Rate)
  • รายงานการจอง

ซ่อมบำรุง/พัสดุ
  • รายงานแจ้งซ่อม
  • รายงานพัสดุ
  • รายงานล้างแอร์/บำรุงรักษาอุปกรณ์ส่วนกลาง

ผู้เช่า
  • รายชื่อผู้เช่าทั้งหมด
  • สัญญาใกล้หมดอายุ
  • อัตราการเข้า-ออกผู้เช่า (Turnover)
```

กดแต่ละลิงก์ → เข้าหน้ารายงานนั้น **เต็มหน้า** (ไม่ใช่ modal) มี filter + ตาราง + ปุ่ม export ในหน้าเดียวกัน มีปุ่ม "ย้อนกลับ" ไปหน้าสารบัญ

### สิทธิ์การเข้าถึง (permission)
- **1 permission code เดียว** (เช่น `report`) ครอบทั้งโมดูล ไม่แยกย่อยตามหมวด/รายงาน — ผูกกับระบบ role/permission เดิม (`User.permissions`) ที่จะไป implement จริงใน module "ตั้งค่า"

### รูปแบบร่วมของทุกรายงาน (ปรับตามแต่ละรายงานได้ตามระบุด้านล่าง)
- Filter ช่วงวันที่แบบเลือกเอง (date range picker) — **default = วันที่ 1 ถึงวันที่ปัจจุบันของเดือนปัจจุบัน** ทุกครั้งที่เข้าหน้า
- มุมขวาบน **2 ปุ่ม export**: **"Export Excel"** (.xlsx) และ **"Export PDF"** (สำหรับปริ้น) — ทุกรายงานมีทั้ง 2 ปุ่มเหมือนกันหมด
  - Excel: แยกไฟล์ต่อ 1 รายงาน ข้อมูลตรงกับที่กรอง/แสดงอยู่ในตารางขณะนั้น
  - PDF: ขนาด **A4 แนวตั้ง (portrait)** — ตารางที่คอลัมน์เยอะ (เช่น matrix รายเดือน) ต้องปรับ font/ความกว้างคอลัมน์ให้พอดีหน้ากระดาษ หรือขึ้นหน้าใหม่ถ้าล้น มีหัวกระดาษระบุชื่อรายงาน + ช่วงวันที่ที่กรอง + วันที่พิมพ์
- ไม่มีมุมมองกราฟ — ตาราง + export เท่านั้น

## หมวด "การเงิน" — สเปครายละเอียด 4 รายงาน

### 1. สรุปรายรับ-รายจ่าย
**Layout: Matrix** — แถว = หมวดหมู่รายรับ/รายจ่าย, คอลัมน์ = เดือนในช่วงที่ filter, cell = ยอดรวมของหมวดนั้นในเดือนนั้น

**แหล่งข้อมูล:**
- รายรับ:
  - แถว "ค่าเช่า" — รวมยอดจาก `Bill`/`Payment` (module_bill) ที่ verified แล้ว
  - แถวตาม `OtherIncome.category` แต่ละหมวด (module_other_income — 10 หมวด fixed)
  - แถวรวม **"รวมรายรับ"** (bold)
- รายจ่าย:
  - แถวตาม `ExpenseLineItem.category` แต่ละหมวด (module_expense — 7 หมวด fixed: ค่าน้ำ/ค่าไฟ/ซ่อมแซม/ค่าอินเตอร์เน็ต/เงินเดือน/วัสดุสิ้นเปลือง/อื่นๆ)
  - แถวรวม **"รวมรายจ่าย"** (bold)
- แถวสุดท้าย **"กำไร/ขาดทุนสุทธิ"** (bold) = รวมรายรับ − รวมรายจ่าย ต่อเดือน
- คอลัมน์ขวาสุด = "รวม" ของแต่ละแถวตลอดช่วงที่ filter

ตัวอย่าง:

| หมวดหมู่ | ม.ค. 69 | ก.พ. 69 | มี.ค. 69 | รวม |
|---|---|---|---|---|
| รายรับ - ค่าเช่า | 150,000 | 152,000 | 148,000 | 450,000 |
| รายรับ - ค่าปรับ | 2,000 | 0 | 1,500 | 3,500 |
| รายรับ - รายได้อื่นๆ (หมวดอื่น) | 5,000 | 3,000 | 4,000 | 12,000 |
| **รวมรายรับ** | **157,000** | **155,000** | **153,500** | **465,500** |
| รายจ่าย - ค่าน้ำ | 8,000 | 8,500 | 8,200 | 24,700 |
| รายจ่าย - ค่าไฟ | 12,000 | 12,500 | 11,300 | 35,800 |
| รายจ่าย - ซ่อมแซม | 8,000 | 3,000 | 12,000 | 23,000 |
| รายจ่าย - อื่นๆ | 5,000 | 4,000 | 6,000 | 15,000 |
| **รวมรายจ่าย** | **33,000** | **28,000** | **37,500** | **98,500** |
| **กำไร/ขาดทุนสุทธิ** | **124,000** | **127,000** | **116,000** | **367,000** |

**Filter:** ช่วงวันที่ (ตาม `date`/`paid_at` ของแต่ละ entity)
**เกณฑ์การนับ:** เฉพาะรายการที่ verified/ชำระแล้วจริง (ไม่นับบิลค้างชำระเป็นรายรับ)

### 2. สรุปห้องค้างชำระ (Aging)
**ใช้ query/logic ชุดเดียวกับแท็บ "ยอดค้างชำระ-ค้างรับ" (ฝั่งค้างรับจากผู้เช่า) ใน `module_accounting_key_features.md`** — ไม่สร้าง logic คำนวณยอดค้างซ้ำใหม่ เพื่อไม่ให้ตัวเลขสองที่ไม่ตรงกัน หน้านี้เป็นชั้น **filter + export** ทับข้อมูลชุดเดียวกัน (หน้าฐานข้อมูลบัญชีเป็นตารางดูสดอย่างเดียว ไม่มี export/filter ละเอียด)

- **ขอบเขต: เฉพาะยอดค้างชำระของผู้เช่า (บิลค้าง) เท่านั้น — ไม่รวมยอดค้างจ่ายฝั่งซื้อเชื่อ (Expense `purchase_type=credit`)** ฝั่งนั้นดูที่ตาราง "ค้างจ่าย" ในฐานข้อมูลบัญชีแทน
- **มุมมอง 2 แบบ ให้ผู้ใช้เลือกสลับได้ (toggle/dropdown บนหัวตาราง):**
  1. **แบบสรุปตามห้อง** — 1 แถวต่อ 1 ห้อง: เลขห้อง, ชื่อผู้เช่า, จำนวนบิลที่ค้าง, ยอดรวมค้างของห้องนั้น, ค้างมากสุดกี่วัน
  2. **แบบรายการละเอียด** — 1 แถวต่อ 1 บิลที่ค้าง: เลขห้อง, ชื่อผู้เช่า, เดือนบิล (`billing_month`), ยอดค้างของบิลนั้น, ค้างมากี่วัน (คำนวณจาก `due_date`)
- **เรียงลำดับ:** เลือกได้ทั้ง 2 แบบ (ปุ่ม/dropdown สลับ) — (ก) ค้างนานสุดก่อน (มากไปน้อย) หรือ (ข) เรียงตามหมายเลขห้อง
- แถวสุดท้ายของตาราง (ทั้ง 2 มุมมอง): **"ยอดรวมค้างชำระทั้งหมด"**
- **Filter:** ช่วงวันที่ครบกำหนด (`due_date`) — ไม่มี filter ห้อง/ผู้เช่าแยก (ดูทั้งหมดในอาคารที่เลือก)

### 3. สรุปยอดตามบัญชีที่รับเงิน
**Layout: List** — 1 แถวต่อ 1 บัญชี (`Account`), group ตาม `account_id` ที่ผูกกับการรับเงินจริง — **ไม่ group ตาม payment method** (เพราะ Account สื่อความหมาย เงินสด/บัญชีธนาคารแต่ละบัญชี อยู่ในตัวอยู่แล้ว)

**แหล่งข้อมูล (รวมทุกช่องทางรับเงิน):**
- `Payment` (module_bill) — `method: cash | transfer`
- `OtherIncomePayment` (module_other_income) — `method: cash | transfer | check | credit_card`

**คอลัมน์:** ชื่อบัญชี (`Account.name`), ประเภทบัญชี (`Account.type`), จำนวนรายการ, ยอดรวมที่รับเข้าบัญชีนี้ในช่วงที่ filter
แถวสุดท้าย: **"รวมทั้งหมด"**

**Filter:** ช่วงวันที่ (ตาม `paid_at`)

### 4. สรุปเงินสด-โอน
สำหรับใช้ชนยอดเงินสดในมือจริง/ชนกับ Bank Statement — **นับเฉพาะ `method = cash` และ `method = transfer` เท่านั้น** (ไม่นับ `check`/`credit_card` เพราะไม่ใช่เงินสดหรือโอนจริง)

- **Filter:** ช่วงวันที่แบบเลือกเอง (date range — ไม่ตายตัวแค่ "วันนี้" เลือกดูวันอื่น/ช่วงอื่นได้ด้วย) default เป็นวันนี้วันเดียวเมื่อเข้าหน้าครั้งแรก
- **Layout:** 1 แถวต่อ 1 วันในช่วงที่ filter — คอลัมน์: วันที่, ยอดรับเงินสดรวม, ยอดรับโอนรวม, รวมทั้งวัน
- แถวสุดท้าย: **"รวมทั้งหมด"** ของทั้งช่วง
- **แหล่งข้อมูล:** รวมทั้ง `Payment` (module_bill) และ `OtherIncomePayment` (module_other_income) ที่ `method` เป็น cash/transfer

### 5. สรุปภาษีซื้อ-ขาย (VAT / หัก ณ ที่จ่าย)
ใช้ข้อมูลจาก `ExpenseLineItem.vat_amount` (ภาษีซื้อ) และ `Expense.wht_amount` (หัก ณ ที่จ่าย) — **ฝั่งรายรับค่าเช่าไม่มี VAT** (ยกเว้นภาษีตามกฎหมาย ตาม `module_receipt_key_features.md`) จึงมีแค่ฝั่งซื้อ (Expense)

**Layout: List** — 1 แถวต่อเดือน: เดือน, ยอดซื้อรวมก่อน VAT, ภาษีซื้อรวม (VAT), ยอดหัก ณ ที่จ่ายรวม (WHT), จำนวนบิลที่มี VAT/WHT
แถวสุดท้าย: **"รวมทั้งช่วง"**

> **หมายเหตุสำคัญ:** `wht_amount` เป็น memo field ที่กรอกเอง ไม่ได้คำนวณอัตโนมัติ (ตาม `module_expense_key_features.md`) — รายงานนี้แค่รวมยอดตัวเลขที่กรอกไว้ ใช้เป็นข้อมูลอ้างอิงเบื้องต้นสำหรับเตรียมยื่นภาษี **ไม่ใช่การคำนวณภาษีที่แม่นยำระดับยื่นจริง**

**Filter:** ช่วงวันที่ (ตาม `Expense.date`)
**Export:** Excel + PDF

---

### 6. ยอดซื้อ-ขายตามคู่ค้า
ใช้ข้อมูลจาก `Contact` (master data ร่วม) ผูกกับ `Expense.vendor_contact_id` (ฝั่งซื้อ) และ `OtherIncome.buyer_contact_id` (ฝั่งขาย/รับเงิน — **เฉพาะกรณี `buyer_type = contact` เท่านั้น**)

> **ขอบเขต: เฉพาะคู่ค้าที่เป็น Contact ภายนอก** — ไม่รวมกรณี `OtherIncome.buyer_type = tenant` (ผู้ซื้อเป็นผู้เช่าในระบบ ผูก `buyer_tenant_id` ไม่ใช่ Contact) เพราะยอดรับจากผู้เช่าดูได้จากรายงานฝั่งบิล/การเงินอื่นอยู่แล้ว รายงานนี้เน้นวิเคราะห์คู่ค้าภายนอก (ผู้ขาย/ลูกค้าทั่วไป)

**Layout: List** — 1 แถวต่อ 1 Contact: ชื่อคู่ค้า, จำนวนรายการฝั่งซื้อ, ยอดซื้อรวม (จาก Expense), จำนวนรายการฝั่งขาย, ยอดขายรวม (จาก OtherIncome) — แสดงทั้งสองฝั่งในตารางเดียว (Contact ตัวเดียวกันอาจเป็นทั้งผู้ขายและผู้ซื้อได้ในเวลาต่างกัน)
**Sort default:** เรียงตามยอดรวม (ซื้อ+ขาย) มากไปน้อย

**Filter:** ช่วงวันที่, ประเภท (แสดงเฉพาะฝั่งผู้ขาย/ฝั่งผู้ซื้อ/ทั้งหมด)
**Export:** Excel + PDF

## หมวด "ห้องพัก" — สเปครายละเอียด 2 รายงาน

### 1. สรุปสถานะห้องพัก/ผู้เช่า
รวม 2 requirement เดิม ("ห้องรายเดือน/รายวันมีกี่ห้อง" + "ห้องไหนลูกค้าคนไหนอยู่") เป็นรายงานเดียว — **เป็น snapshot สถานะปัจจุบันเท่านั้น ไม่มี filter ช่วงวันที่ ไม่ดูย้อนหลัง**

**Stat cards ด้านบน** (นับจากการเช่าจริง — active Contract=รายเดือน / active Booking=รายวัน ตามที่แก้ไว้ใน `module_room_key_features.md`, ไม่ใช่นับจาก `rental_type_support` ที่ตั้งไว้ตอน setup):
- ห้องทั้งหมด
- ห้องมีผู้เช่ารายเดือน
- ห้องมีผู้เช่ารายวัน
- ห้องว่าง
- ห้องจองแล้ว
- ห้องปิดปรับปรุง

**ตารางด้านล่าง — 1 แถวต่อ 1 ห้อง (ครบทุกห้องในอาคาร ไม่ใช่แค่ห้องที่มีผู้เช่า):**
เลขห้อง, ชั้น, ประเภทการรองรับ (`rental_type_support`), สถานะห้อง, ประเภทการเช่าปัจจุบัน (รายวัน/รายเดือน/— ถ้าว่าง), ชื่อผู้เช่าปัจจุบัน (หรือ "-"), เบอร์โทรผู้เช่า, วันที่เข้าพัก, วันสิ้นสุดสัญญา/วันที่จองถึง (ถ้ามี)

**Filter:** สถานะห้อง, ประเภทการรองรับ (ไม่มี filter ช่วงวันที่ เพราะเป็น snapshot)
**Export:** Excel + PDF

### 2. รายงานเงินมัดจำ
ใช้ข้อมูลจาก `Deposit` entity (`module_accounting_key_features.md`) — ผูกกับ Contract/ห้อง/ผู้เช่า

**ตาราง:** ห้อง, ชื่อผู้เช่า, วันที่ทำสัญญา (`collected_date`), จำนวนเงินมัดจำ (`amount`), สถานะ (ถืออยู่/คืนแล้ว/ริบแล้ว), วันที่คืน/ริบ (ถ้ามี)
แถวสุดท้าย: **"ยอดรวมมัดจำที่ถืออยู่"** (รวมเฉพาะสถานะ `held`)

**Filter:**
- สถานะมัดจำ (multi-select: ถืออยู่/คืนแล้ว/ริบแล้ว — default แสดงทุกสถานะ)
- ช่วงวันที่ทำสัญญา (`collected_date`)

**Export:** Excel + PDF

### 3. รายงานมิเตอร์น้ำ-ไฟ (เทียบรายเดือน)
ใช้ข้อมูลจาก `MeterReading` (`module_meter_key_features.md`) — **ไม่มีมุมมองกราฟ ตารางเทียบเดือนเท่านั้น**

**Layout: Matrix** — แถว = ห้อง (ครบทุกห้องที่มีประวัติมิเตอร์ในช่วงที่ filter), คอลัมน์ = เดือน แต่ **แต่ละเดือนแบ่งเป็น 2 คอลัมน์ย่อย: "น้ำ" และ "ไฟ"** (หัวตารางกลุ่ม 2 ชั้น — แถวบนสุด = ชื่อเดือน คร่อม 2 คอลัมน์, แถวรองลงมา = "น้ำ"/"ไฟ") ค่าในแต่ละเซล = `water_units`/`electric_units` ของเดือนนั้น — ไม่ต้องแยกเป็นตารางน้ำ-ไฟคนละตาราง แต่ก็ไม่ยุบรวมอยู่เซลเดียวกัน

ตัวอย่าง:

| ห้อง | ม.ค. 69 น้ำ | ม.ค. 69 ไฟ | ก.พ. 69 น้ำ | ก.พ. 69 ไฟ | รวมน้ำ | รวมไฟ |
|---|---|---|---|---|---|---|
| 101 | 15 | 120 | 14 | 118 | 29 | 238 |
| 102 | 12 | 95 | 13 | 100 | 25 | 195 |

คอลัมน์ขวาสุด: รวมหน่วยน้ำ / รวมหน่วยไฟ ตลอดช่วงที่ filter ของห้องนั้น (คนละคอลัมน์)
แถวล่างสุด: รวมหน่วยน้ำ/ไฟทุกห้องต่อเดือน (คนละแถวย่อยใต้แต่ละเดือน หรือ 2 แถวสรุปท้ายตาราง "รวมน้ำทุกห้อง" / "รวมไฟทุกห้อง")

**ไม่ไฮไลต์เซลที่หน่วยผิดปกติ** — การเตือนหน่วยผิดปกติเป็นของหน้าบันทึกมิเตอร์ (`module_meter`) เท่านั้น หน้ารายงานนี้แสดงตัวเลขเทียบเดือนตรงไปตรงมา

**Filter:** ช่วงเดือน (เลือกช่วงเดือนเริ่ม-สิ้นสุด แทน date range ปกติ เพราะข้อมูลเป็นรายเดือนอยู่แล้วตาม `reading_month`)
**Export:** Excel + PDF

### 4. อัตราการเข้าพัก (Occupancy Rate)
**วิธีคำนวณ: Room-nights** — นับจำนวนวันที่ห้องมีผู้เช่าจริง (active Contract หรือ Booking คาบเกี่ยววันนั้น) รวมทุกห้อง หารด้วย (จำนวนห้องทั้งหมด × จำนวนวันในเดือน) — แม่นยำกว่าการนับ snapshot ณ วันเดียว เพราะนับรวมห้องที่มีผู้เช่าเข้า-ออกกลางเดือนด้วย

**Layout: List** — 1 แถวต่อเดือน: เดือน, จำนวนห้องทั้งหมด, ผลรวม room-nights ที่มีผู้เช่า, room-nights สูงสุดที่เป็นไปได้ (ห้อง × วันในเดือน), **% อัตราการเข้าพัก**
แถวสุดท้าย: ค่าเฉลี่ยทั้งช่วงที่ filter

**Filter:** ช่วงเดือน
**Export:** Excel + PDF

### 2. สัญญาใกล้หมดอายุ

**เกณฑ์ "ใกล้หมดอายุ": เหลืออีก ≤ 60 วันก่อนวันหมดสัญญา** — ใช้เกณฑ์เดียวกับที่การ์ดห้องใน `module_room_key_features.md` ใช้เตือน (ไฮไลต์ล่วงหน้า 2 เดือน) เพื่อให้ตรงกันทั้งระบบ

**ตาราง:** ห้อง, ชื่อผู้เช่า, เบอร์โทร, วันเริ่มสัญญา, วันหมดสัญญา, เหลืออีกกี่วัน (เรียงจากใกล้หมดสุดไปหาไกลสุด — default sort)

**Filter:** ปรับจำนวนวันเกณฑ์ "ใกล้" ได้ (default 60 วัน, ปรับเป็น 30/90 วันได้จาก dropdown) — ไม่มี filter ช่วงวันที่แยก
**Export:** Excel + PDF

## หมายเหตุสำหรับ implement
- ทุกรายงานเป็น **read-only** ไม่มีการแก้ไขข้อมูลจากหน้านี้ — query จากตารางที่มีอยู่แล้ว (`Bill`, `Payment`, `Expense`, `ExpenseLineItem`, `ExpensePayment`, `OtherIncome`, `OtherIncomeLineItem`, `OtherIncomePayment`, `Account`, `Room`, `Contract`, `Booking`, `Deposit`, `RepairRequest`, `MaintenanceLog`, `SharedEquipment`, `Parcel`, `Tenant`, `room_occupancies`, `MeterReading`, `Booking`, `Contact`) **ไม่ต้องเพิ่ม field/ตารางใหม่**
- **PDF export ต้องมี library/mechanism แปลงตาราง HTML → PDF (A4 แนวตั้ง)** — เลือก library ตอน implement จริง (เช่น server-side render แล้ว print-to-PDF) ยังไม่ตัดสินใจ tech เฉพาะ ณ ตอนทำสเปคนี้
- ปัดเศษทศนิยม 2 ตำแหน่งทุกจุดคำนวณ ให้สอดคล้องกับ module อื่น
