# Key Feature Spec — Module: ห้องพัก (Room Management)
อ้างอิงจากแอปต้นแบบ "LangHorPak"

## ภาพรวมหน้าจอ
หน้า "จัดการห้องพัก" แสดงห้องพักทั้งหมด แบ่งกลุ่มตามชั้น มี 3 มุมมอง: **Grid (การ์ด)**, **List (ตาราง)**, และ **Calendar (Gantt รายสัปดาห์ — [Feature เพิ่มเติม] ดูรายละเอียดหัวข้อ "Calendar View" ด้านล่าง)** สลับได้ด้วยปุ่ม toggle มุมขวาบน

## [สำคัญมาก — เปลี่ยนโครงสร้างระบบ] รองรับหลายอาคาร/สาขา (Multi-Building) ตั้งแต่แรก
**ยืนยันแล้ว: ระบบต้องรองรับหลายอาคาร/สาขาตั้งแต่ MVP** ไม่ใช่ทำอาคารเดียวก่อนแล้วค่อยขยายทีหลัง — กระทบโครงสร้างข้อมูลและ UI ของทุกโมดูลที่เกี่ยวกับห้อง:

- เพิ่ม entity **"อาคาร/สาขา" (Building/Branch)** เป็นระดับบนสุด — ห้องทุกห้องต้องผูกกับอาคารหนึ่งอาคารเสมอ (`building_id`)
- **ชั้นเป็นของแต่ละอาคารแยกกัน** ไม่ใช่ชั้นรวมข้ามอาคาร (เช่น อาคาร A ชั้น 1 กับอาคาร B ชั้น 1 เป็นคนละกลุ่มห้อง)
- **ยืนยันแล้ว: ไม่แสดงหลายอาคารในหน้าเดียวกัน** — ทุกหน้าจอ (ห้องพัก, ผู้เช่า, การเงิน ฯลฯ) แสดงข้อมูลของ**อาคารที่กำลังเลือกอยู่เท่านั้น** ไม่ปนอาคารอื่น
- **ยืนยันแล้ว: การสลับอาคาร ทำงานเหมือน "สลับโปรไฟล์" (คล้าย workspace switcher)** — ผู้ใช้เลือกอาคารตั้งแต่ตอนเข้าระบบครั้งแรก (หน้าจอเลือกอาคารหลัง login ถ้ามีมากกว่า 1 อาคาร) และเลือก/สลับอาคารได้อีกทีจากหน้า "ตั้งค่า" — ไม่มี dropdown สลับอาคารลอยอยู่ในทุกหน้าแบบ global switcher ตลอดเวลา แต่เป็นการ "เข้าไปทำงานในบริบทของอาคารนั้น" จนกว่าจะสลับใหม่
  - บ่งบอกว่าต้องมี **หน้าจอเลือกอาคาร (Building Selector)** เป็นอีกหน้าหนึ่งของระบบ — แสดงหลังจาก login สำเร็จ ถ้าบัญชีนี้มีมากกว่า 1 อาคาร (ถ้ามีอาคารเดียว ข้ามหน้านี้ไปตรงเข้าหน้าหลักเลย)
  - session/state ปัจจุบันของผู้ใช้ต้องจำไว้ว่ากำลังทำงานอยู่ในอาคารไหน (คล้าย current workspace) ทุก query/action ที่เกี่ยวกับห้อง/ผู้เช่า/บิล ฯลฯ ให้ scope ตาม building ปัจจุบันนี้โดยอัตโนมัติ
- **"ค่าตั้งสาขา"** ที่ห้องพักอ้างอิงอยู่ทุกจุด (ค่าน้ำ-ไฟ default, มัดจำ default ฯลฯ) หมายถึง **ค่าตั้งต่ออาคาร/สาขานี้เอง** ไม่ใช่ค่าตั้งกลางของทั้งระบบ — module "ตั้งค่า" ต้องรองรับตั้งค่าแยกต่ออาคาร
- Filter Tabs / ตัวนับจำนวนห้อง (ว่าง/มีผู้พัก ฯลฯ) ต้องนับแยกตามอาคารที่กำลังดูอยู่ (หรือมีมุมมองรวมทุกอาคารด้วย — รอตัดสินใจเพิ่ม)
- **ยังไม่ได้ถามรายละเอียด**: พนักงาน/ผู้ใช้ 1 คนดูแลได้กี่อาคาร, มีสิทธิ์แยกตามอาคารไหม (ผูกกับ module "สิทธิ์" ที่ตัดสินใจพักไว้ก่อนหน้านี้), Dashboard ภาพรวม (module "ภาพรวม") ต้องรวมข้อมูลข้ามอาคารหรือแยกดูทีละอาคาร

## Top bar ของหน้า
- หัวข้อ "จัดการห้องพัก" + ปุ่ม settings (ไอคอนเฟือง) ข้างหัวข้อ
- คำอธิบายรอง: "สถานะและข้อมูลห้องพักทั้งหมดของคุณ"
- ปุ่ม toggle Grid/List view
- ปุ่ม "เลือกหลายห้อง" (เข้าสู่ multi-select mode) — เมื่อเข้าโหมดนี้ ปุ่มเปลี่ยนเป็น "ออกจากโหมดเลือก" (ยกเลิกโหมด เคลียร์การเลือกทั้งหมด)
- ปุ่ม "+ เพิ่มห้องพัก" (dropdown 2 ตัวเลือก: "สร้างหลายห้อง" / "+ เพิ่มห้องพัก")

### Multi-select Mode (เลือกหลายห้อง)
- แต่ละการ์ดห้องแสดง checkbox มุมซ้ายบน, การ์ดที่ถูกเลือกไฮไลต์กรอบสีน้ำเงิน
- เมื่อเลือกอย่างน้อย 1 ห้อง แสดง bar สรุปด้านบนรายการห้อง: "เลือก N ห้อง" + ลิงก์ "ยกเลิก" (เคลียร์การเลือก) + ปุ่ม **"แก้ไขที่เลือก"** (primary, เปิด Bulk Edit Modal) + ปุ่ม **"ลบที่เลือก"** (danger, มุมขวา — ต้องมี confirm ก่อนลบ และใช้กฎเดียวกับลบห้องเดี่ยว คือห้องที่มีผู้เช่าอยู่จะลบไม่ได้)
  - **กฎ error message (ยืนยันแล้ว):** ถ้าในรายการที่เลือกมีห้องที่มีผู้เช่าอยู่ปนอยู่ ระบบต้อง **แจ้งเตือนระบุชัดเจนว่าห้องไหนบ้างที่ลบไม่ได้** (เช่น "ไม่สามารถลบห้อง 101, 105 ได้ เนื่องจากมีผู้เช่าอยู่") ไม่ใช่แค่แจ้งว่า "ลบไม่สำเร็จ" เฉยๆ
  - **ยืนยันแล้ว: บล็อกลบทั้งชุด** ถ้ามีห้องใดห้องหนึ่งในรายการที่เลือกลบไม่ได้ (ไม่ใช่ partial success) — ผู้ใช้ต้องเอาห้องที่ลบไม่ได้ออกจากการเลือกก่อน (หรือจัดการผู้เช่าให้เรียบร้อย) จึงจะลบที่เหลือได้

### Modal: แก้ไขข้อมูลห้องพักแบบ Bulk (เปิดจากปุ่ม "แก้ไขที่เลือก")
- หัวข้อ: "แก้ไขข้อมูลห้องพัก N ห้อง"
- แถบสรุป "กำลังแก้ไข N ห้อง" + dropdown "ดูห้องที่เลือก" (แสดงรายชื่อห้องที่เลือกไว้)
- ฟิลด์เหมือน Modal แก้ไขห้องเดี่ยวทุกอย่าง (โหมดเริ่มต้น, ราคารายเดือน/รายวัน, มัดจำ, สถานะ, ขนาด, การคิดค่าน้ำ-ไฟ ฯลฯ) — ค่าที่กรอก/เปลี่ยนจะ **apply ทับทุกห้องที่เลือกพร้อมกัน**
- Footer: ยกเลิก / "บันทึกทั้ง N ห้อง"
- **จุดที่ต้องตัดสินใจตอน implement:** ถ้าห้องที่เลือกมีค่าฟิลด์ไม่เหมือนกันอยู่แล้ว (เช่น บางห้อง 7500 บางห้อง 8000) ฟอร์มควรแสดงเป็นค่าว่าง/placeholder "หลายค่า" ไม่ใช่ดึงค่าห้องแรกมาแสดงเฉยๆ เพื่อไม่ให้ผู้ใช้เข้าใจผิดว่าห้องอื่นมีค่าเท่ากันด้วย

## Filter Tabs (พร้อมตัวนับจำนวนห้อง)
- ทั้งหมด (N)
- รองรับรายเดือน (N)
- รองรับรายวัน (N)
- ว่าง (N)
- **มีผู้พัก (N)** — ยืนยันจากภาพจริง (แทนที่ "รอทำความสะอาด" ที่ตัดออกไปแล้ว)
- **ปิดปรับปรุง (N)** — **ยืนยันแล้ว: เพิ่ม filter tab แยกต่างหาก** ไม่รวมอยู่ใน "ทั้งหมด" เฉยๆ
- (เพิ่มเติมตามสถานะห้องที่ยืนยันแล้ว — ดูหัวข้อ "สถานะห้อง")

## จัดกลุ่มตามชั้น
แสดงเป็น section/tab ต่อชั้น เช่น "ชั้น 1 — 10 ห้อง" ห้องในชั้นเดียวกันแสดงต่อกัน

## สถานะห้อง (Room Status)
**ตัดสินใจแล้ว: ไม่มีสถานะ "รอทำความสะอาด"** — ผู้เช่าเช็คเอาท์ออก ห้องกลับเป็น "ว่าง" ทันที ไม่ต้องมีขั้นตอนรอทำความสะอาดคั่นกลาง

| สถานะ | ความหมาย | สี |
|---|---|---|
| ว่าง | ห้องว่าง พร้อมให้เช่า/จอง | เขียว |
| มีผู้เช่า (Occupied) | มีผู้เช่าพักอยู่จริง | (กำหนดสี) |
| จองแล้ว (Reserved) | ถูกจองไว้ล่วงหน้า ยังไม่เข้าพักจริง — **การ์ดต้องใช้สีที่ต่างจาก "มีผู้เช่า" อย่างชัดเจน** เพื่อแยกสถานะจองกับเข้าพักจริงด้วยสายตา — **ไม่หมดอายุอัตโนมัติ** ต้องมีคนยกเลิกการจองเองเท่านั้น (ไม่มี job/cron ยกเลิกให้อัตโนมัติแม้เลยวันเข้าพักที่ระบุไว้) | (สีต่างหาก เช่น ส้ม/เหลือง) |
| ปิดปรับปรุง/ซ่อมบำรุง | ห้องไม่พร้อมให้เช่าเพราะซ่อมบำรุง — **ยืนยันแล้ว: มีช่องกรอกเหตุผล (free text) ด้วย** เช่น "ทาสีใหม่/ซ่อมท่อ" (ไม่มีวันที่คาดว่าจะเสร็จ — เลือกเฉพาะ "เหตุผล" ไม่ใช่ "วันที่คาดว่าจะเสร็จ") | (กำหนดสี) |

## โหมดรองรับการเช่า (รายเดือน / รายวัน)
- 1 ห้องตั้งราคาได้ทั้ง 2 แบบพร้อมกัน (รายเดือน + รายวัน) แสดง badge ทั้งสองแบบที่การ์ด/แถว
- ระบบมี **"โหมดปัจจุบัน"** ของห้อง ซึ่ง **auto-switch อัตโนมัติ** ตามประเภทการจอง/เช็คอินล่าสุดของห้องนั้น (เช่น ถ้าล่าสุดเช็คอินแบบรายวัน โหมดห้องจะเปลี่ยนเป็นรายวัน)
- ปุ่ม action บนห้องว่างจะเปลี่ยนตามโหมดปัจจุบัน เช่น "Check-in รายวัน"

## ข้อมูลที่แสดงต่อห้อง (การ์ด/แถว)
- เลขห้อง, ชั้น
- Badge สถานะ
- ราคา/เดือน, ราคา/วัน
- Badge "รองรับ" รายเดือน/รายวัน
- ผู้เช่าปัจจุบัน (ถ้ามี — แสดง "-" ถ้าว่าง)
- **[ห้องที่มีผู้เช่าอยู่ — ข้อมูลเพิ่มเติมที่ต้องแสดง]**
  - วันหมดสัญญา — ไฮไลต์/เตือนล่วงหน้าเมื่อเหลืออีก 2 เดือนก่อนหมดสัญญา
  - ยอดค้างชำระ (ถ้ามี)
  - วันครบกำหนดชำระถัดไป
  - ยืนยันจากภาพจริง: การ์ดห้องที่มีผู้เช่าแสดง ชื่อผู้เช่า + ไอคอนเตือน (สีส้ม/เหลือง) พร้อม **วันที่เข้าพัก** (ภาพตัวอย่างที่เห็นเป็น mock data ผิด ไม่ใช่ requirement จริงว่าต้องเป็นช่วงเดียวกัน)
- ขนาดห้อง (ตร.ม.) — เก็บใน data model แม้ไม่โชว์ในการ์ด
- ปุ่ม action ท้ายการ์ด: เปลี่ยนตามสถานะห้อง
  - ห้องว่าง → "Check-in [โหมดปัจจุบัน]" (เช่น "Check-in รายวัน") — กดแล้วเข้า **Check-in Flow** (ดูหัวข้อด้านล่าง)
  - ห้องมีผู้เช่า/จองแล้ว → action อื่นตามบริบท (เช่น ดูรายละเอียด/เช็คเอาท์) — ต้องดูเพิ่มเติมตอนทำ module ผู้เช่า/จองห้อง

## List View (ตาราง)
คอลัมน์: checkbox เลือก, ห้อง, ชั้น, รองรับ, สถานะ, ผู้เช่า, ราคา/เดือน, ราคา/วัน

## เพิ่มห้องพักเดี่ยว (Modal "เพิ่มห้องพักใหม่")
Fields:
- หมายเลขห้อง* (text) — **ยืนยันแล้ว: รองรับตัวอักษรผสมตัวเลข** (เช่น "A101") ไม่ใช่ตัวเลขล้วนบังคับ
- ชั้น* (number)
- โหมดเริ่มต้น* (dropdown: รายเดือน/รายวัน) — หมายเหตุในฟอร์ม: "ห้อง รองรับ ได้ทั้ง 2 แบบ (มีราคา/เดือน = รองรับรายเดือน, มีราคา/วัน = รองรับรายวัน) โหมดนี้จะถูกปรับอัตโนมัติตามการจอง/เช็คอินล่าสุด"
- ราคารายเดือน (บาท)* — ต้องกรอกอย่างน้อย 1 ใน 2 ราคา
- ราคารายวัน (บาท)
- เงินมัดจำรายเดือน (บาท) — placeholder "ใช้ค่าสาขา" = default ดึงจากค่าตั้งสาขา override ได้ต่อห้อง
- เงินมัดจำรายวัน (บาท) — เช่นเดียวกับด้านบน (ยืนยันแล้วว่ามีทั้งสองแบบ)
- สถานะ* (dropdown: ว่าง / มีผู้เช่า / จองแล้ว / ปิดปรับปรุง)
- ขนาด (ตร.ม.)
- **ส่วนการคิดค่าน้ำ-ไฟ (เฉพาะห้องนี้)**: เลือกได้ทั้ง 2 แบบต่อห้อง
  - อิงหน่วยมิเตอร์ + อัตราต่อหน่วย (ค่า default ดึงจากค่าตั้งสาขา / module มิเตอร์น้ำ-ไฟ)
  - เหมาจ่ายรายเดือน (Flat rate)
  - หมายเหตุในฟอร์ม: "ค่าเริ่มต้นดึงจากการตั้งค่าสาขา สามารถปรับได้ตามต้องการ"
- ปุ่ม ยกเลิก / บันทึก

## สร้างหลายห้องพร้อมกัน (Modal "สร้างห้องพักหลายห้อง")
Auto-generate section:
- ชั้นเริ่มต้น / ชั้นสิ้นสุด
- เลขห้องเริ่มต้น / เลขห้องสิ้นสุด
- ราคารายเดือน (บาท) — apply ให้ทุกห้องที่ generate
- ราคารายวัน (บาท)
- checkbox "ใช้เลขชั้นนำหน้า" (เช่น 101, 102, ...) + dropdown เลือกโหมด (รายเดือน/รายวัน)
- Preview/editable table ด้านล่าง: จัดกลุ่มตามชั้น แต่ละแถวแก้ไขได้ (เลขห้อง, ประเภท, ราคา/เดือน, ราคา/วัน, สถานะ) + ปุ่มลบแถว, checkbox เลือกทั้งแถว/ทั้งชั้น
- ปุ่ม "+ เพิ่มแถว" (เพิ่มห้องนอกช่วง auto-generate)
- Footer: สรุปจำนวนห้องทั้งหมด/จำนวนชั้น + ปุ่ม ยกเลิก / "สร้างทั้งหมด (N ห้อง)"

## Modal: แก้ไขข้อมูลห้องพัก (เปิดจากปุ่ม "แก้ไข" ใน Room Detail หรือจากการ์ด)
Fields เหมือน "เพิ่มห้องพักใหม่" ทั้งหมด (หมายเลขห้อง, ชั้น, โหมดเริ่มต้น, ราคารายเดือน/รายวัน, มัดจำรายเดือน/รายวัน, สถานะ, ขนาด) **บวกรายละเอียดเพิ่มเติมที่เห็นชัดในฟอร์มแก้ไข:**

### การคิดค่าน้ำ-ไฟ (เฉพาะห้องนี้) — ละเอียดกว่าที่เห็นตอนแรก
แต่ละประเภทค่าใช้จ่าย (ค่าน้ำ, ค่าไฟ, ค่าอินเทอร์เน็ต, ค่าส่วนกลาง) มี:
- checkbox **"ไม่คิด"** ต่อประเภท — ถ้าติ๊ก = ห้องนี้ไม่เก็บค่านี้เลย (ยกเว้นค่าใช้จ่ายนี้ให้ห้อง)
- checkbox/toggle **"ใช้ตามสาขา"** — ถ้าติ๊ก = ดึงค่า/สูตรจากหน้าตั้งค่าสาขา (แสดง helper text อธิบายว่ากำลังใช้ค่าอะไรจากสาขา เช่น "คิดค่าน้ำตามที่ตั้งไว้ในหน้าตั้งค่าสาขา (แถมอัตรา)")
- **ลำดับความสำคัญ: "ไม่คิด" ชนะทุกกรณี** — ถ้าติ๊ก "ไม่คิด" ระบบจะไม่เก็บค่านี้เลย ไม่ว่า "ใช้ตามสาขา" จะติ๊กอยู่หรือไม่ก็ตาม (2 checkbox ไม่ใช่ mutually exclusive แต่ "ไม่คิด" override เสมอ)
- ถ้าไม่ติ๊ก "ใช้ตามสาขา" → เปิดช่องกรอกค่า override เฉพาะห้อง (รูปแบบ/อัตรา ตามประเภท เช่น เหมาจ่าย vs อิงมิเตอร์)
- ค่าน้ำ/ค่าไฟ มี dropdown "รูปแบบ" เพิ่มเติม (เช่น ใช้ตามสาขา / เหมาจ่าย / อิงมิเตอร์) ส่วนอินเทอร์เน็ต/ส่วนกลางเป็นค่าเหมาจ่ายตรงๆ

### ค่าใช้จ่ายอื่นๆ รายเดือน (เฉพาะห้องนี้)
- Section เพิ่มค่าใช้จ่ายพิเศษที่คิดทุกเดือนเฉพาะห้องนี้ (นอกเหนือน้ำ/ไฟ/เน็ต/ส่วนกลาง)
- ปุ่ม "+ เพิ่มรายการ" → เพิ่มแถว (ชื่อรายการ + จำนวนเงิน) แบบ dynamic list

### สิ่งอำนวยความสะดวก (Amenities)
- Input พิมพ์แล้วกด Enter เพื่อเพิ่ม tag เอง หรือเลือกจาก preset ที่ให้มา (เตียง, ที่นอน, ตู้เสื้อผ้า, โต๊ะทำงาน, โต๊ะเครื่องแป้ง, เก้าอี้, ชั้นวางของ, แอร์, เครื่องทำน้ำอุ่น, ทีวี, ตู้เย็น, ไมโครเวฟ, ระเบียง, เครื่องซักผ้า, ผ้าม่าน, Wi-Fi)
- **ยืนยันแล้ว: preset ตายตัว ไม่ต้องให้เจ้าของอาพาร์ตเมนต์เพิ่ม/แก้ preset เองได้ (MVP)** — ยังพิมพ์ tag เองอิสระได้ตามเดิม แค่ตัว preset 16 รายการไม่ต้องมีหน้าจัดการแยก
- เก็บเป็น array ของ tag ต่อห้อง

### รูปห้อง
- อัปโหลดได้สูงสุด 10 รูป/ห้อง, แต่ละรูปไม่เกิน 10MB, รองรับ JPG/PNG/WEBP/GIF
- **ยืนยันแล้ว: เลือก "รูปปก" (cover photo) ได้** — 1 รูปในจำนวนที่อัปโหลดถูกกำหนดเป็นรูปหลักที่ใช้โชว์บนการ์ดห้องใน Grid View / preview อื่นๆ (ถ้าไม่เลือก ใช้รูปแรกที่อัปโหลดเป็น default)
- หมายเหตุ: รูปจะแสดงในหน้าองค์สาธารณะด้วย (เช่น หน้าประกาศห้องว่าง/หน้าเว็บสาธารณะ — เป็น requirement ที่บอกใบ้ว่าจะมี public listing page ในอนาคต)

### รายละเอียดเพิ่มเติม
- Textarea อิสระ สำหรับบันทึกโน้ตเกี่ยวกับห้อง

## ลบห้องพัก
- ปุ่ม "ลบ" ใน Room Detail modal
- **กฎสำคัญ (ยืนยันจากผู้ใช้): ถ้าห้องมีผู้เช่าอยู่ (สถานะ "มีผู้เช่า") จะลบไม่ได้** ต้องย้ายผู้เช่าออก/เช็คเอาท์ก่อนจึงจะลบห้องได้ — แสดง error/แจ้งเตือนอธิบายเหตุผลเมื่อพยายามลบห้องที่มีผู้เช่า
- **ยืนยันเพิ่มเติม: ห้องสถานะ "จองแล้ว" ก็ลบไม่ได้เช่นกัน** ต้องยกเลิกการจองให้กลับเป็น "ว่าง" ก่อนจึงจะลบห้องได้ — สรุปคือ **ลบได้เฉพาะห้องสถานะ "ว่าง" หรือ "ปิดปรับปรุง" เท่านั้น**
- ต้องมี confirm dialog ก่อนลบจริง (ป้องกันลบพลาด)

## Calendar View (มุมมองที่ 3 คู่กับ Grid/List) — [Feature เพิ่มเติมนอกเหนือต้นแบบ]
เพิ่มปุ่ม toggle มุมมองที่ 3 ในหน้า "จัดการห้องพัก" (เดิมมี Grid/List) → **Calendar**

- **รูปแบบ: Gantt แนวนอน รายสัปดาห์** — แกนซ้าย (Y) = รายชื่อห้องทั้งหมด (จัดกลุ่มตามชั้นเหมือน Grid/List), แกนบน (X) = วันที่ 7 วันของสัปดาห์ปัจจุบัน
- มีปุ่มเลื่อนสัปดาห์ก่อนหน้า/ถัดไป + ปุ่มกลับสัปดาห์ปัจจุบัน ("วันนี้")
- แต่ละแถว (ห้อง) แสดงเป็นแท่ง (bar) ทับบนช่วงวันที่ตามสถานะจริงของห้องในสัปดาห์นั้น:
  - ว่าง = พื้นที่ว่าง/สีเขียวอ่อน (หรือไม่มีแท่งเลย)
  - จองแล้ว = แท่งสีส้ม/เหลือง ยาวตามช่วงวันที่จอง — ให้สีตรงกับสถานะ "จองแล้ว" ในมุมมอง Grid/List เพื่อความสอดคล้อง
  - มีผู้เช่า = แท่งสีน้ำเงิน/ฟ้า ยาวตามช่วงวันเข้าพัก-สิ้นสุด (รายเดือนที่ไม่กำหนดวันออก แสดงแท่งยาวไปจนสุดขอบ view หรือมีลูกศรบอกว่า "ไม่มีกำหนดสิ้นสุด")
  - ปิดปรับปรุง = แท่งสีเทา
- **Interaction:**
  - คลิกที่แท่งของห้องที่มีข้อมูล (จอง/มีผู้เช่า) → เปิด Room Detail modal ของห้องนั้น
  - **คลิกที่ช่องว่าง (วันที่ห้องว่าง) → เปิด modal จอง/เพิ่มผู้เช่าทันที** พร้อม prefill วันที่ที่คลิกเป็นวันเข้าพัก
  - **MVP: ไม่รองรับลาก (drag) แท่งเพื่อเลื่อนวัน/ขยายช่วงเวลา** — การแก้ไขวันที่ทำผ่าน Room Detail modal เท่านั้น (drag interaction เป็นของเพิ่มทีหลังถ้าต้องการ)
- Calendar View นี้เป็นอีก view หนึ่งของ module "ห้องพัก" เอง ไม่ใช่ sub-module แยก (แต่ข้อมูลที่แสดงเชื่อมกับ sub-module "จองห้อง" อยู่ดี เพราะดึงช่วงวันจอง/เข้าพักมาโชว์)

## Room Detail Modal (เปิดจากคลิกห้อง)
Header: ไอคอนบ้าน + "ห้อง 101" + badge สถานะ + บรรทัดรอง "ชั้น 1 · ฿7500/เดือน · ฿600/วัน" + ปุ่ม "แก้ไข" (เปิดฟอร์มแก้ไขห้องเดิม) / ปุ่ม "ลบ" (ยืนยันก่อนลบ) / ปุ่มปิด (X)

Tabs ภายใน modal:
1. **ข้อมูลห้อง** (default)
2. **ผู้เช่า**
3. **สัญญา**
4. **มิเตอร์**
5. **แจ้งซ่อม**
6. **การชำระ**
7. **ประวัติ**

### Tab: ข้อมูลห้อง
- การ์ด: หมายเลขห้อง, ชั้น
- การ์ด: รองรับ (เช่น "รายเดือน + รายวัน")
- การ์ด: ราคา (แสดงราคาโหมดปัจจุบัน)
- Section "การคิดค่าสาธารณูปโภค" — แก้ไข data model utility เดิมให้ครอบคลุม **4 ประเภท**:
  - ค่าน้ำ
  - ค่าไฟ
  - ค่าอินเทอร์เน็ต
  - ค่าส่วนกลาง
  - แต่ละประเภทแสดงค่าปัจจุบัน + label "ใช้ตามสาขา" (= ยังไม่ override, ดึงจากค่าตั้งสาขา) หรือค่าที่ override เฉพาะห้องถ้ามี

### Tab: ผู้เช่า
- ถ้าห้องว่าง (ไม่มีผู้เช่า): แสดง empty state ไอคอนคน + ข้อความ "ยังไม่มีผู้เช่าในห้องนี้" + ปุ่ม "+ เพิ่มผู้เช่า" (primary) และ "จองห้อง" (secondary → ไปหน้า/module จองห้อง)
- ถ้ามีผู้เช่า: แสดงข้อมูลผู้เช่าปัจจุบัน (รอดูภาพเพิ่มเติม)

### Tab: สัญญา
- **ยืนยันแล้ว: Generate สัญญาจาก template ในระบบ** (ไม่ใช่แค่อัปโหลดไฟล์สัญญาที่เซ็นเองแล้ว) — ระบบต้องมี template สัญญาเช่าที่ดึงข้อมูลผู้เช่า/ห้อง/ราคา/วันที่มาสร้างเป็นเอกสารอัตโนมัติ รายละเอียด template (แก้ไขข้อความได้แค่ไหน, export เป็น PDF, e-signature หรือไม่) รอสเปคเต็มตอนทำ module "เอกสารสัญญา" โดยเฉพาะ

### Tab: แจ้งซ่อม
**ยืนยันแล้ว** ฟิลด์ที่ต้องมี:
- หัวข้อ
- รายละเอียด
- สถานะงาน (รอดำเนินการ / เสร็จสิ้น — อาจมีสถานะกลาง เช่น "กำลังดำเนินการ" รอสเปคเพิ่มตอนทำ module แจ้งซ่อมเต็มรูปแบบ)
- มอบหมายช่าง/ผู้รับผิดชอบ
- รูปประกอบ — **ไม่บังคับ** (ผู้ใช้ตอบก้ำกึ่งระหว่าง "ไม่ต้องมีรูป" กับ "มีรูปประกอบ" ตีความว่า = แนบรูปได้แต่ไม่บังคับกรอก ต้องยืนยันอีกทีตอนทำสเปค module แจ้งซ่อมเต็มรูปแบบ)

### Tab: มิเตอร์ / การชำระ / ประวัติ
- ยังไม่เห็นภาพ — เชื่อมกับ module "มิเตอร์น้ำ-ไฟ", "การเงิน", "ประวัติการใช้งาน" ตามลำดับ รอสเปคละเอียดตอนทำ module นั้นๆ

## Modal: เพิ่มผู้เช่า (เปิดจาก Tab ผู้เช่า > "+ เพิ่มผู้เช่า")
*หมายเหตุ: นี่คือจุดเชื่อมกับ module "ผู้เช่า" — บันทึกไว้ตรงนี้ก่อนเพราะเห็นจากภาพชุดห้องพัก จะขยายรายละเอียดเพิ่มตอนทำ module ผู้เช่าโดยเฉพาะ*

หัวข้อ Modal: "เพิ่มผู้เช่า - ห้อง [เลขห้อง]"
2 โหมดการทำงาน (tab บนสุดของ modal):
- **เลือกจากผู้เช่าที่มีอยู่** — ค้นหา/เลือกผู้เช่าเดิมในระบบ (เช่น กรณีผู้เช่าย้ายห้อง หรือมีผู้เช่าหลายห้อง) — **ค้นหาด้วยชื่อ**
- **สร้างผู้เช่าใหม่** — กรอกข้อมูลผู้เช่าใหม่

### Section: ข้อมูลการเข้าพัก (แสดงทั้ง 2 โหมด)
- ประเภทการเข้าพัก: toggle "รายเดือน (฿ราคา)" / "รายวัน (฿ราคา)" — ดึงราคาจากห้อง
- วันเข้าพัก* (date, required)
- **[Feature เพิ่มเติมนอกเหนือต้นแบบ]** ช่อง **"จำนวนคืน"** (number, ไม่บังคับ) — กรอกแล้วระบบ **คำนวณ "วันออก" ให้อัตโนมัติ** จาก วันเข้าพัก + จำนวนคืน (เพื่อไม่ต้องให้พนักงานนับวันเอง) — ผู้ใช้ยังแก้ไข "วันออก" เองตรงๆ ได้เช่นเดิมถ้าต้องการ (กรอกจำนวนคืนหรือกรอกวันออกตรงๆ ก็ได้ สองช่องนี้ sync กัน)
- วันออก (ถ้ามี) (date) — hint: "เว้นว่าง = รายเดือนไม่กำหนดวันออก"
- เงินมัดจำ (บาท) — prefill จาก deposit ของห้อง (override ได้)
- มิเตอร์เริ่มต้น (จดเลขวันเข้าอยู่ — ไม่บังคับ): ช่องน้ำ, ช่องไฟ
- checkbox "ออกบิลแรกเข้าให้เลย" — hint: "เก็บค่าเช่าช่วงแรก + เงินมัดจำ + ค่าดูแล ในคลิกเดียว — กรอก 'รับเงินแล้ว' ครบยอด บิลปิด ออกใบเสร็จทันที" (= auto-generate + auto-close บิลแรกเข้า)

### โหมด "สร้างผู้เช่าใหม่" — ฟอร์มข้อมูลผู้เช่า
- ปุ่ม "สร้างข้อมูลสมมติ (Mock)" — auto-fill ข้อมูลปลอมไว้ทดสอบ/เดโม
- รูปบัตรประชาชน (upload, รองรับ JPG/PNG ไม่เกิน 10MB)
  - **[Feature เพิ่มเติมนอกเหนือต้นแบบ]** รองรับถ่ายรูป/อัปโหลดบัตรประชาชนแล้ว **OCR อ่านข้อมูลอัตโนมัติ** เพื่อ autofill ฟอร์ม:
    - ชื่อ-นามสกุล
    - เลขบัตรประชาชน
    - ที่อยู่ตามบัตร (เติมลงช่อง "ที่อยู่เดิม")
    - ผู้ใช้ตรวจสอบ/แก้ไขค่าที่ OCR อ่านได้ก่อนกดบันทึก (ป้องกัน OCR อ่านผิด)
    - ต้องเลือกแนวทาง OCR ตอน implement จริง (เช่น เรียก API OCR บัตรประชาชนไทยโดยเฉพาะ หรือ generic OCR) — เป็นเรื่อง tech stack ที่จะตัดสินใจทีหลังตามที่ตกลงกันไว้
- ข้อมูลส่วนตัว:
  - ชื่อ-นามสกุล* (required — มี validation "จำเป็นต้องกรอก")
  - เบอร์โทรศัพท์
  - เพศ (dropdown)
  - อายุ
  - LINE ID
  - เลขบัตรประชาชน
  - อีเมล
  - ที่อยู่เดิม (textarea)
  - เบอร์ติดต่อฉุกเฉิน
  - ภาษาบิลที่ส่งทาง LINE (dropdown, default ไทย TH)
  - หมายเหตุ (textarea, จำกัด 2000 ตัวอักษร, มีตัวนับ)
  - ข้อมูลยานพาหนะ (+ ปุ่ม "เพิ่มยานพาหนะ" — dynamic list, ไม่บังคับ)
- Footer: ปุ่ม ยกเลิก / "บันทึกและเพิ่มเข้าห้อง" (บันทึกผู้เช่า + ผูกเข้าห้อง + สร้างสถานะเข้าพักในขั้นตอนเดียว)

## Check-in Flow (ฉบับปรับปรุงตามการตัดสินใจล่าสุด — สำคัญ)

**ยืนยันแล้ว: ระบบไม่ป้องกันการจอง/เช็คอินซ้อนทับช่วงวันเดียวกัน** ในห้องเดียวกัน — ไม่ต้อง validate วันที่ชนกันเอง ให้พนักงานเป็นคนตรวจสอบ/จัดการเอง (ลดความซับซ้อนของระบบ ไม่ block การบันทึก)

**กรณีห้องสถานะ "จองแล้ว" แล้วผู้เช่ามาเข้าพักจริง:** กด Check-in จากห้องนั้น → เปิดฟอร์ม "เพิ่มผู้เช่า" เดิม **พร้อม prefill ข้อมูลที่กรอกไว้ตอนจองครบทุกช่อง** (ผู้เช่า, วันเข้าพัก, มัดจำ ฯลฯ) ให้ผู้ใช้ตรวจสอบ/แก้ไขแล้วกดต่อเข้าสู่ขั้นตอนทำบิล/รับชำระเงินตามปกติ ไม่ต้องกรอกใหม่ทั้งหมด

กดปุ่ม "Check-in รายวัน/รายเดือน" จากการ์ดห้อง **หรือ** จาก Tab ผู้เช่าใน Room Detail → เปิด modal "เพิ่มผู้เช่า" แบบเดิม แต่ **ไม่บันทึกจบทันทีที่ปุ่ม "บันทึกและเพิ่มเข้าห้อง"** — ต้องผ่านขั้นตอนทำบิล/รับชำระเงินก่อนจึงจะปิดจบ

ลำดับขั้นตอนที่ต้องมี:
1. กรอกข้อมูลผู้เช่า + ข้อมูลการเข้าพัก (ตามฟอร์มเดิม)
2. **ตัวเลือก "เป็นการจองหรือไม่"** (checkbox/toggle) — ถ้าติ๊ก = บันทึกจบแค่นี้ สถานะห้อง → "จองแล้ว" (การ์ดเปลี่ยนสีของ "จอง" โดยเฉพาะ) ไม่ต้องทำบิล/รับเงิน เพราะยังไม่เข้าพักจริง
3. ถ้า **ไม่ติ๊กว่าเป็นการจอง** (= เข้าพักจริงทันที) → สถานะห้องจะเปลี่ยนเป็น **"มีผู้เช่า"** แต่ก่อนจบ flow ต้องผ่านขั้นตอนทำบิล/รับชำระเงิน ประกอบด้วย:
   - สรุปยอดที่ต้องเก็บ: ค่าเช่า (ตามราคาห้อง/โหมดที่เลือก) + เงินมัดจำ + ค่าใช้จ่ายอื่นๆ ที่ตั้งไว้กับห้อง (ถ้ามี)
   - **ส่วนลด** — **ยืนยันแล้ว รองรับทั้ง 2 แบบ**: จำนวนเงินตายตัว (เช่น ลด 200 บาท) หรือเปอร์เซ็นต์ (เช่น ลด 10%) ให้เลือกโหมดได้ ปรับยอดสุทธิตามที่เลือก
   - **ใบกำกับภาษี** — **ยืนยันแล้ว: ออกเป็นใบกำกับภาษีเต็มรูปแบบ** ต้องมีฟอร์มข้อมูลผู้เสียภาษี (ชื่อ/เลขผู้เสียภาษี/ที่อยู่ตามใบกำกับ) — toggle เปิด/ปิดว่าจะออกใบกำกับภาษีให้บิลนี้หรือไม่
   - **วิธีชำระเงิน** — เลือกได้ระหว่าง เงินสด / โอนเงิน
     - ถ้าเลือกโอน → ต้องเลือกว่าโอนเข้า **บัญชีธนาคารไหน** (ระบบรองรับตั้งค่าได้หลายบัญชีธนาคาร — ผูกกับ module "ฐานข้อมูลบัญชี")
   - **รองรับแบ่งจ่ายหลายวิธีในบิลเดียว (split payment)** — เช่น เงินสด 300 บาท + โอน 300 บาท ในรายการชำระเดียวกัน ต้องมี UI เพิ่มแถวการชำระได้หลายแถว แต่ละแถวเลือกวิธี+จำนวนเงิน
     - **ยืนยันแล้ว: อนุญาตให้จ่ายไม่ครบยอดได้ (ค้างชำระ)** — ยอดที่กรอกรวมกันไม่จำเป็นต้องเท่ากับยอดสุทธิ ส่วนต่างที่เหลือบันทึกเป็นยอดค้างชำระของบิล/ผู้เช่า (ไปโผล่ในข้อมูล "ยอดค้างชำระ" ที่แสดงบนการ์ดห้องตามที่ตกลงไว้ก่อนหน้า)
   - ปุ่มปิดจบ: ออกบิล + บันทึกการชำระ + ออกใบเสร็จ (เชื่อมกับ checkbox เดิม "ออกบิลแรกเข้าให้เลย")

**หมายเหตุ:** ฟีเจอร์ทำบิล/รับชำระเงินนี้ที่จริงเป็นส่วนหนึ่งของ module "การเงิน" (บิลค่าเช่า) แต่ถูกเรียกใช้ซ้อนอยู่ใน flow check-in ของห้องพัก จึงบันทึก requirement ไว้ตรงนี้ก่อน จะขยายรายละเอียดเต็มรูปแบบ (โครงสร้างบิล, การออกใบเสร็จ, ภาษีมูลค่าเพิ่ม ฯลฯ) ตอนทำสเปค module การเงินโดยเฉพาะ

## เช็คเอาท์ Flow (ยังไม่เห็นภาพ UI — บันทึกกฎที่ตกลงไว้ล่วงหน้า)
- **ยืนยันแล้ว: การคืนเงินมัดจำทำอยู่ใน flow เช็คเอาท์ของห้องเลย** (ไม่ใช่ไปทำแยกที่หน้าการเงินทีหลัง) — เช็คเอาท์ต้องมีขั้นตอนสรุป/คืนเงินมัดจำ (หักค่าเสียหาย/ค่าใช้จ่ายค้างชำระถ้ามี แล้วคืนส่วนที่เหลือ) ในหน้าจอเดียวกัน
- **รายการหักลบเงินมัดจำ (ยืนยันแล้ว)** — ต้องเลือกได้จากรายการสำเร็จรูป หรือเพิ่มเองได้ (เหมือน pattern "ค่าใช้จ่ายอื่นๆ" ที่ใช้ในฟอร์มแก้ไขห้อง): ค่าล้างแอร์, ค่าทำความสะอาด, ค่าข้าวของเสียหาย, + ปุ่ม "เพิ่มรายการ" custom เอง (ชื่อรายการ + จำนวนเงิน)
- **คำนวณค่าน้ำ-ไฟก่อนเช็คเอาท์ (ยืนยันแล้ว)** — ต้องมีขั้นตอนจดมิเตอร์ล่าสุด (วันจดครั้งก่อน → วันเช็คเอาท์) แล้วคำนวณเป็นบิลปิดยอดของห้องนั้นก่อนคืนเงินมัดจำ (ยอดนี้ไปหักจากเงินมัดจำที่จะคืนด้วย ถ้ายังไม่ได้จ่าย)
- ลำดับการคำนวณคืนเงินมัดจำ: เงินมัดจำที่วางไว้ − (ค่าน้ำ-ไฟงวดสุดท้าย + ยอดค้างชำระอื่นๆ + รายการหักลบที่เลือก) = ยอดคืนสุทธิ (ถ้าติดลบ = ผู้เช่าต้องจ่ายเพิ่มแทนที่จะได้เงินคืน)
- หลังเช็คเอาท์ สถานะห้อง → "ว่าง" ทันที (ไม่มี "รอทำความสะอาด" ตามที่ตัดสินใจไว้แล้ว)
- ยังไม่เห็น UI จริงของหน้านี้ — รอภาพเพิ่มเติมเพื่อลงรายละเอียด

## ย้ายห้อง (Room Transfer) Flow — [ยืนยันแล้ว: ทำได้จาก module ห้องพักเลย]
เข้าถึงได้จาก Room Detail ของห้องที่มีผู้เช่าอยู่ (Tab ผู้เช่า หรือปุ่ม action บนการ์ด) → ปุ่ม "ย้ายห้อง"

**แนวคิดหลัก: การย้ายห้อง = ปิดห้องเดิม (mini เช็คเอาท์) + เปิดห้องใหม่ (mini check-in) ในขั้นตอนเดียวต่อเนื่องกัน**

ขั้นตอน:
1. เลือกห้องปลายทาง — ต้องเป็นห้องสถานะ "ว่าง" เท่านั้น (ใช้กฎเดียวกับ "ไม่ป้องกันวันจองซ้อนทับ" อยู่แล้ว จึงไม่ต้องเช็ค edge case เพิ่ม)
2. **ปิดห้องเดิม** — ใช้กระบวนการเดียวกับเช็คเอาท์ Flow ด้านบนทั้งหมด:
   - จดมิเตอร์น้ำ-ไฟล่าสุดของห้องเดิม → คำนวณบิลปิดยอด
   - เลือก/เพิ่มรายการหักลบเงินมัดจำ (ค่าล้างแอร์, ค่าทำความสะอาด, ค่าของเสียหาย, custom)
   - สรุปยอดเงินมัดจำห้องเดิมที่จะคืน/หัก
   - **ยืนยันแล้ว: ย้ายห้องได้แม้ห้องเดิมมียอดค้างชำระอยู่** ไม่บล็อกการย้าย (ยอดค้างยังติดตามต่อในระบบตามปกติ ไม่ต้องเคลียร์ก่อน)
3. **ค่าเช่าคืน/ปรับตามสัดส่วนวัน (Prorated Rent) — ยืนยันแล้ว: ทำแบบยืดหยุ่น เคสบายเคส** — ไม่บังคับสูตรคำนวณคืนอัตโนมัติตายตัว พนักงานเลือกเองได้ว่าจะคืนส่วนต่างค่าเช่าที่จ่ายเกินมาของห้องเดิมหรือไม่ (เช่น ย้ายกลางเดือน) → UI ต้องมีช่องให้พนักงานกรอก/ปรับยอดเองอิสระ ไม่ auto-calculate บังคับ
4. **เปิดห้องใหม่** — ใช้ฟอร์มเดียวกับ "เพิ่มผู้เช่า"/Check-in Flow: ดึงข้อมูลผู้เช่าเดิมมาเลย (ไม่ต้องกรอกใหม่) + กำหนดวันเข้าพักห้องใหม่ + เงินมัดจำห้องใหม่ (ราคาอาจต่างจากห้องเดิม)
   - **มิเตอร์เริ่มต้นห้องใหม่ — ยืนยันแล้ว: บังคับต้องจด** (ต่างจาก check-in ปกติที่ไม่บังคับ เพราะการย้ายห้องมีความเสี่ยงข้อมูลมิเตอร์คลาดเคลื่อนสูงกว่า)
5. **เงินมัดจำห้องเดิม vs ห้องใหม่ (ยืนยันแล้ว):**
   - **ระดับข้อมูล/บัญชี (data model):** บันทึกเป็น **2 ธุรกรรมแยกกัน** — "คืนเงินมัดจำห้องเดิม" 1 รายการ + "รับเงินมัดจำห้องใหม่" 1 รายการ (แต่ละรายการผูกกับห้อง/บิลของตัวเอง เพื่อให้ประวัติ/บัญชีของแต่ละห้องถูกต้องครบถ้วน)
   - **ระดับ UX ที่พนักงานเห็น:** ระบบ **หักลบยอดอัตโนมัติ (netting)** แล้วแสดง/เก็บเงินจริงแค่ส่วนต่างครั้งเดียว (พนักงานไม่ต้องรับเงินคืนมัดจำเก่าจริงๆ แล้วจ่ายมัดจำใหม่จริงๆ 2 ครั้งแยกกัน) — เช่น มัดจำเก่าคืนได้ 5,000 หักค่าเสียหาย 500 = คืนสุทธิ 4,500, มัดจำห้องใหม่ต้องวาง 7,500 → ระบบสรุปให้ว่า "เก็บเพิ่มจากลูกค้าสุทธิ 3,000 บาท" ในหน้าจอเดียว แต่เบื้องหลังบันทึกลง 2 ธุรกรรมตามที่ตกลง
6. **สัญญาเช่า (ยืนยันแล้ว) — ต้องทำสัญญาใหม่เสมอตอนย้ายห้อง:**
   - **ปิดสัญญาเดิมของห้องเก่า** (สถานะสัญญา → สิ้นสุด/ปิด เพราะย้ายห้อง ไม่ใช่เพราะยกเลิกเช่า)
   - **สร้างสัญญาใหม่สำหรับห้องใหม่** ทันทีในขั้นตอนเดียวกัน (ไม่ต้องแยกไปทำทีหลัง)
   - **ต้องออกบิลด้วย** (ผูกกับขั้นตอนทำบิล/รับชำระเงินของ Check-in Flow ที่มีอยู่แล้ว)
5. บันทึกจบ: ห้องเดิม → สถานะ "ว่าง", ห้องใหม่ → สถานะ "มีผู้เช่า", ประวัติการย้ายห้องบันทึกไว้ใน Tab "ประวัติ" ของทั้ง 2 ห้อง

## รายการทบทวน Gap Analysis (ตัดสินใจแล้ว)
- **AI Search bar (top bar)** — **ตัดออก ไม่ต้องทำ**
- **Notification bell** — **ตัดออก ไม่ต้องมีตอนนี้**
- **ย้ายห้อง (room transfer)** — **ทำสเปคครบแล้ว** ดูหัวข้อ "ย้ายห้อง (Room Transfer) Flow" ด้านบน
- **ผู้เช่าร่วม/หลายคนต่อห้อง** — **ไม่ต้องมี** ยืนยันแล้วว่า 1 ห้อง = ผู้เช่าหลัก 1 คน (ข้อมูลยานพาหนะ/ผู้ติดต่อฉุกเฉินยังเก็บได้ในฟอร์มเดิม แต่ไม่ใช่ผู้เช่าร่วมแยกบัญชี)
- **ต่อสัญญา/ต่ออายุอัตโนมัติ** — **ยืนยันแล้ว: ทำอัตโนมัติได้** เมื่อครบกำหนดสัญญารายเดือนไม่มีการเช็คเอาท์ ระบบต่ออายุ/ต่อสัญญาให้เอง (รายละเอียดกลไก เช่น ต่อกี่เดือน/สร้างบิลใหม่อัตโนมัติหรือไม่ รอสเปคตอนทำ module "การเงิน"/"เอกสารสัญญา")
- **Role/สิทธิ์พนักงาน** — ยังไม่ต้องคิดตอนนี้ เก็บไว้ทำเป็น module "สิทธิ์การใช้งาน" แยกต่างหากทีหลัง (ไม่ต้องออกแบบ permission ให้ทุก action ตอนทำสเปคห้องพัก จะย้อนกลับมาผูก role ทีหลังเมื่อทำ module สิทธิ์)
- **LINE OA integration (ส่งบิลผ่าน LINE)** — เก็บไว้เป็นคำถามที่ต้องถามผู้ใช้เพิ่มเติมทีหลัง (ยังไม่ตัดสินใจรายละเอียด)
- **Export ข้อมูล (Excel/CSV)** — **ยืนยันแล้ว: ทำได้** แต่ย้ายไปอยู่ใน **module ใหม่ "รายงาน" (Reports)** ซึ่งไม่ได้อยู่ใน 7 กลุ่ม module เดิมที่วางแผนไว้ — **ต้องเพิ่ม module "รายงาน" เข้าไปในแผนภาพรวมด้วย**

## จุดที่ต้องรอ module อื่นมาต่อ (ทำสเปคภายหลัง)
- ปุ่ม "Check-in" → ไปเชื่อมกับ module ผู้เช่า/จองห้อง
- ค่า default ค่าน้ำ-ไฟและมัดจำที่ดึงจาก "ค่าตั้งสาขา" → ไปเชื่อมกับ module ตั้งค่า
- อัตราต่อหน่วยน้ำ-ไฟ → ไปเชื่อมกับ module มิเตอร์น้ำ-ไฟ

## ยังไม่ได้เห็นภาพ (รอ module ย่อยถัดไป)
- จองห้อง (Sub-module)
- มิเตอร์น้ำ-ไฟ (Sub-module)
