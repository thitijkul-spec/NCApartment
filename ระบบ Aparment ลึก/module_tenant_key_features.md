# Key Feature Spec — Module: ผู้เช่า (Tenant)

**สถานะ:** Design Complete — รอ implement (ขึ้นกับโมดูล "ห้องพัก/จองห้อง/มิเตอร์น้ำ-ไฟ" ต้อง implement โค้ดจริงให้ตรงสเปคก่อน — ยังไม่มีโค้ดจริงสักโมดูล ดู `next_module_prompt.md`)

## หน้าที่ของโมดูล
ศูนย์รวมข้อมูลผู้เช่าทั้งหมดในสาขา (ทั้งรายเดือนและรายวัน/walk-in) — ดู, เพิ่ม, แก้ไข, ติดตามสถานะการพัก และเข้าถึงเอกสารสัญญา
**ไม่ใช่จุดที่ใช้จัดห้องให้ผู้เช่า** — การผูกห้อง-ผู้เช่าทำที่หน้า "ห้องพัก" เท่านั้น (ดูเหตุผลในหัวข้อ Business Rule)

## ตำแหน่งเมนู
เมนูหลัก "ผู้เช่า" (ไม่ใช่ sub-tab)

## Multi-building
หน้ารายการแสดง**เฉพาะผู้เช่าของอาคารที่กำลังเลือกอยู่เท่านั้น** ทุก record ผูกกับ `building_id` ตามสถาปัตยกรรมหลักของระบบ

## Business Rule — ห้ามผูกห้องกับผู้เช่าจากหน้านี้

**การเลือกว่าห้องไหนมีผู้เช่าคนไหน (สร้าง/แก้ไข room_occupancies) ทำได้ที่หน้า "ห้องพัก" เท่านั้น** เพื่อป้องกันข้อมูลขัดแย้งกัน (สองจุดพยายามผูกห้องเดียวกันพร้อมกัน)

- ฟอร์ม "เพิ่มผู้เช่าใหม่" **ไม่มีช่องเลือกห้อง** — บันทึกผู้เช่าเสร็จแล้ว ต้องไปกดจัดห้องที่หน้าห้องเอง
- ปุ่ม **"ย้ายห้อง" และ "ย้ายออก"** ในหน้ารายละเอียดผู้เช่า **ไม่เปิด modal ในหน้านี้เสมอ 100%** — พาไปหน้าห้องที่เกี่ยวข้องเพื่อทำรายการจริงที่นั่น (เพราะถ้าเช่าหลายห้อง ต้องเลือกก่อนว่าจะย้าย/ย้ายออกห้องไหน ให้หน้าห้องเป็นคนจัดการ)
- **ข้อยกเว้น 1: "นำเข้าไฟล์" (Import CSV/Excel)** อนุญาตให้ระบุเลขห้อง+วันเข้าพักตรงในไฟล์ได้เลย เพราะเป็นเครื่องมือนำเข้าข้อมูลจำนวนมากครั้งเดียว (ตั้งค่าระบบครั้งแรก/ย้ายข้อมูลจากระบบเก่า)
  - ถ้าเลขห้องในไฟล์ชนกับห้องที่มี occupancy active อยู่แล้ว → **บล็อกเฉพาะแถวนั้น** ขึ้น error ชี้แถวที่ชน แถวอื่นที่ไม่ชนนำเข้าได้ตามปกติ
- **ข้อยกเว้น 2: Check-in จากหน้าห้อง** สร้าง occupancy ใหม่ได้โดยตรง (เป็นจุดเดียวที่ได้รับอนุญาตให้ผูกห้อง-ผู้เช่าตามที่ออกแบบไว้)

## Check-in จากหน้าห้อง → ต้องบันทึกข้อมูลผู้เช่าเต็มรูปแบบในโมดูลนี้ด้วย
เมื่อพนักงานกด check-in ที่หน้าห้องแล้วเลือก "ผู้เช่าใหม่" — ข้อมูลที่กรอกตอนนั้น**ต้องถูกบันทึกเป็น tenant record เต็มรูปแบบในโมดูลผู้เช่า** (ฟิลด์เดียวกับฟอร์ม "เพิ่มผู้เช่าใหม่") ไม่ใช่แค่เก็บแบบย่อไว้ในฝั่ง booking เท่านั้น
- ถ้ากรอกเบอร์โทร/เลขบัตรที่ซ้ำกับผู้เช่าเดิมที่มีอยู่แล้ว → **เตือน + ให้พนักงานเลือก** ว่าจะ "ใช้ record ผู้เช่าเดิม" (เพิ่ม occupancy ห้องใหม่ให้คนเดิม) หรือ "สร้าง record ใหม่แยกต่างหาก"

## ข้อมูลซ้ำ (เบอร์โทร / เลขบัตร ปชช.) — ตอนเพิ่ม/แก้ไขในหน้าผู้เช่าโดยตรง
ถ้ากรอกเบอร์โทรหรือเลขบัตรที่ซ้ำกับ record อื่นในระบบ — **ขึ้นข้อความเตือน แต่ยังบันทึกได้** (ไม่บล็อก) เผื่อกรณีพี่น้องคนเดียวกันเช่าเพิ่มห้อง/ผู้ปกครองเซ็นเพิ่มเอง

## ผู้เช่ารายวัน (Walk-in) กับรายเดือน
แสดง**รวมกันในรายการเดียวกัน** — ผู้เช่ารายวันถูกสร้าง record อัตโนมัติจากโมดูล "จองห้อง" ตอน check-in มี filter แยก "รายวัน / รายเดือน" ให้กรองดูเฉพาะประเภทได้

## หน้าจอย่อย

### รายการ (List) — สลับได้ 3 มุมมอง: Table / Card / Spreadsheet
- ค้นหา: ชื่อ, เบอร์โทร, หมายเลขห้อง — **ไม่รวมผู้เช่าที่เก็บเข้าคลัง (archived) โดยดีฟอลต์** ต้องกดเข้าไปดู Archive แยกต่างหากถึงจะเห็น
- Filter สถานะผู้เช่า (เลือกได้หลายอัน):
  - ผู้เช่าปัจจุบัน
  - ย้ายออกแล้ว (มี occupancy บางห้อง/ทุกห้อง status=moved_out)
  - ใกล้หมดสัญญา — เกณฑ์ ≤ 30 วันก่อน planned_checkout_date (เช็คระดับ occupancy)
  - ใกล้ถึงกำหนดชำระ — เกณฑ์**ตั้งค่าได้เองที่หน้าตั้งค่า** (ผูกกับโมดูลการเงิน)
  - ค้างชำระ — ผูกกับโมดูลการเงิน (สถานะบิล overdue)
- Filter ประเภท: รายวัน / รายเดือน
- Card view: แสดงชื่อ + badge ห้อง (ถ้าเช่าหลายห้อง แสดงเป็นตัวเลขนับจำนวนห้อง)
- Table columns: ชื่อ-นามสกุล, บัตร (มี/ไม่มี), เบอร์โทร, ห้อง (แสดงทุกห้องที่มี occupancy active + วันที่เตือนถ้าใกล้หมด), LINE (เชื่อมต่อ/ยังไม่เชื่อม), เอกสารสัญญา (ลิงก์เข้าดู — เฉพาะผู้เช่ารายเดือน), การดำเนินการ (แก้ไข / เก็บเข้าคลัง / ลบ)
  - ตัดคอลัมน์ "เครดิต" และปุ่ม "ให้คะแนน" ออก — ไม่มีระบบ blacklist/คะแนนผู้เช่า ใช้ช่อง "หมายเหตุ" แทน
- ไม่มีปุ่ม Export Excel/CSV ในโมดูลนี้ (ไม่จำเป็นสำหรับ MVP)
- ปุ่ม "เพิ่มหลายห้อง" (bulk) — **ตัดออก** (ซ้ำซ้อนกับ "นำเข้าไฟล์")

### Modal "เพิ่มผู้เช่าใหม่ / แก้ไขข้อมูล"
ฟิลด์: รูปบัตรประชาชน (อัปโหลด JPG/PNG ≤10MB), ชื่อ-นามสกุล* (required), เบอร์โทรศัพท์, เพศ (ชาย/หญิง), อายุ, LINE ID, เลขบัตรประชาชน, อีเมล, ที่อยู่เดิม, **ชื่อผู้ติดต่อฉุกเฉิน + เบอร์ติดต่อฉุกเฉิน**, ภาษาบิลที่ส่งทาง LINE, หมายเหตุ (free text ≤2000 ตัวอักษร), ยานพาหนะ (เพิ่มได้หลายคัน: ทะเบียน + ยี่ห้อ/รุ่น + สี)
**ไม่มีช่องเลือกห้อง** (ดู Business Rule ด้านบน) — ฟอร์มนี้สร้างแค่ `tenants` record ไม่ผูก occupancy ใดๆ
ข้อมูลผู้เช่าแก้ไขได้ทุกฟิลด์ภายหลัง

### Modal "รายละเอียดผู้เช่า"
- ชื่อ + badge ห้อง+ชั้น ของทุก occupancy ที่ active (read-only, ลิงก์ไปหน้าห้อง)
- ข้อมูลติดต่อ: เบอร์โทร, LINE ID, LINE Account (ปุ่ม "เชื่อมต่อ LINE"), บัตรประชาชน, ยานพาหนะ
- กล่องแดง **"หมดเวลาพักแล้ว"** (เฉพาะ occupancy ที่มาจากผู้เช่า**รายเดือน**เท่านั้น — รายวันติดตามผ่านโมดูล "จองห้อง" แทน) — **แสดงแยกต่อห้อง** ถ้าเช่าหลายห้อง อาจมีหลายกล่อง — แสดงอัตโนมัติเมื่อ `วันนี้ > planned_checkout_date` ของ occupancy นั้น และยังไม่ moved_out/แก้ไขวันออกใหม่
  - แสดง: ห้อง, วันเข้าพัก, วันออก(วางแผน), เงินมัดจำ — ของ occupancy นั้นๆ
  - **ไม่มีปุ่ม "ต่ออายุ" แยกต่างหาก** — ใช้ปุ่ม "แก้ไข" เพื่อเปลี่ยน planned_checkout_date แทน ครอบคลุมทั้งกรณีต่อยาว (ทำสัญญาใหม่) และกรณีขอพักต่ออีกสั้นๆ (2-3 วัน ถึง 2-3 เดือน) — การเลื่อนวันออกสามารถผูกกับการคิดเงินเพิ่ม/ออกบิลเพิ่มได้ (เชื่อมโมดูลการเงิน)
- ส่วน **"เอกสารสัญญา"** (เฉพาะผู้เช่ารายเดือน) — ผูกกับ `occupancy_id` (= ผู้เช่า+ห้อง+ช่วงวันที่) ถ้าผู้เช่าเช่าหลายห้อง แสดงเป็นรายการสัญญาแยกตามห้อง — ข้อมูลชุดเดียวกับที่แสดงในหน้าห้อง (ไม่อัปโหลดซ้ำสองที่)
- ปุ่ม: แก้ไขข้อมูล · ย้ายห้อง (พาไปหน้าห้อง, เลือกห้องถ้ามีหลายห้อง) · เอกสารสัญญา (เฉพาะรายเดือน) · เชื่อมต่อ LINE
- การจัดการ: **ย้ายออก (พาไปหน้าห้องเสมอ 100% — ให้เลือก/ยืนยันห้องที่หน้าห้อง)** · ลบ

### Flow "ย้ายออก" (ทำที่หน้าห้อง)
บังคับกรอก: วันที่ย้ายออกจริง + เหตุผล → บันทึกลง `room_occupancies.moved_out_date`/`moved_out_reason` ของห้องนั้น, occupancy.status = `moved_out`, **ห้องกลับเป็น "ว่าง" อัตโนมัติ**
ผู้เช่าจะถูก auto-archive เองเมื่อทุกห้องที่เช่า status='moved_out' ครบ และผ่านมาเกิน 14 วัน (ดู Data Model)

### Flow "เชื่อมต่อ LINE"
รองรับ 2 วิธี (ต้องมีบัญชี LINE OA ก่อนถึงจะใช้งานจริงได้ — ตอนนี้ยังไม่มี ให้กรอก `line_id`/`line_user_id` ด้วยมือไปพลางก่อน):

1. **พนักงานจับคู่มือ** — ลูกค้าแอด LINE OA เอง พนักงานเทียบเบอร์โทรที่ทักเข้ามา กับเบอร์โทรในระบบ แล้วกด "จับคู่" ยืนยัน
2. **ลูกค้ากรอกเอง (Self-service ผ่าน LIFF/บอท) — ไม่ต้อง verify ตัวตนเพิ่ม:**
   - ลูกค้าเปิดฟอร์มจาก LINE OA กรอก **เลขห้อง + เบอร์โทร**
   - ระบบเทียบกับ `tenants.phone` (เบอร์หลัก/เบอร์สัญญาเท่านั้น — รองรับ 1 เบอร์ต่อผู้เช่า ไม่รองรับหลายเบอร์ต่อห้อง) + ห้องที่มี occupancy active จริง
   - ตรง → ผูก `line_user_id` อัตโนมัติทันที
   - ไม่ตรง → กรอกใหม่ได้สูงสุด **10 ครั้ง** เกินจากนั้นต้องให้พนักงานเข้าไปแก้ไข/ผูกให้เองในระบบผู้ใช้งาน (fallback ไปวิธีที่ 1)

## การลบ / เก็บเข้าคลัง (Archive)
สองระดับ:
1. **"เก็บเข้าคลัง"** (ไอคอน archive ในตาราง, manual หรือ auto) = soft-delete — ซ่อนจากรายการหลัก แต่ข้อมูลยังอยู่ในระบบ กู้คืนได้
   - **Auto-archive:** batch job รันสัปดาห์ละ 1 ครั้งพอ (ไม่ต้อง real-time) — เช็คผู้เช่าที่ occupancy ทุกห้อง status='moved_out' ครบแล้ว และวันที่ย้ายออกล่าสุดผ่านมาเกิน 14 วัน → archived_at auto set
2. **"ลบ"** — ทำงานต่างกันตามบริบท:
   - กดจากรายการปกติ = soft-delete (`archived_at` set) เหมือนเก็บเข้าคลัง
   - กดจากภายใน Archive (ยืนยันซ้ำ) = **ลบถาวรจริง** ลบออกจากฐานข้อมูล
   - **บล็อกไม่ให้ลบ** (ทั้ง soft และถาวร) ถ้าผู้เช่ายังมี occupancy ที่ status = active อยู่ — ต้องย้ายออกครบทุกห้องก่อนเสมอ

## Action หลัก
เพิ่มผู้เช่า (ไม่เลือกห้อง) · แก้ไขข้อมูล · นำเข้าไฟล์ (bulk, ระบุห้องได้, บล็อกเฉพาะแถวชน) · ย้ายห้อง/ย้ายออก (ลิงก์ไปหน้าห้อง 100%) · เชื่อมต่อ LINE (2 วิธี) · เก็บเข้าคลัง (manual/auto) · ลบ (soft/ถาวรตามบริบท, บล็อกถ้ายัง active) · ค้นหา/กรอง (ไม่รวม archived) · สลับมุมมอง Table/Card/Spreadsheet

## สิทธิ์
ใช้ role ที่มีอยู่แล้ว (`owner | staff`) — ไม่มี sub-role เพิ่มสำหรับโมดูลนี้

## ความสัมพันธ์กับ module อื่น
- **ห้องพัก**: การผูกห้อง-ผู้เช่าทั้งหมด (assign, ย้ายห้อง, ย้ายออก, check-in) เกิดที่หน้าห้อง สร้าง/แก้ `room_occupancies` โมดูลนี้แค่แสดงผล/ลิงก์ไปหา — **check-in ที่หน้าห้องต้องสร้าง tenant record เต็มรูปแบบในโมดูลนี้ด้วยเสมอ** (ไม่ใช่แค่เก็บย่อฝั่ง booking)
- **จองห้อง**: ผู้เช่ารายวัน (walk-in) ถูกสร้าง record อัตโนมัติตอน check-in, `tenant_type` sync มาจาก booking, การเตือนหมดเวลาพักของรายวันอยู่ที่โมดูลจองห้อง ไม่ใช่โมดูลนี้
- **เอกสารสัญญา**: ไฟล์/ข้อมูลสัญญาผูกกับ `occupancy_id` แสดงได้ทั้งหน้าผู้เช่าและหน้าห้อง เฉพาะผู้เช่ารายเดือน
- **การเงิน**: filter "ใกล้ถึงกำหนดชำระ" / "ค้างชำระ" ดึงจากสถานะบิล, เกณฑ์วันตั้งค่าที่หน้าตั้งค่า, การเลื่อนวันออก(ต่อพักสั้นๆ)ผูกกับการออกบิลเพิ่ม
- **สื่อสาร (LINE)**: ปุ่ม "เชื่อมต่อ LINE" ผูก `line_user_id` เข้ากับผู้เช่า ทั้งแบบพนักงานจับคู่มือและลูกค้ากรอกเอง (ต้องรอมีบัญชี LINE OA ก่อน)
- **ตั้งค่า/ผู้ใช้งาน**: ใช้ role เดิม owner/staff, multi-building ผูกทุก record กับ `building_id` และกรองแสดงเฉพาะอาคารที่เลือกอยู่

## ตัดออกจาก MVP (ยืนยันแล้ว)
- ระบบให้คะแนนผู้เช่า (Rating)
- คอลัมน์/ระบบเครดิต
- ระบบ Blacklist (ใช้ช่อง "หมายเหตุ" แทน)
- ปุ่ม "ต่ออายุ" แยกต่างหาก (ใช้ปุ่มแก้ไขวันออกแทน)
- ปุ่ม "เพิ่มหลายห้อง"
- Checkbox "จัดเข้าห้องพักทันที" ในฟอร์มเพิ่มผู้เช่า
- ผู้ร่วมพัก (roommate) แยก record ในห้องเดียวกัน — 1 ห้อง มี occupancy active ได้แค่ 1 record เท่านั้น
- Export Excel/CSV ของรายการผู้เช่า
- เอกสารสัญญาสำหรับผู้เช่ารายวัน (walk-in)

## ⚠️ หมายเหตุสำคัญก่อน implement จริง
เช่นเดียวกับโมดูล "จองห้อง" และ "มิเตอร์น้ำ-ไฟ" — โมดูลนี้อ้างอิงข้อมูลห้อง/สัญญาจากสเปค `module_room_key_features.md` ไม่ใช่โค้ดปัจจุบันในโปรเจกต์ ต้องรอ implement โมดูล "ห้องพัก" ให้ตรงสเปคก่อน แล้วจึงย้อนมาทำ "ผู้เช่า" ตามสเปคนี้

**LINE OA ยังไม่มีบัญชีจริง** (ตาม README) — Flow เชื่อมต่อ LINE ทั้ง 2 วิธีเป็นการออกแบบล่วงหน้า ใช้งานจริงได้ต่อเมื่อสมัครบัญชี LINE Developers (Messaging API) แล้วเท่านั้น ก่อนหน้านั้นให้กรอก LINE ID/User ID ด้วยมือเป็นข้อมูลอ้างอิงไปพลางก่อน
