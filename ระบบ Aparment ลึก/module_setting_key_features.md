# Module: ตั้งค่า (Settings)

> ไม่มีภาพต้นแบบอ้างอิง — รวบรวมจาก "ของค้าง" ที่ module อื่นอ้างอิงไว้ตลอดการทำสเปคก่อนหน้า (role/permission, ข้อมูลกิจการ, ค่าตั้งสาขา, ช่าง, template สัญญา, LINE OA)

## หน้าที่ของ module
ศูนย์รวมค่าตั้งค่าระดับระบบ/ระดับอาคารที่ module อื่นดึงไปใช้ — **ไม่รวมการจัดการ `Account` (บัญชี CRUD)** เพราะย้ายไปอยู่ที่แท็บ "จัดการบัญชี" ใน `module_accounting_key_features.md` แล้ว

## ความสัมพันธ์กับระบบ multi-building
- ค่าตั้งค่าส่วนใหญ่ **แยกตามอาคาร** (ดูระบุไว้ต่อหัวข้อด้านล่าง) — ยกเว้น "ผู้ใช้งาน/สิทธิ์" ที่เป็นระดับบัญชีผู้ใช้รวม (1 บัญชีเจ้าของมีหลายอาคาร)
- **จัดการอาคาร/สาขา (เพิ่ม/ลบอาคาร) ไม่ได้อยู่ในหน้า "ตั้งค่า"** — แยกเป็นหน้า **Building Selector** ต่างหาก (หน้าเดียวกับที่ใช้สลับอาคารตอน login/สลับ workspace ตาม `module_room_key_features.md`)

## โครงสร้างหน้าจอ
Layout: **เมนูด้านข้าง (sidebar)** ซ้ายมือ แยกหัวข้อ, เนื้อหาเปลี่ยนทางขวาตามหัวข้อที่เลือก — ไม่ใช้ tab แนวนอน (หัวข้อเยอะเกินไป)

```
ตั้งค่า
├─ ข้อมูลกิจการ/ผู้รับเงิน   [ต่ออาคาร]
├─ ค่าตั้งสาขา              [ต่ออาคาร]
├─ ผู้ใช้งาน/สิทธิ์          [ระดับบัญชี — ไม่แยกอาคาร]
├─ ช่าง                    [ต่ออาคาร]
├─ ประเภทงานซ่อม            [ต่ออาคาร]
├─ Template สัญญาเช่า       [ต่ออาคาร]
└─ เชื่อมต่อ LINE OA        [ต่ออาคาร]
```

## 1. ข้อมูลกิจการ/ผู้รับเงิน (`building_payee_settings`)
**รวมเป็นชุดข้อมูลเดียว** — เดิมมี 2 จุดอ้างอิงแยกกัน (module_receipt เรียก "ข้อมูลกิจการ" สำหรับใบกำกับภาษี, module_contract เรียก "ข้อมูลผู้รับเงิน" สำหรับสัญญา) ข้อมูลซ้ำกันมาก (ชื่อ/ที่อยู่/เลขผู้เสียภาษี) จึงรวมเป็นจุดเดียว ให้ทั้ง 2 module ดึงจากที่นี่

**Fields (ต่ออาคาร):**
- ชื่อเจ้าของ/ชื่อบริษัท *
- เลขบัตรประชาชน หรือ เลขผู้เสียภาษีนิติบุคคล (13 หลัก) *
- เบอร์โทร
- ที่อยู่ *
- โลโก้ (upload รูป — ใช้พิมพ์บนใบกำกับภาษี/เอกสารทางการ)
- **ลายเซ็น** (upload รูปลายเซ็นของผู้รับเงิน/เจ้าของ — ใช้ประทับอัตโนมัติบนเอกสารแทนช่องเซ็นมือ เช่น ใบเสร็จ/ใบกำกับภาษี/สัญญาเช่า)
- ทั้งโลโก้และลายเซ็น: **ไฟล์เดียว ไม่เกิน 10MB, รองรับ JPG/PNG/WEBP/GIF** — ใช้ขีดจำกัดเดียวกับรูปห้องใน `module_room_key_features.md` เพื่อความสอดคล้อง
- ข้อความเปิดสัญญา (free text — ใช้เป็นข้อความเกริ่นนำในสัญญาเช่า)

**ใช้โดย:**
- `module_contract` — snapshot ตอนสร้างสัญญาใหม่ (ไม่มีช่องแก้ไขในฟอร์มสร้างสัญญา ต้องมาแก้ที่นี่เท่านั้น)
- `module_receipt` — snapshot ตอนออกใบเสร็จ/ใบกำกับภาษี (`payee_name_snapshot`, `payee_tax_id_snapshot`) + พิมพ์โลโก้บนเอกสาร

> **[แก้สเปคย้อนหลัง] `module_receipt_key_features.md`** เดิมออกแบบไว้เป็นช่องเซ็นมือเปล่า ("ผู้รับเงิน: ....................") — **ถ้ามีรูปลายเซ็นอัปโหลดไว้ที่นี่ ให้พิมพ์รูปลายเซ็นทับลงบนช่องนั้นอัตโนมัติแทนเว้นว่าง** (ถ้ายังไม่อัปโหลด ใช้ช่องเปล่าเหมือนเดิม)

## 2. ค่าตั้งสาขา (branch defaults)
**Fields (ต่ออาคาร):**
- ค่าน้ำ default — รูปแบบ (เหมาจ่าย/อิงหน่วยมิเตอร์) + ค่า/อัตรา
- ค่าไฟ default — เดียวกัน
- ค่าอินเทอร์เน็ต default — เหมาจ่ายรายเดือน
- ค่าส่วนกลาง default — เหมาจ่ายรายเดือน
- เงินมัดจำ default รายเดือน
- เงินมัดจำ default รายวัน

**ใช้โดย:** `module_room` — ทุกห้องที่ตั้งค่า utility/มัดจำเป็น "ใช้ตามสาขา" (ไม่ override เฉพาะห้อง) จะดึงค่าจากที่นี่

**พฤติกรรมเมื่อแก้ค่า default ภายหลัง: Live อัปเดตทันที** — ห้องที่ตั้ง "ใช้ตามสาขา" ไว้จะเปลี่ยนตามค่าที่แก้ใหม่ทันที (ไม่ใช่ snapshot ค่าตอนตั้งห้อง) ต่างจาก template สัญญา/ข้อมูลผู้รับเงินที่เป็น snapshot — เพราะค่าตั้งสาขาเป็น "ค่าที่กำลังใช้อยู่ปัจจุบัน" ไม่ใช่ข้อมูลบนเอกสารที่ออกไปแล้วต้องคงที่

## 3. ผู้ใช้งาน/สิทธิ์ (User)
**ระดับบัญชีผู้ใช้รวม ไม่แยกตามอาคาร** — 1 staff เข้าได้หลายอาคารพร้อมกัน (ผูกผ่านตาราง mapping user↔building)

**การสร้าง user:** เจ้าของบัญชี (owner) เป็นคนสร้าง user ให้ staff โดยตรง — **ตั้ง username/password เองตรงๆ ไม่มีระบบส่งอีเมลเชิญ**

**บัญชี owner คนแรกของระบบ:** เกิดจาก **หน้าสมัครสมาชิกทั่วไป (Sign up)** — คนแรกที่สมัครผ่านหน้านี้จะกลายเป็น owner โดยอัตโนมัติ พร้อมสร้างอาคารแรกให้เลยระหว่าง flow สมัคร (จากนั้น owner คนนี้เป็นคนสร้าง staff ต่อทั้งหมด ไม่มีหน้า sign up สำหรับ staff)

**เปลี่ยน/รีเซ็ต password:** **Owner เป็นคนรีเซ็ตให้ staff เท่านั้น** (ปุ่ม "รีเซ็ตรหัสผ่าน" ในหน้าจัดการ user) — staff ไม่มีหน้า profile ให้เปลี่ยนรหัสผ่านเอง (ระบบเล็ก ไม่มีอีเมลสำหรับ flow ลืมรหัสผ่าน)

**Fields ฟอร์ม CRUD user:**
- ชื่อ-นามสกุล *
- Username *
- Password (ตั้งตอนสร้าง, รีเซ็ตได้ภายหลัง)
- Role: `owner` / `staff` — **มีได้แค่ 1 owner ต่อ 1 บัญชี** (คนที่สมัคร sign up คนแรกเท่านั้น) ฟอร์มสร้าง user จากหน้านี้สร้างได้แค่ role `staff`
- อาคารที่เข้าถึงได้ — multi-select เลือกได้หลายอาคาร (เฉพาะ role=staff — owner เข้าได้ทุกอาคารเสมอโดยอัตโนมัติ ไม่ต้องเลือก)
- Permission — **checkbox เปิด/ปิดระดับ module** (ไม่ลงลึกถึง action ดู/แก้ไข/ลบ ไม่ลงลึกถึง sub-module) **แบ่งตาม 7 หมวดเมนูหลักของระบบ ตรงกับโครงสร้างเมนูจริง**: ห้องพัก (รวมจองห้อง+มิเตอร์), ผู้เช่า (รวมเอกสารสัญญา), การเงิน (รวมบิล/ใบเสร็จ/ค่าใช้จ่าย/รายได้อื่นๆ/ฐานข้อมูลบัญชี), ซ่อมบำรุง/พัสดุ, รายงาน, ตั้งค่า, ภาพรวม — **permission ชุดเดียวใช้ได้กับทุกอาคารที่ user คนนั้นเข้าถึง** (ไม่แยก permission ต่ออาคาร, ไม่แยกย่อยระดับ sub-module ภายในแต่ละหมวด)

**Data model แนวคิด:**
- `User`: id, name, username, password_hash, role (owner/staff), permissions (array รหัส module)
- `UserBuildingAccess`: user_id, building_id (many-to-many — เฉพาะ staff, owner ไม่ต้องมี record ก็เข้าได้ทุกอาคาร)

## 4. ช่าง (Technician)
**แยกตามอาคาร** — ช่างของอาคาร A ไม่ปนกับอาคาร B (ต้องเพิ่มใหม่ต่ออาคารถ้าช่างคนเดียวกันทำงานหลายอาคาร)

**Fields:** ชื่อ, เบอร์โทร, หมายเหตุ
**ใช้โดย:** `module_repair` (มอบหมายงานแจ้งซ่อม, บันทึกล้างแอร์/บำรุงรักษา)

**ลบช่างที่มีงานผูกอยู่:** **ลบได้อิสระเสมอ ไม่บล็อก** — งาน/ประวัติเก่าที่เคยมอบหมายช่างคนนี้ไว้ (`assigned_technician_id`/`technician_id` เป็น FK nullable) จะกลายเป็น "ยังไม่มอบหมาย"/ว่างอัตโนมัติ ไม่ลบประวัติงานทิ้ง

---

## 5. ประเภทงานซ่อม (RepairCategory)
**แยกตามอาคาร**

**Fields:** ชื่อประเภท — default เริ่มต้น 5 รายการ: ไฟฟ้า/ประปา/แอร์/เครื่องใช้ไฟฟ้า/อื่นๆ (แก้ไข/เพิ่ม/ลบเองได้)
**ใช้โดย:** `module_repair` — เลือกตอนแจ้งซ่อม (บันทึกเป็น snapshot `category_name` ไม่ใช่ live FK ตามสเปคเดิม จึงลบ RepairCategory ได้แม้มีงานอ้างอิงอยู่)

---

## 6. Template สัญญาเช่า
**แยกตามอาคาร**

**Fields:** รายการข้อสัญญา (ordered list) — default เริ่มต้น 12 ข้อ, เพิ่มข้อใหม่ได้ไม่จำกัด, แก้ไขข้อความได้, จัดลำดับใหม่ได้ (drag reorder), ลบได้
**ใช้โดย:** `module_contract` — ใช้ template นี้เป็นฐานตอน generate สัญญาใหม่ทุกฉบับ (ร่วมกับข้อมูลผู้รับเงินจากหัวข้อ 1)

**Versioning: Snapshot ตอนสร้างสัญญา** — สัญญาที่ generate ไปแล้วเก็บข้อความไว้คงที่ ณ ตอนสร้าง แก้ template ภายหลังไม่กระทบสัญญาเก่าที่พิมพ์ไปแล้ว (สอดคล้องกับหลัก snapshot ที่ใช้ทั่วทั้งระบบ เช่น ข้อมูลผู้รับเงิน/ผู้ขาย/ผู้ซื้อ)

## 7. เชื่อมต่อ LINE OA
**แยกตามอาคาร** — แต่ละอาคารมีบัญชี LINE OA ของตัวเอง (สอดคล้องกับสถาปัตยกรรม multi-building ที่ไม่ปนข้อมูลข้ามอาคาร)

**Fields:** Channel ID, Channel Secret, Channel Access Token — **ตอนนี้ยังไม่มีบัญชี LINE OA จริง เป็นแค่ช่องกรอก placeholder ไว้ก่อน** พร้อมสถานะ "ยังไม่ได้เชื่อมต่อ" + ปุ่ม "ทดสอบการเชื่อมต่อ" (disabled/แจ้งเตือนถ้ายังไม่กรอกครบ)

**ใช้โดย:**
- `module_tenant` — เชื่อมต่อ LINE ผู้เช่า (จับคู่มือ/ลูกค้ากรอกเอง)
- `module_bill` — ส่งบิลผ่าน LINE (บล็อกปุ่มส่งถ้ายังไม่ตั้งค่า LINE OA)
- `module_repair` — แจ้งซ่อมผ่าน LINE LIFF
- `module_parcel` — แจ้งเตือนพัสดุผ่าน LINE

## หน้า Building Selector (แยกออกจากหน้า "ตั้งค่า")
- แสดงหลัง login สำเร็จ ถ้าบัญชีนี้เข้าถึงได้มากกว่า 1 อาคาร (อาคารเดียว ข้ามหน้านี้ไปตรงเข้าหน้าหลัก)
- CRUD อาคาร: เพิ่มอาคารใหม่ (ชื่ออาคาร, ที่อยู่, **จำนวนชั้น**), แก้ไข, ลบ (เฉพาะ owner) — จำนวนชั้นเป็นแค่ข้อมูลอ้างอิง/ตั้งต้น ไม่ผูก validation กับชั้นจริงที่มีห้องอยู่ใน `module_room` (เพิ่ม/ลดห้องข้ามชั้นได้อิสระโดยไม่ต้องแก้ค่านี้ก่อน)
- คลิกอาคารในรายการ → เข้าทำงานในบริบทอาคารนั้น (เหมือน workspace switcher)
- ปุ่ม "สลับอาคาร" เข้าถึงได้อีกทีจากเมนูในระบบ (ไม่ใช่ dropdown ลอยอยู่ทุกหน้า) → พากลับมาหน้านี้

### ลบอาคาร — ขั้นตอนป้องกันการลบพลาด (สำคัญ เพราะกระทบข้อมูลทั้งอาคาร)
1. กด "ลบอาคาร" → popup แจ้งเตือนครั้งที่ 1 (สรุปผลกระทบ เช่น "อาคารนี้มี N ห้อง, M ผู้เช่า จะถูกลบทั้งหมด")
2. กดยืนยัน → popup แจ้งเตือนครั้งที่ 2 (ย้ำอีกครั้งว่าย้อนกลับไม่ได้)
3. กดยืนยันอีกครั้ง → **บังคับกรอกรหัสผ่านของบัญชี owner** เพื่อยืนยันตัวตนก่อนลบจริง
4. ผ่านทั้ง 3 ขั้นแล้วจึงลบจริง (hard delete ทั้งอาคารและข้อมูลที่ผูกอยู่)

## หน้าสมัครสมาชิก (Sign up) — จุดกำเนิดบัญชี owner คนแรก
- ไม่มีอยู่ในหน้า "ตั้งค่า" หรือ Building Selector — เป็นหน้าแยกก่อนเข้าระบบ (คู่กับหน้า Login)
- กรอกข้อมูลผู้สมัคร → สร้างบัญชีเป็น **role = owner โดยอัตโนมัติ** (ระบบนี้ไม่มี role อื่นเกิดจากการ sign up เอง)
- Flow สมัครรวมขั้นตอนสร้าง **อาคารแรก** ไปด้วย (ชื่ออาคาร, ที่อยู่) เพื่อให้เข้าใช้งานได้ทันทีหลังสมัคร ไม่ต้องเปิดหน้า Building Selector ว่างเปล่าตั้งอาคารเองแยกขั้นตอน
- Staff ทุกคนหลังจากนี้ **ไม่มีหน้า sign up ของตัวเอง** ต้องรอ owner สร้างให้เท่านั้น (ตามหัวข้อ "ผู้ใช้งาน/สิทธิ์")

## หมายเหตุสำหรับ implement
- `module_accounting` (`Account`) และ `module_room`/`module_bill`/`module_expense`/`module_other_income` (role/permission reference) รอ module นี้เสร็จก่อนถึงจะ implement การเชื่อมต่อจริงได้ครบ
- ปุ่ม export/import ต่างๆ ที่เคยพักไว้ (เช่น export มิเตอร์) ไม่เกี่ยวกับโมดูลนี้
