# UI Style Guide — ระบบจัดการอพาร์ตเมนต์ (Mockup)

สรุปสไตล์ที่ตกลงใช้กับทุก mockup/หน้าจอในระบบ (ตัดสินใจจากแชท mockup โมดูล "ภาพรวม (Dashboard)") — ใช้เป็น baseline อ้างอิงก่อนส่งให้โปรแกรมเมอร์เขียนโค้ดจริง

**อ้างอิงภาพ:** [langhorpak.com](https://langhorpak.com/) — เลือกเพราะอ่านง่าย โทนสะอาด ทันสมัย เหมาะกับ SaaS จัดการหอพัก/อพาร์ตเมนต์

---

## 1. ฟอนต์

**Prompt** (Google Fonts) — รองรับทั้งไทย/อังกฤษในตัวเดียว น้ำหนักที่ใช้:
- 400 (ตัวเนื้อหาปกติ)
- 500 (label / ปุ่มรอง)
- 600 (หัวข้อการ์ด / ปุ่มหลัก)
- 700 (หัวข้อหน้า / ตัวเลขสำคัญ)

## 2. สี (Light theme)

| Token | ค่า | ใช้กับ |
|---|---|---|
| `--bg` | `#F8FAFC` | พื้นหลังหน้าเว็บ |
| `--surface` | `#FFFFFF` | การ์ด/แถบเมนู |
| `--surface-2` | `#F1F5F9` | พื้นหลังรอง/hover |
| `--border` | `#E2E8F0` | เส้นขอบ |
| `--text` | `#0F172A` | ตัวอักษรหลัก |
| `--text-muted` | `#64748B` | ตัวอักษรรอง/label |
| `--accent` | `#2563EB` | สีหลักของระบบ (ปุ่ม, ลิงก์, ไอคอนเน้น) |
| `--accent-dark` / `--accent-darker` | `#1D4ED8` / `#1E40AF` | gradient/hover ของสีหลัก |
| `--accent-soft` | `#EEF4FF` | พื้นหลังอ่อนของสีหลัก (badge, ไอคอนวงกลม) |
| `--success` | `#059669` | ตัวเลข/สถานะเชิงบวก |
| `--warning` | `#D97706` | ตัวเลข/สถานะเตือน |
| `--danger` | `#E11D48` | ตัวเลข/สถานะค้าง-ผิดพลาด |

**Dark theme** มี token ชุดคู่ขนานแล้วในไฟล์ mockup ตัวอย่าง (โทนกรมท่า `#0B1220` + accent ฟ้าอ่อนลง `#5B8DEF`) — ให้ยึดรูปแบบเดียวกันทุกหน้า

## 3. Component convention

- **ปุ่ม**: ทรง pill (`border-radius: 999px`)
- **การ์ด**: มุมโค้ง 16–18px, เงานุ่ม (`shadow` ตื้นๆ ไม่ใช้เส้นขอบหนัก)
- **Sidebar**: แถบเมนูซ้าย กว้าง ~240px, ไอเทมที่ active ใช้พื้นหลัง `--accent` เต็ม + ตัวอักษรขาว
- **Stat card**: label สีเทาอ่อนด้านบน + ตัวเลขใหญ่ตัวหนา + บรรทัด delta สีความหมาย (เขียว/แดง/ฟ้า)
- **กล่องอธิบายข้อมูล** (เฉพาะช่วง mockup ไม่ใช้ในระบบจริง): กรอบเส้นประ พื้นหลัง `--surface-2` บอกว่าแต่ละ block ดึงข้อมูลจาก entity ไหน

## 4. ไฟล์ตัวอย่าง

ดู mockup ที่ทำสไตล์นี้แล้วที่ [`mockup/dashboard_mockup.html`](mockup/dashboard_mockup.html) (module ภาพรวม/Dashboard) — เปิดในเบราว์เซอร์ได้ตรงๆ ไม่ต้อง build

## 5. ขั้นตอนถัดไป

ทำ mockup module อื่นต่อในสไตล์เดียวกัน (ห้องพัก, ผู้เช่า, การเงิน, แจ้งซ่อม, พัสดุ, รายงาน, ประวัติการใช้งาน, ตั้งค่า) ก่อนส่งสเปค + mockup ทั้งชุดให้โปรแกรมเมอร์เริ่ม implement โค้ดจริง
