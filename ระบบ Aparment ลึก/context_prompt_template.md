# Context Prompt สำหรับเริ่มแชทใหม่ (ต่อ 1 Module)

คัดลอกข้อความด้านล่างนี้ไปวางเป็นข้อความแรกในแชทใหม่ แล้วแนบภาพแคปหน้าจอของ module นั้นๆ ตามด้วย

---

ฉันกำลังพัฒนา **ระบบจัดการอพาร์ตเมนต์** โดยอ้างอิงจากโปรแกรมต้นแบบที่มีอยู่แล้ว เป้าหมายคือทำให้ฟังก์ชันการทำงานและหน้าตาใกล้เคียงต้นแบบก่อน ส่วนฟีเจอร์เพิ่มเติมจะทำทีหลัง

**วิธีทำงาน:** ฉันจะทำทีละ module แยกกันคนละแชท เพื่อไม่ให้ context ปนกันและแก้ไขง่ายในอนาคต

**สิ่งที่ต้องการจากคุณในแชทนี้:**
1. ดูภาพแคปหน้าจอที่แนบมา (module: [ระบุชื่อ module เช่น "จัดการห้องพัก"])
2. วิเคราะห์โครงสร้างหน้าจอ: layout, ฟิลด์ข้อมูล, ปุ่ม/action, ตาราง, filter/search, validation ที่เห็นได้จากภาพ
3. สรุปออกมาเป็น **prompt/สเปค** สำหรับใช้สร้างโค้ดจริงของ module นี้ (ไม่ใช่การก็อปปี้ดีไซน์ตรงๆ แต่ออกแบบใหม่ให้ทำงานเทียบเท่า) ครอบคลุม:
   - ชื่อ/หน้าที่ของ module
   - Data model / field ที่ต้องมี (ชื่อ, ประเภทข้อมูล)
   - หน้าจอย่อยที่ต้องมี (list, add/edit form, detail, ฯลฯ)
   - Action/ฟังก์ชันที่ผู้ใช้ทำได้ (CRUD, filter, export, ฯลฯ)
   - ความสัมพันธ์กับ module อื่น (เช่น ห้องพักเชื่อมกับผู้เช่า, บิลเชื่อมกับห้องพัก)
4. หลังจากสรุปสเปคแล้ว รอฉัน confirm ก่อนค่อยเริ่ม implement โค้ดจริง

**Tech stack ของโปรเจกต์:** ยังไม่กำหนด (จะตัดสินใจทีหลัง) — ตอนนี้โฟกัสที่ product feature/สเปคก่อน

**[สำคัญ — สถาปัตยกรรมระดับระบบ] รองรับหลายอาคาร/สาขา (Multi-Building) ตั้งแต่แรก:**
- ระบบต้องรองรับเจ้าของที่มีมากกว่า 1 อาคาร/อพาร์ตเมนต์ ภายใต้บัญชีเดียวกัน (ไม่ใช่ทำอาคารเดียวก่อน)
- ทุก entity ที่เกี่ยวกับห้อง (ห้อง, ชั้น, ผู้เช่า, บิล, ค่าตั้งสาขา ฯลฯ) ต้องผูกกับ `building_id`
- **ไม่แสดงหลายอาคารในหน้าเดียวกัน** — ทุกหน้าจอแสดงข้อมูลเฉพาะอาคารที่กำลังเลือกอยู่เท่านั้น
- **การสลับอาคารทำงานเหมือน "สลับโปรไฟล์/workspace switcher"** — เลือกอาคารตอน login ครั้งแรก (มีหน้า Building Selector ถ้ามีมากกว่า 1 อาคาร) และสลับได้อีกทีจากหน้า "ตั้งค่า" ไม่ใช่ dropdown ลอยอยู่ทุกหน้า
- ทุก module ที่ทำสเปคต้องคำนึงถึงเรื่องนี้ (เช่น เลขห้องต้อง unique เฉพาะภายในอาคารเดียวกัน ไม่ใช่ unique ทั้งระบบ)

**โฟลเดอร์โปรเจกต์:** `D:\ระบบ อพาร์มเม้นท์\code`

**รายการ Module ทั้งหมดของระบบ (สำหรับอ้างอิงภาพรวม):**

1. **ภาพรวม** (Dashboard)
2. **ห้องพัก**
   - ห้องพัก
   - จองห้อง
   - มิเตอร์น้ำ-ไฟ
3. **ผู้เช่า**
   - ผู้เช่า
   - เอกสารสัญญา
4. **การเงิน**
   - บิลค่าเช่า
   - บิลกำหนดเอง
   - ค่าใช้จ่าย
   - ฐานข้อมูลบัญชี
   - แจ้งซ่อม
   - พัสดุ
5. **สื่อสาร**
6. **ประวัติการใช้งาน**
7. **ตั้งค่า**
8. **รายงาน** (Reports) — เพิ่มเข้ามาภายหลัง สำหรับ export ข้อมูล (Excel/CSV) และรายงานสรุปต่างๆ

โปรดใช้รายการนี้เป็นแผนที่อ้างอิงว่ากำลังทำ module ไหนอยู่ และ module นั้นสัมพันธ์กับ module อื่นอย่างไร (เช่น "บิลค่าเช่า" ต้องอ้างอิงข้อมูลจาก "ห้องพัก" และ "ผู้เช่า", "มิเตอร์น้ำ-ไฟ" เป็นข้อมูลตั้งต้นของ "บิลค่าเช่า")

**Module ที่กำลังทำในแชทนี้:** [ระบุชื่อ module เช่น "ห้องพัก > จองห้อง"]

## หมายเหตุการใช้งาน
- แก้ `[ระบุชื่อ module ...]` ให้ตรงกับแชทนั้นๆ ก่อนส่ง
- ถ้า module ไหนเชื่อมกับ module ที่ทำสเปคไปแล้ว ให้แปะสรุปสั้นๆ ของ module ก่อนหน้าต่อท้ายด้วย (เช่น field ที่ module อื่นต้องอ้างอิง) เพื่อให้เชื่อมกันถูกต้อง
- แนะนำลำดับการทำ: ห้องพัก → ผู้เช่า → มิเตอร์น้ำ-ไฟ → บิลค่าเช่า/บิลกำหนดเอง → ค่าใช้จ่าย/ฐานข้อมูลบัญชี → แจ้งซ่อม/พัสดุ → สื่อสาร/ประวัติการใช้งาน/ตั้งค่า → ภาพรวม (Dashboard ควรทำท้ายสุดเพราะต้องรวมข้อมูลจาก module อื่น)
