# Key Feature Spec — Module: เอกสารสัญญา (Contract)

**สถานะ:** Design Complete — รอ implement (ยังไม่มีโค้ดจริงสักโมดูล ดู `next_module_prompt.md`)

## หน้าที่ของโมดูล
สร้าง แก้ไข พิมพ์ และเก็บเอกสารสัญญาเช่าของผู้เช่ารายเดือน (รายวัน/walk-in ไม่มีสัญญา — ดู `module_tenant_key_features.md`)
เข้าถึงได้ทั้งจากเมนู "เอกสารสัญญา" โดยตรง และจากหน้า "ห้องพัก"/"ผู้เช่า" (ข้อมูลชุดเดียวกัน ไม่อัปโหลดซ้ำสองที่)

## ตำแหน่งเมนู
เมนูหลัก "เอกสารสัญญา" — หน้า list รวมทุกสัญญาในสาขาที่กำลังเลือกอยู่

## Multi-building
ทุก record ผูกกับ `building_id` ตามสถาปัตยกรรมหลักของระบบ

## ความสัมพันธ์กับ module อื่น
- **ผู้เช่า (required):** เลือกจากผู้เช่าที่มีอยู่ หรือสร้างผู้เช่าใหม่จากหน้านี้ได้เลย — ปุ่ม "สร้างผู้เช่าใหม่" เปิดฟอร์มเต็มรูปแบบเดียวกับหน้า module "ผู้เช่า" ทุก field (ใช้ component/ฟอร์มเดียวกัน ไม่ทำฟอร์มย่อแยกต่างหาก) กรอกเสร็จแล้วบันทึกลงตาราง `tenants` กลางโดยตรง (ไม่ใช่ shadow/duplicate record) จึงไปโผล่ในหน้า module "ผู้เช่า" ทันที — `tenant_type` ถูกตั้งเป็น `'monthly'` เสมอ (เพราะมีแค่ผู้เช่ารายเดือนเท่านั้นที่มีสัญญา ดู `module_tenant_key_features.md`)
- **ห้องพัก (required):** ต้องเลือก 1 ห้องเสมอต่อสัญญา (ใช้ดึงราคา/ข้อมูลห้องมาพิมพ์ในเอกสาร)
- **occupancy_id (optional):** สัญญา**ไม่บังคับ**ผูกกับ `room_occupancy` ตอนสร้าง — สร้างสัญญาได้อิสระก่อน แล้วค่อยผูก occupancy ทีหลังได้ (เช่น ตอน check-in จริง) ระบบเพียงแนะนำ flow ให้สร้างผู้เช่าก่อนสร้างสัญญา แต่ไม่บังคับ

## Business Rules

### ไม่มีระบบสถานะสัญญา (ตัดออกจากต้นแบบ)
ต้นแบบมีสถานะ "ร่าง / ใช้งาน / หมดอายุ" พร้อม stat cards — **โมดูลนี้ตัดออกทั้งหมด** ไม่มี field สถานะ ไม่มี stat cards บนหน้า list
การดูว่าห้อง/ผู้เช่าคนไหน "มีสัญญาแล้ว" ให้ดูจากหน้า "ห้องพัก" หรือ "ผู้เช่า" โดยตรง (ลิงก์ไปยังเอกสารสัญญาที่ผูกกับ occupancy/tenant นั้น) ไม่ใช่จากการกรองสถานะในหน้านี้

### การเซ็นสัญญา (ตัด LINE LIFF และระบบไฟล์แนบออกทั้งหมด)
- วิธีเดียวที่ระบบรองรับ: **เซ็นสดบน iPad** (canvas signature) ต่อหน้าพนักงาน — เซ็นแล้วถือว่าสัญญาเสร็จสมบูรณ์ในระบบ
- สัญญาตัวจริงที่พิมพ์กระดาษให้เซ็นสด/เก็บเข้าแฟ้ม เป็นกระบวนการนอกระบบ (physical filing) — **ระบบไม่มีฟีเจอร์อัปโหลด/แนบไฟล์สแกนหรือรูปภาพใดๆ ทั้งสิ้น** (ตัดออกตามที่ตัดสินใจ เพราะเป็นการใช้งานภายในที่ไม่จำเป็นต้องเก็บซ้ำในระบบ)
- ไม่มีลิงก์เซ็นผ่าน LINE, ไม่มี field วันหมดอายุลิงก์, ไม่มีลายเซ็นฝั่งผู้เช่าแยกจากผู้ให้เช่า (เซ็นสดต่อหน้ากันในสถานที่เดียว)

### ข้อมูลผู้รับเงิน — ตั้งค่าครั้งเดียวที่ "ตั้งค่าหอพัก"
- ชื่อเจ้าของ/ชื่อบริษัท, เลขบัตร ปชช./เลขผู้เสียภาษี, เบอร์โทร, ที่อยู่, ข้อความเปิดสัญญา — ตั้งค่าที่หน้า **"ตั้งค่าหอพัก"** เท่านั้น (`building_payee_settings`)
- หน้าสร้างสัญญา**ไม่มีช่องให้พิมพ์หรือแก้ไขข้อมูลนี้อีก** แสดงเป็น read-only (พร้อมลิงก์ "แก้ไขที่ตั้งค่า" ถ้าต้องการเปลี่ยน)
- ระบบ snapshot ค่าที่ใช้จริง ณ วันสร้างสัญญาเก็บไว้ในตัวสัญญาเอง (`*_snapshot`) เพื่อไม่ให้สัญญาที่พิมพ์ไปแล้วเปลี่ยนแปลงย้อนหลังหากมีการแก้ไขตั้งค่าในภายหลัง

### ข้อสัญญา (Clause) — Template กลาง เริ่มต้น 12 ข้อ เพิ่มได้ที่ตั้งค่า
- ลดจำนวนข้อสัญญาจากต้นแบบ (17 ข้อ) เหลือ **เริ่มต้น 12 ข้อ** โดยรวมข้อที่เนื้อหาใกล้เคียงกันให้กระชับแต่ยังครอบคลุมประเด็นสำคัญทางกฎหมาย (ดูรายการเต็มด้านล่าง)
- ข้อความข้อสัญญาทั้งหมดเป็น **template กลางระดับสาขา** จัดการ/แก้ไข/**เพิ่มข้อใหม่ได้ไม่จำกัดจำนวน**/จัดลำดับได้ที่หน้า "ตั้งค่า" เท่านั้น ใช้ร่วมกันทุกสัญญา
- ข้อที่เพิ่มใหม่ กรอกได้ทั้งภาษาไทยและอังกฤษ (`title_en`/`body_en`) — ถ้าเว้นว่างช่องอังกฤษไว้ ตอนพิมพ์แบบ bilingual จะแสดงเฉพาะภาษาไทยของข้อนั้น ไม่มีคำเตือน
- ตอนสร้าง/แก้ไขสัญญาแต่ละฉบับ ทำได้แค่ **เลือกเปิด/ปิด (รวม/ไม่รวม)** ว่าจะพิมพ์ข้อไหนบ้างในสัญญานี้ (รวมข้อที่เพิ่มใหม่ด้วย) — แก้ไขข้อความเฉพาะสัญญาไม่ได้ ต้องไปแก้ที่ตั้งค่า
- Placeholder ในข้อความ (เช่น {หมายเลขห้อง} {วันเริ่มสัญญา} {ค่าเช่า}) ถูกแทนที่อัตโนมัติด้วยข้อมูลของสัญญานั้นๆ ตอนแสดงผล/พิมพ์
- แก้ไขข้อความภาษาไทยของข้อที่มีอยู่แล้ว **ไม่มีการเตือนหรือบังคับให้แก้ภาษาอังกฤษตาม** สองภาษาแก้ไขเป็นอิสระจากกันโดยสิ้นเชิง เป็นความรับผิดชอบของผู้ตั้งค่าที่ต้องแก้ให้ตรงกันเอง

### ข้อมูลทางการเงิน
- ค่าเช่า/เดือน ดึงค่าเริ่มต้นจากราคาห้องที่เลือกอัตโนมัติ แต่ **แก้ไขได้อิสระ** ต่อสัญญา (ไม่กระทบราคาตั้งต้นของห้อง) — รองรับกรณีลูกค้าต่างชาติเช่าระยะสั้นในราคาสูงกว่าปกติได้โดยตรง ไม่ต้องมี field พิเศษเพิ่ม

### Placeholder ที่ดึงจากที่อื่น (ไม่ใช่ field ของสัญญาเอง)
- `{ที่อยู่หอพัก}` — ดึงจาก address ของ building/สาขา ที่มีอยู่แล้วในระบบ (ไม่ใช่ `payee_address` ซึ่งเป็นที่อยู่เจ้าของ/บริษัท อาจเป็นคนละที่กัน)
- `{อนุญาต/ไม่อนุญาตให้เลี้ยงสัตว์}` — map จาก `allow_pets`: true → "อนุญาตให้เลี้ยงสัตว์เลี้ยง" / false → "ไม่อนุญาตให้เลี้ยงสัตว์เลี้ยง" (EN: "pets are allowed" / "pets are not allowed")
- `{อนุญาต/ห้ามสูบบุหรี่ในอาคาร}` — map จาก `no_smoking`: true → "ห้ามสูบบุหรี่ในอาคาร" / false → "อนุญาตให้สูบบุหรี่ในพื้นที่ที่กำหนด" (EN: "smoking is prohibited inside the building" / "smoking is permitted in designated areas")
- วันที่ทุก placeholder วันที่ (เช่น `{วันเริ่มสัญญา}` `{วันสิ้นสุดสัญญา}` `{วันที่ทำสัญญา}`) — ฉบับภาษาไทยแสดงเป็น **พ.ศ. เสมอ** (ตามกฎหมายไทย) เช่น "15 สิงหาคม 2569" ฉบับภาษาอังกฤษ (เมื่อเปิด bilingual) แสดงเป็น **ค.ศ.** เช่น "August 15, 2026"
- จำนวนเงินทุก placeholder (เช่น `{ค่าเช่า}` `{เงินประกัน}`) — นอกจากตัวเลขแล้ว **ต้องสะกดเป็นตัวหนังสือไทยกำกับด้วยเสมอ** เช่น "7,500 บาท (เจ็ดพันห้าร้อยบาทถ้วน)" ต้องมี utility function แปลงตัวเลข→ข้อความไทยแบบใช้ในเอกสารราชการ/สัญญา (ฉบับอังกฤษไม่ต้องสะกด แสดงแค่ตัวเลข)

### โหมดสองภาษา (ไทย + อังกฤษ) สำหรับลูกค้าต่างชาติ
- มี checkbox "พิมพ์เอกสารสองภาษา" ในหน้าสร้าง/แก้ไขสัญญา (`is_bilingual`)
- เมื่อเปิดใช้: เอกสารที่พิมพ์แสดง **ข้อภาษาไทย ตามด้วยข้อภาษาอังกฤษของข้อเดียวกัน ทีละข้อ** (ไม่ใช่แยกคนละหน้า/คนละคอลัมน์) โดยดึงจาก `title`/`body` (ไทย) และ `title_en`/`body_en` (อังกฤษ) ของแต่ละ clause template ที่ถูกเลือกรวมไว้
- เมื่อปิดโหมดนี้: พิมพ์เฉพาะภาษาไทยตามปกติ ไม่มีข้อปิดท้ายเรื่องภาษาต่อท้าย
- **ข้อปิดท้าย — ภาษาที่ใช้บังคับ (fixed clause แยกจาก template):** เมื่อเปิดโหมดสองภาษา ระบบต่อท้ายข้อนี้เสมอเป็น**ข้อสุดท้าย** **ปิด/ลบไม่ได้** โดยเลขข้อคำนวณอัตโนมัติเป็น (จำนวนข้อที่ถูกเลือกรวมในสัญญานี้ + 1) เสมอ ไม่ใช่เลขคงที่ "13" (เพราะตอนนี้ template เพิ่มข้อได้ไม่จำกัด จำนวนข้อจริงต่อสัญญาจึงไม่เท่ากับ 12 เสมอไป) ระบุว่าหากตีความขัดแย้งกันให้ยึดภาษาไทยเป็นหลัก (ข้อความคงที่ ดูด้านล่าง)

### แก้ไขสัญญาหลังเซ็นแล้ว
- แก้ไขข้อมูลสัญญา (ค่าเช่า, วันที่, ข้อสัญญาที่เลือก ฯลฯ) ได้เสมอ ไม่มีการล็อกฟอร์ม
- แต่ถ้าสัญญานั้นเซ็นไปแล้ว การแก้ไขจะ **ล้างลายเซ็นเดิมทิ้งทันที** (`owner_signature_image`/`signed_at` กลับเป็น null) ต้องให้เซ็นใหม่อีกครั้งเพื่อยืนยันข้อมูลที่แก้ไข

### การลบสัญญา
- สัญญาที่**ยังไม่เซ็น** ลบได้อิสระ (hard delete)
- สัญญาที่**เซ็นแล้ว** ลบจริงไม่ได้ ทำได้แค่ **soft-delete/archive** (`archived_at`) — ยังค้นหา/ดูย้อนหลังได้ แต่ไม่แสดงในหน้า list ปกติ

### ห้องซ้ำ/มีสัญญา active อยู่แล้ว
ตอนสร้างสัญญาใหม่ ถ้าห้องที่เลือกมีสัญญาที่เซ็นแล้วและยังไม่หมดอายุของผู้เช่าคนอื่นอยู่ก่อน ระบบ**แจ้งเตือนเฉยๆ ไม่บล็อก** ผู้ใช้ยืนยันให้สร้างสัญญาซ้อนต่อได้ตามดุลยพินิจของพนักงาน

4. **เงินประกันการเช่า / Security Deposit**

   - TH: ผู้เช่าได้ตรวจรับห้องพักพร้อมเฟอร์นิเจอร์และอุปกรณ์ตามสภาพที่ตรวจสอบร่วมกันแล้ว ผู้เช่าต้องดูแลรักษาทรัพย์สินและความสะอาดของห้องพักให้อยู่ในสภาพเรียบร้อย ไม่ต่อเติม ดัดแปลง หรือเจาะผนัง/โครงสร้างโดยไม่ได้รับอนุญาตเป็นลายลักษณ์อักษร หากเกิดความเสียหายจากการใช้งานผิดวิธีหรือความประมาทเลินเล่อของผู้เช่า ผู้เช่าต้องรับผิดชอบค่าซ่อมแซมหรือชดใช้ตามราคาที่แท้จริง

   - TH: หากผู้เช่าค้างชำระค่าเช่าหรือค่าใช้จ่ายใดๆ ติดต่อกันเกิน {จำนวนวันค้างชำระที่อนุญาต} วันนับแต่วันครบกำหนดชำระ ผู้ให้เช่ามีสิทธิบอกเลิกสัญญาและให้ผู้เช่าออกจากห้องพักได้ทันทีโดยไม่ต้องแจ้งล่วงหน้า

### เอกสารเดียว ใช้ได้หลายที่
สัญญาแสดงผลได้ทั้งจากหน้าผู้เช่าและหน้าห้อง (ข้อมูลชุดเดียวกัน)

## หน้าจอย่อย
1. **หน้า list "เอกสารสัญญา"** — ตารางรวมทุกสัญญาในสาขา (เอกสาร/ผู้เช่า/ห้อง/ระยะเวลา/ค่าเช่า/การดำเนินการ: พิมพ์/แก้ไข/ลบ) search ได้ด้วยชื่อผู้เช่า, วันที่, หรือเลขห้อง — **ไม่มี stat cards สถานะ** (ตัดออก), สัญญาที่ archive แล้วไม่แสดงในหน้านี้
2. **หน้าสร้าง/แก้ไขสัญญา** — ฟอร์มตามที่วิเคราะห์จากภาพ: ข้อมูลผู้รับเงิน (**read-only** แสดงค่าจากตั้งค่าหอพัก พร้อมลิงก์ไปแก้ที่ตั้งค่า) → เลือกผู้เช่า → ห้องพักและระยะเวลา → รายละเอียดทางการเงิน → checkbox "พิมพ์เอกสารสองภาษา (ไทย+อังกฤษ)" → เลือกข้อสัญญา (เปิด/ปิดจาก 12 ข้อ template กลาง) → เงื่อนไขสัญญาเช่า → พยาน → เซ็นด้วย iPad
3. **หน้าจัดการ Template ข้อสัญญา** (ในหน้า "ตั้งค่า") — แก้ไข/จัดลำดับ/**เพิ่มข้อใหม่**ในข้อสัญญากลาง (เริ่มต้น 12 ข้อ ไม่จำกัดจำนวนสูงสุด) ทั้งฉบับภาษาไทยและอังกฤษ แก้แยกอิสระจากกัน ไม่มีการเตือน sync (ข้อปิดท้ายเรื่องภาษาที่ใช้บังคับ เป็นข้อความคงที่ในระบบ แก้ไม่ได้ ไม่แสดงในรายการนี้)
4. **หน้าตั้งค่าข้อมูลผู้รับเงิน** (ในหน้า "ตั้งค่าหอพัก") — จุดเดียวที่แก้ไขชื่อเจ้าของ/บริษัท, เลขบัตร/เลขผู้เสียภาษี, เบอร์โทร, ที่อยู่, ข้อความเปิดสัญญาได้
5. **หน้าพิมพ์/preview** — เอกสารเต็มรูปแบบตามข้อสัญญาที่เลือกรวม พร้อมดาวน์โหลด PDF/พิมพ์

- สร้างสัญญาใหม่ (เลือกผู้เช่าเดิม/สร้างใหม่ + เลือกห้อง)

- พิมพ์ / ดาวน์โหลด PDF
